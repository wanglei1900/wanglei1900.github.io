容器化技术：Docker 核心架构原理 - 完整学习笔记 ​

一、Docker 概述与核心理念 ​

1.1 什么是 Docker？ ​

  • 官方定义：开源的应用容器引擎，基于 Go 语言开发
  • 核心价值：一次构建，处处运行（Build, Ship, Run Anywhere）
  • 与传统虚拟化的区别：
    传统虚拟机：物理机 → Hypervisor → 完整Guest OS → 应用
Docker容器：物理机 → Docker Engine → 应用（直接使用宿主机内核）

1.2 Docker 的核心理念 ​

  • 镜像（Image）：应用的静态打包，包含完整运行环境
  • 容器（Container）：镜像的运行实例，轻量级沙箱环境
  • 仓库（Registry）：镜像的存储和分发中心

二、Docker 整体架构 ​

2.1 C/S 架构模型 ​

┌─────────────────────────────────────────────────────┐
│                   Docker Client                      │
│  (docker CLI / API客户端 / Docker Desktop GUI)        │
└─────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────┐
│                Docker Daemon (dockerd)               │
│   (REST API / 镜像管理 / 容器管理 / 网络存储管理)        │
└─────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────┐
│                   Containerd                         │
│          (容器生命周期管理 / 跨平台抽象层)              │
└─────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────┐
│                     Runc                             │
│      (OCI标准实现 / 创建容器 / Linux内核调用)           │
└─────────────────────────────────────────────────────┘

2.2 架构组件详解 ​

2.2.1 Docker Client ​

  • docker CLI：命令行工具，发送指令给 Docker Daemon
  • Docker API：RESTful API，支持程序化操作
  • 示例命令流程：
    bash
    # 用户输入
docker run nginx:latest

# 实际发生
1. CLI解析命令 → 2. 通过API发送到Daemon → 3. Daemon执行

2.2.2 Docker Daemon (dockerd) ​

  • 核心服务进程：常驻后台，监听API请求
  • 主要职责：
    • 镜像管理（build, pull, push）
    • 容器生命周期管理
    • 网络管理（Network drivers）
    • 数据卷管理（Volume drivers）
    • 日志收集

2.2.3 Containerd ​

  • 独立守护进程：从Docker 1.11+分离出来
  • 功能：
    • 容器生命周期（create, start, stop, pause, rm）
    • 镜像分发与管理
    • 存储管理
    • 网络管理（通过CNI插件）
  • 架构优势：
    • 解耦设计，可以被其他工具（k8s）直接调用
    • 更轻量，更稳定

2.2.4 Runc ​

  • OCI Runtime 标准实现：负责与Linux内核交互
  • 核心功能：创建容器进程，设置命名空间和控制组（cgroups）
  • 容器创建流程：
    go
    // 简化的runc创建流程
1. 解析config.json（OCI标准配置文件）
2. 创建namespaces（隔离视图）
3. 设置cgroups（资源限制）
4. 设置rootfs（容器文件系统）
5. 执行entrypoint（容器入口进程）

三、核心原理：Linux 内核技术支撑 ​

3.1 命名空间（Namespaces） - 隔离机制 ​

PID命名空间  → 进程隔离（独立PID 1）
Net命名空间 → 网络隔离（独立网络栈）
Mnt命名空间 → 文件系统隔离（独立/）
UTS命名空间 → 主机名隔离
IPC命名空间 → 进程间通信隔离
User命名空间 → 用户权限隔离（从Docker 1.10+）

示例：查看容器的命名空间

bash
# 查看容器进程ID
docker inspect --format '{{.State.Pid}}' <container_id>

# 查看该进程的命名空间
ls -la /proc/<pid>/ns/

3.2 控制组（cgroups） - 资源限制 ​

  • 资源控制维度：
    cpu     → CPU使用率限制
memory  → 内存限制
blkio   → 块设备IO限制
devices → 设备访问控制
freezer → 进程挂起/恢复

示例：查看容器的cgroups配置

bash
# 查看容器的cgroup路径
docker inspect --format '{{.Id}}' <container_id>

# 查看内存限制
cat /sys/fs/cgroup/memory/docker/<container_id>/memory.limit_in_bytes

3.3 联合文件系统（UnionFS） ​

  • 核心概念：分层、写时复制（Copy-on-Write）
  • 常用驱动：
    Overlay2（推荐）← 性能最佳
AUFS        ← 早期默认
DeviceMapper← RHEL/CentOS
Btrfs/ZFS   ← 高级特性

Overlay2 工作流程：

容器层 (upperdir)   ← 读写层，用户修改保存于此
镜像层 (lowerdir)   ← 只读层，多个镜像层叠加
合并层 (merged)     ← 统一视图层

3.4 容器网络模型 ​

3.4.1 网络命名空间隔离 ​

bash
# 容器拥有独立的：
# 1. 网络设备（eth0）
# 2. IP地址
# 3. 路由表
# 4. iptables规则

3.4.2 Docker 网络驱动 ​

bridge（默认）   ← 创建docker0网桥，NAT方式
host           ← 共享宿主机网络栈
none           ← 无网络配置
overlay        ← 跨主机容器网络（Swarm）
macvlan        ← 为容器分配MAC地址

3.4.3 Bridge 网络详细流程 ​

容器A (10.0.0.2)                容器B (10.0.0.3)
         ↓                              ↓
    veth pair                     veth pair
         ↓                              ↓
    docker0网桥 (172.17.0.1)
         ↓
  宿主机eth0 (192.168.1.100)
         ↓
       外网

关键配置：

bash
# 创建自定义网桥
docker network create --subnet=172.18.0.0/16 mynet

# 运行容器并指定网络
docker run --network=mynet --ip=172.18.0.10 nginx

3.5 数据持久化：Volume vs Bind Mount ​

yaml
# Volume（Docker管理）
优点：便携、备份迁移方便、可加密
位置：/var/lib/docker/volumes/
命令：docker volume create myvol

# Bind Mount（宿主机路径）
优点：高性能、直接访问
位置：任意宿主机路径
命令：docker run -v /host/path:/container/path

四、Docker 镜像深度解析 ​

4.1 镜像分层结构 ​

示例：nginx:latest镜像
Layer 4: 添加nginx配置文件  ← 可写层
Layer 3: 安装nginx软件
Layer 2: 安装基础工具
Layer 1: 基础操作系统层（debian:buster）

4.2 Dockerfile 构建原理 ​

dockerfile
# 每个指令都会创建一个新层
FROM ubuntu:20.04           ← 基础层
RUN apt-get update          ← 层1
RUN apt-get install -y nginx← 层2
COPY index.html /var/www/html ← 层3
EXPOSE 80                   ← 元数据，不创建层
CMD ["nginx", "-g", "daemon off;"] ← 元数据

4.3 镜像存储机制 ​

bash
# 镜像存储位置
/var/lib/docker/
    ├── image/           # 镜像元数据
    │   └── overlay2/    # Overlay2驱动存储
    ├── overlay2/        # 分层存储
    ├── containers/      # 容器运行时数据
    └── volumes/         # 数据卷

# 重要：容器=进程，不是虚拟机！

六、Docker 安全机制 ​

6.1 安全最佳实践 ​

  • 非root用户运行容器：
    dockerfile
    USER 1000:1000
  • 只读根文件系统：
    bash
    docker run --read-only ...
  • 安全扫描：
    bash
    docker scan nginx:latest
  • 内容信任（DCT）：
    bash
    export DOCKER_CONTENT_TRUST=1

6.2 Linux 安全模块集成 ​

  • AppArmor：访问控制配置文件
  • SELinux：强制访问控制
  • Seccomp：系统调用过滤

七、Docker 核心工作流程 ​

7.1 docker run 完整流程 ​

mermaid
graph TD
    A[docker run nginx] --> B[Docker Client]
    B --> C[Docker Daemon API调用]
    C --> D[检查本地镜像]
    D -->|存在| E[直接使用]
    D -->|不存在| F[Docker Hub拉取]
    F --> G[下载镜像层]
    G --> H[解压到存储目录]
    H --> I[Containerd创建容器]
    I --> J[Runc设置命名空间/cgroups]
    J --> K[挂载UnionFS]
    K --> L[启动entrypoint进程]
    L --> M[容器运行]

7.2 端口映射原理 ​

bash
# docker run -p 8080:80 nginx 的背后：
# 1. 创建iptables规则
iptables -t nat -A DOCKER -p tcp --dport 8080 -j DNAT --to-destination 172.17.0.2:80

# 2. 启用内核转发
echo 1 > /proc/sys/net/ipv4/ip_forward

九、总结与核心要点 ​

9.1 三大核心特性 ​

  1. 隔离性：基于Namespaces（进程、网络、文件系统等）
  2. 可配额：基于cgroups（CPU、内存、磁盘等）
  3. 便携性：基于UnionFS（分层、写时复制）

9.2 架构演进趋势 ​

Docker 1.11前：Monolithic架构
Docker 1.11+：  模块化架构（Daemon→Containerd→Runc）
Kubernetes时代：Containerd成为标准运行时

9.3 性能关键点 ​

  • 镜像分层：最小化层数，合理利用缓存
  • 存储驱动：生产环境推荐Overlay2
  • 网络模式：host模式性能最佳（牺牲隔离性）
  • 资源限制：必须设置cgroups限制防止资源耗尽
