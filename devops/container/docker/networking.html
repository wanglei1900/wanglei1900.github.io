Docker网络模型详解 - 完整学习笔记 ​

一、Docker网络基础概念 ​

1.1 Docker网络架构 ​

用户空间                                   内核空间

1.2 核心组件 ​

  • Network Namespace（网络命名空间）：提供网络栈的隔离
  • veth pair（虚拟以太网对）：连接不同网络命名空间的虚拟网卡
  • bridge（网桥）：二层网络设备，连接多个网络接口
  • iptables：网络包过滤和NAT规则

二、Docker网络驱动类型 ​

2.1 Bridge网络（默认网络驱动） ​

工作原理： ​

┌─────────────────────────────────────────────────────┐
│                 Host Machine                         │
│  ┌─────────────┐   ┌─────────────┐                  │
│  │ Container A │   │ Container B │                  │
│  │   eth0      │   │   eth0      │                  │
│  │ 172.17.0.2  │   │ 172.17.0.3  │                  │
│  └──────┬──────┘   └──────┬──────┘                  │
│         │                 │                         │
│         └──────┬──────┬───┘                         │
│                │      │                             │
│        ┌───────▼──────▼────────┐                   │
│        │     docker0 bridge     │                   │
│        │      IP: 172.17.0.1    │                   │
│        └────────────┬───────────┘                   │
│                     │                               │
│              ┌──────▼──────┐                       │
│              │  eth0       │                       │
│              │ Host NIC    │                       │
│              │ 10.0.0.5    │                       │
│              └─────────────┘                       │
└─────────────────────────────────────────────────────┘

配置示例： ​

bash
# 查看默认bridge网络
docker network inspect bridge

# 创建自定义bridge网络
docker network create \
  --driver bridge \
  --subnet=192.168.100.0/24 \
  --gateway=192.168.100.1 \
  --opt "com.docker.network.bridge.name"="mybridge" \
  my-bridge-network

# 运行容器连接到网络
docker run -d \
  --name web1 \
  --network my-bridge-network \
  --ip 192.168.100.10 \
  nginx:alpine

# 端口映射（容器->主机）
docker run -d \
  --name web2 \
  -p 8080:80 \
  -p 8443:443 \
  nginx:alpine

2.2 Host网络 ​

特点： ​

  • 容器直接使用主机网络栈
  • 没有网络隔离
  • 性能最好（无NAT开销）
bash
# 使用host网络模式
docker run -d \
  --name web \
  --network host \
  nginx:alpine

# 容器直接使用主机的80端口
# 无法使用端口映射（-p参数无效）

2.3 None网络 ​

  • 容器只有lo回环接口
  • 完全网络隔离
bash
docker run -it \
  --network none \
  --rm \
  alpine sh

# 容器内只有lo接口
# ifconfig 或 ip addr 只能看到lo

2.4 Container网络 ​

  • 容器共享另一个容器的网络命名空间
bash
# 创建第一个容器
docker run -d \
  --name nginx \
  nginx:alpine

# 创建第二个容器，共享nginx的网络栈
docker run -it \
  --name debugger \
  --network container:nginx \
  --rm \
  alpine sh

# debugger容器中可以看到nginx的网络接口

2.5 Overlay网络（多主机网络） ​

工作原理： ​

Swarm Cluster
┌─────────────────┐         ┌─────────────────┐
│   Node 1        │         │   Node 2        │
│  ┌───────────┐  │         │  ┌───────────┐  │
│  │Container A│  │         │  │Container B│  │
│  │10.0.0.2   │  │         │  │10.0.0.3   │  │
│  └─────┬─────┘  │         │  └─────┬─────┘  │
│        │        │         │        │        │
│  ┌─────▼─────┐  │         │  ┌─────▼─────┐  │
│  │Overlay    │◄───────────┼─►│Overlay    │  │
│  │Network    │  │         │  │Network    │  │
│  └─────┬─────┘  │         │  └─────┬─────┘  │
│        │        │         │        │        │
│  ┌─────▼─────┐  │         │  ┌─────▼─────┐  │
│  │ Host NIC  │  │         │  │ Host NIC  │  │
│  │ eth0      │  │         │  │ eth0      │  │
│  └───────────┘  │         │  └───────────┘  │
└─────────────────┘         └─────────────────┘

配置示例： ​

bash
# 初始化Swarm集群
docker swarm init --advertise-addr <MANAGER_IP>

# 创建overlay网络
docker network create \
  --driver overlay \
  --subnet=10.0.0.0/24 \
  --attachable \
  my-overlay-network

# 在Swarm服务中使用overlay网络
docker service create \
  --name web \
  --network my-overlay-network \
  --replicas 3 \
  nginx:alpine

2.6 Macvlan网络 ​

  • 为容器分配MAC地址
  • 容器在物理网络中像独立设备
bash
# 创建macvlan网络
docker network create \
  --driver macvlan \
  --subnet=192.168.1.0/24 \
  --gateway=192.168.1.1 \
  --ip-range=192.168.1.100/28 \
  -o parent=eth0 \
  my-macvlan-network

# 运行容器
docker run -d \
  --name macvlan-container \
  --network my-macvlan-network \
  nginx:alpine

2.7 IPvlan网络 ​

  • 共享主机MAC地址
  • 为容器分配独立IP地址
bash
# 创建IPvlan网络
docker network create \
  --driver ipvlan \
  --subnet=192.168.1.0/24 \
  --gateway=192.168.1.1 \
  -o ipvlan_mode=l2 \
  -o parent=eth0 \
  my-ipvlan-network

bash
# 设置MTU
docker network create \
  --driver bridge \
  --opt "com.docker.network.driver.mtu"="1500" \
  custom-mtu-network

# 设置网桥属性
docker network create \
  --driver bridge \

# 创建内部网络（不提供NAT到外部）
docker network create \
  --driver bridge \
  --internal \
  internal-network

四、网络通信原理 ​

4.1 容器间通信机制 ​

同主机容器通信： ​

bash
# 默认bridge网络
容器A(172.17.0.2) <--> docker0(172.17.0.1) <--> 容器B(172.17.0.3)

# 自定义bridge网络（通过DNS）
容器A(web1) <--DNS解析--> 容器B(web2)

# 通过links通信（已弃用）
docker run -d --name web1 nginx
docker run -d --name web2 --link web1:nginx_alias alpine

跨主机容器通信： ​

yaml
# docker-compose.yml示例
version: '3.8'
services:
  web:
    image: nginx:alpine
    networks:
      - frontend
      - backend
    ports:
      - "80:80"
    
  app:
    image: myapp:latest
    networks:
      - backend
    depends_on:
      - db
  
  db:
    image: postgres:13
    networks:
      - backend
    environment:
      POSTGRES_PASSWORD: secret

networks:
  frontend:
    driver: bridge
    ipam:
      config:
        - subnet: 10.10.0.0/24
  backend:
    driver: bridge
    ipam:
      config:
        - subnet: 10.20.0.0/24

4.2 网络数据流向分析 ​

容器访问外部网络： ​

容器进程 → 容器eth0 → veth pair → docker0 → iptables MASQUERADE → 主机eth0 → 互联网

外部访问容器： ​

互联网 → 主机eth0 → iptables DNAT → docker0 → veth pair → 容器eth0 → 容器进程

同网络容器通信： ​

容器A → vethA → docker0 → vethB → 容器B

五、网络安全配置 ​

5.1 网络隔离策略 ​

bash
# 1. 创建隔离网络
docker network create \
  --internal \
  isolated-network

# 2. 配置网络策略
docker network create \
  --driver bridge \
  --opt com.docker.network.bridge.enable_icc=false \
  no-icc-network

# 3. 使用用户定义网络的容器隔离
docker run -d \
  --name secure-app \
  --network isolated-network \
  --security-opt no-new-privileges \
  myapp:latest

5.2 iptables规则管理 ​

bash
# 查看Docker创建的iptables规则
iptables -t nat -L -n -v
iptables -t filter -L DOCKER -n -v

# 限制容器访问外部特定端口
iptables -I DOCKER-USER -i docker0 -o eth0 -p tcp --dport 22 -j DROP

# 允许特定容器访问外部
iptables -I DOCKER-USER -s 172.17.0.2 -j ACCEPT
iptables -I DOCKER-USER -j DROP

六、网络诊断与故障排查 ​

6.1 诊断工具和命令 ​

bash
# 1. 基础网络检查
docker exec -it container-name ip addr
docker exec -it container-name ip route
docker exec -it container-name cat /etc/resolv.conf
docker exec -it container-name ping -c 4 google.com

# 2. 网络连通性测试
docker run --rm \
  --network container:target-container \
  appropriate/curl curl http://localhost:8080

# 3. 网络数据包捕获
docker run --rm \
  --net container:target-container \
  nicolaka/netshoot tcpdump -i any -n port 80

# 4. 网络诊断容器
docker run -it --rm \
  --network host \
  --pid host \
  --privileged \
  nicolaka/netshoot

6.2 常见问题排查 ​

bash
# 问题1：容器无法访问外部网络
# 检查步骤：
1. 检查主机网络连接
2. 检查iptables规则
3. 检查DNS配置
4. 检查MTU设置

# 问题2：容器间无法通信
# 检查步骤：
1. 确认容器在同一网络
2. 检查防火墙规则
3. 验证DNS解析
4. 检查网络驱动状态

# 问题3：端口映射失败
# 检查步骤：
1. 验证端口是否被占用
2. 检查iptables NAT规则
3. 确认容器是否监听正确端口
4. 检查SELinux/AppArmor策略

6.3 高级诊断技巧 ​

bash
# 查看网络命名空间
ls -la /var/run/docker/netns/

# 容器内：

# 跟踪网络请求

七、生产环境网络设计 ​

7.1 多环境网络架构 ​

yaml
# 生产环境网络架构示例
version: '3.8'

networks:
  # 公共网络 - 对外服务
  public:
    driver: bridge
    ipam:
      config:
        - subnet: 10.10.0.0/24
    driver_opts:
      com.docker.network.bridge.name: br-public

  # 应用网络 - 内部通信
  app-tier:
    driver: overlay
    attachable: true
    ipam:
      config:
        - subnet: 10.20.0.0/24
    labels:
      environment: production

  # 数据网络 - 数据库服务
  data-tier:
    driver: overlay
    internal: true  # 不暴露到外部
    ipam:
      config:
        - subnet: 10.30.0.0/24

services:
  # 负载均衡器
  traefik:
    image: traefik:v2.10
    networks:
      - public
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock

  # Web应用
  webapp:
    image: myapp:latest
    networks:
      - public
      - app-tier
    labels:
      - "traefik.http.routers.webapp.rule=Host(`app.example.com`)"

  # API服务
  api:
    image: api:latest
    networks:
      - app-tier
      - data-tier

  # 数据库
  postgres:
    image: postgres:14
    networks:
      - data-tier
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}

7.2 网络性能优化 ​

bash
# 1. 使用host网络模式提升性能
docker run -d \
  --network host \
  --restart unless-stopped \
  nginx:alpine

# 2. 优化TCP参数

九、总结与最佳实践 ​

9.1 网络选择指南 ​

场景推荐网络类型说明
开发测试bridge简单易用，支持端口映射
生产Web服务bridge + 反向代理灵活配置，易于管理
高性能应用host无NAT开销，性能最佳
数据库集群overlay多主机通信，自动发现
物理网络集成macvlan/ipvlan直接接入物理网络
安全隔离环境多bridge + 内部网络分层安全架构

9.2 最佳实践要点 ​

  1. 网络规划：

    • 提前规划IP地址分配
    • 设计网络分层架构
    • 考虑未来扩展需求

  2. 安全策略：

    • 使用网络策略限制通信
    • 实施最小权限原则
    • 定期审计网络配置

  3. 性能优化：

    • 选择合适的网络驱动
    • 优化MTU设置
    • 监控网络流量和性能

  4. 运维管理：

    • 统一网络命名规范
    • 文档化网络架构
    • 自动化网络配置

9.3 故障排查流程 ​

容器网络问题排查流程：
1. 检查容器状态：docker ps
2. 验证网络配置：docker network inspect
3. 测试容器内连通性：docker exec ping
4. 检查主机网络：iptables, route, DNS
5. 验证网络驱动：lsmod, dmesg
6. 捕获网络流量：tcpdump
7. 检查日志：docker logs, journalctl

通过深入理解Docker网络模型，您可以构建出稳定、安全、高效的容器网络架构，满足不同场景下的业务需求。
