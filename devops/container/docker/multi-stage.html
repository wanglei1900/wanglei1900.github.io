Docker多阶段构建详解 - 完整学习笔记 ​

一、多阶段构建核心概念 ​

1.1 什么是多阶段构建 ​

多阶段构建允许在单个Dockerfile中使用多个FROM指令，每个FROM指令开始一个新的构建阶段。每个阶段可以基于不同的基础镜像，并且可以选择性地将文件从一个阶段复制到另一个阶段。

1.2 为什么需要多阶段构建 ​

传统构建的问题： ​

传统单阶段构建：
应用源代码 + 构建工具 + 运行时依赖 = 最终镜像
结果：镜像臃肿（通常>1GB），包含不必要的构建工具和中间文件

多阶段构建的优势： ​

第一阶段（构建阶段）：应用源代码 + 构建工具 = 编译产物
第二阶段（运行阶段）：仅运行时依赖 + 编译产物 = 最终镜像
结果：镜像精简（通常<100MB），安全且高效

1.3 核心优势对比 ​

特性单阶段构建多阶段构建
镜像大小大（包含所有构建依赖）小（仅包含运行时所需）
安全性较低（可能包含敏感信息）高（仅暴露运行环境）
构建速度较慢（每次全量构建）较快（可缓存中间阶段）
维护性复杂（需手动清理）简单（自动分离关注点）
生产就绪需要额外优化开箱即用

二、多阶段构建语法详解 ​

2.1 基本语法结构 ​

dockerfile
# 第一阶段：构建阶段
FROM [基础镜像] AS [阶段名称]
# 构建指令...
RUN [构建命令]

# 第二阶段：运行阶段
FROM [运行镜像]
# 从构建阶段复制文件
COPY --from=[阶段名称] [源路径] [目标路径]
# 运行指令...
CMD [启动命令]

2.2 阶段命名与引用 ​

dockerfile
# 方式1：显式命名阶段
FROM golang:1.21-alpine AS builder
# ...构建操作

FROM alpine:3.18 AS runtime
COPY --from=builder /app /app  # 引用命名阶段

# 方式2：使用阶段索引
FROM node:18-alpine
# ...第一阶段

FROM python:3.11-slim
COPY --from=0 /dist /app/dist  # 引用阶段索引(0代表第一个FROM)

# 方式3：使用外部镜像
COPY --from=nginx:alpine /etc/nginx/nginx.conf /app/nginx.conf

2.3 高级语法特性 ​

dockerfile
# 1. 多阶段并行构建（Docker 18.09+）
FROM golang:1.21 AS backend-builder
# ...后端构建

FROM node:18 AS frontend-builder
# ...前端构建

# 2. 条件构建（需BuildKit）
# docker build --target builder --build-arg BUILD_ENV=production
ARG BUILD_ENV=production

FROM base AS development-build
# 开发环境构建逻辑

FROM base AS production-build
# 生产环境构建逻辑

# 3. 动态选择目标阶段
FROM base AS final
# 根据参数选择文件来源
COPY --from=${BUILD_ENV}-build /app /app

三、实战案例详解 ​

3.1 Go应用多阶段构建 ​

完整示例： ​

dockerfile
# 第一阶段：依赖下载阶段（利用缓存）
FROM golang:1.21-alpine AS deps
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download

# 第二阶段：构建阶段
FROM golang:1.21-alpine AS builder
WORKDIR /build

# 从依赖阶段复制go modules缓存
COPY --from=deps /go/pkg/mod /go/pkg/mod

# 复制源代码
COPY . .

# 构建参数
ARG VERSION=1.0.0
ARG COMMIT_HASH=unknown
ARG BUILD_TIME

# 编译（禁用CGO，静态链接）
RUN CGO_ENABLED=0 GOOS=linux go build \
    -ldflags="-w -s \
    -X main.version=${VERSION} \
    -X main.commit=${COMMIT_HASH} \
    -X main.buildTime=${BUILD_TIME}" \
    -o app .

# 第三阶段：测试阶段（可选）
FROM builder AS tester
RUN go test -v ./...

# 第四阶段：运行阶段
FROM scratch AS runtime

# 复制时区数据（如需要）
COPY --from=builder /usr/share/zoneinfo /usr/share/zoneinfo
ENV TZ=Asia/Shanghai

# 复制SSL证书
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/

# 复制应用
COPY --from=builder /build/app /app
COPY --from=builder /build/config /config

# 健康检查
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
    CMD ["/app", "health"]

# 使用非root用户（通过scratch镜像需要特殊处理）
USER 10001:10001

EXPOSE 8080
CMD ["/app"]

构建命令： ​

bash
# 完整构建
docker build \
  --target runtime \
  -t myapp:latest .

# 仅构建测试阶段
docker build \
  --target tester \
  -t myapp:test .

# 带构建参数
docker build \
  --build-arg VERSION=2.0.0 \
  --build-arg COMMIT_HASH=$(git rev-parse --short HEAD) \
  --build-arg BUILD_TIME=$(date -u +'%Y-%m-%dT%H:%M:%SZ') \
  -t myapp:$COMMIT_HASH .

3.2 Node.js应用多阶段构建 ​

完整示例： ​

dockerfile
# 第一阶段：基础依赖
FROM node:18-alpine AS base
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production --ignore-scripts
# 保存生产依赖用于运行时

# 第二阶段：开发依赖（用于构建）
FROM node:18-alpine AS dev-deps
WORKDIR /app
COPY package*.json ./
RUN npm ci --include=dev

# 第三阶段：构建器
FROM node:18-alpine AS builder
WORKDIR /app

# 从dev-deps复制node_modules
COPY --from=dev-deps /app/node_modules ./node_modules
COPY . .

# 环境变量
ARG NODE_ENV=production
ENV NODE_ENV=${NODE_ENV}

# 构建应用
RUN npm run build

# 第四阶段：测试（可选）
FROM builder AS test
RUN npm test

# 第五阶段：运行阶段
FROM node:18-alpine AS runner
WORKDIR /app

# 创建非root用户
RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nodejs

# 从base复制生产依赖
COPY --from=base /app/node_modules ./node_modules

# 从builder复制构建产物
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/package.json ./package.json

# 复制必要的配置文件
COPY --from=builder /app/.env.example ./.env

# 设置权限
RUN chown -R nodejs:nodejs /app

# 切换用户
USER nodejs

# 暴露端口
EXPOSE 3000

# 健康检查
HEALTHCHECK --interval=30s --timeout=10s --start-period=30s \
    CMD node -e "require('http').get('http://localhost:3000/health', (r) => { if (r.statusCode !== 200) throw new Error() })"

# 启动命令（使用node而不是npm start）
CMD ["node", "dist/index.js"]

优化技巧： ​

dockerfile
# 使用npm缓存层（加速后续构建）
FROM node:18-alpine AS npm-cache
WORKDIR /app
COPY package*.json ./
RUN npm cache clean --force && \
    npm ci --only=production --prefer-offline --no-audit

# 分离依赖安装，利用Docker缓存
# package.json不变时，不会重新安装依赖

3.3 Java应用多阶段构建 ​

完整示例： ​

dockerfile
# 第一阶段：构建阶段
FROM eclipse-temurin:17-jdk-jammy AS builder

# 设置Maven缓存
ARG MAVEN_OPTS="-Dmaven.repo.local=/tmp/maven-repo"
ENV MAVEN_OPTS=${MAVEN_OPTS}

WORKDIR /workspace

# 复制构建文件
COPY mvnw .
COPY .mvn .mvn
COPY pom.xml .
COPY src src

# 下载依赖（单独步骤以利用缓存）
RUN ./mvnw dependency:go-offline -B

# 构建应用（跳过测试）
RUN ./mvnw clean package -DskipTests

# 第二阶段：提取JAR文件
FROM eclipse-temurin:17-jdk-jammy AS extractor
WORKDIR /workspace
COPY --from=builder /workspace/target/*.jar app.jar

# 解压JAR以分离依赖（减小最终镜像）
RUN java -Djarmode=layertools -jar app.jar extract

# 第三阶段：运行阶段
FROM eclipse-temurin:17-jre-jammy AS runtime

# 安装必要工具
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
    curl \
    tini && \
    rm -rf /var/lib/apt/lists/*

# 创建应用用户
RUN groupadd -r spring && useradd -r -g spring spring
USER spring:spring

WORKDIR /application

# 分层复制（优化镜像构建）
COPY --from=extractor --chown=spring:spring dependencies/ ./
COPY --from=extractor --chown=spring:spring spring-boot-loader/ ./
COPY --from=extractor --chown=spring:spring snapshot-dependencies/ ./
COPY --from=extractor --chown=spring:spring application/ ./

# JVM参数优化
ENV JAVA_OPTS="-XX:+UseG1GC -XX:MaxRAMPercentage=75 -XX:+ExitOnOutOfMemoryError"
ENV JAVA_TOOL_OPTIONS="-XX:+UseContainerSupport"

# 使用tini作为init进程
ENTRYPOINT ["tini", "-g", "--"]

# 健康检查
HEALTHCHECK --interval=30s --timeout=3s --start-period=60s \
    CMD curl -f http://localhost:8080/actuator/health || exit 1

EXPOSE 8080
CMD ["java", "org.springframework.boot.loader.JarLauncher"]

3.4 Python应用多阶段构建 ​

完整示例： ​

dockerfile
# 第一阶段：构建阶段
FROM python:3.11-slim AS builder

WORKDIR /app

# 安装构建依赖
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
    gcc \
    g++ \
    python3-dev \
    libpq-dev && \

# 安装依赖（生产环境）
RUN pip install --no-cache-dir --upgrade pip && \
    pip install --no-cache-dir -r requirements.txt

# 复制应用代码并安装
COPY . .
RUN pip install --no-cache-dir -e .

# 运行测试（可选）
FROM builder AS tester
RUN pip install -r requirements-dev.txt
RUN pytest --cov=app --cov-report=html

# 第二阶段：运行阶段
FROM python:3.11-slim AS runtime

# 安装运行时依赖
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
    libpq5 \
    curl && \
    rm -rf /var/lib/apt/lists/*

# 创建非root用户
RUN groupadd -r appuser && useradd -r -g appuser appuser

# 从构建阶段复制虚拟环境
COPY --from=builder /opt/venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"

# 复制应用代码
COPY --chown=appuser:appuser . .

# 设置权限
RUN chown -R appuser:appuser /app
USER appuser

# 创建必要的目录
RUN mkdir -p /app/logs /app/data

# 环境变量
ENV PYTHONUNBUFFERED=1 \
    PYTHONDONTWRITEBYTECODE=1 \
    PYTHONPATH=/app

# 健康检查
HEALTHCHECK --interval=30s --timeout=10s --start-period=40s \
    CMD python -c "import requests; requests.get('http://localhost:8000/health', timeout=5)"

EXPOSE 8000

# 使用gunicorn运行
CMD ["gunicorn", "--bind", "0.0.0.0:8000", "--workers", "4", "--threads", "2", "app:app"]

四、高级多阶段构建技巧 ​

4.1 多架构构建支持 ​

dockerfile
# 构建x86_64和arm64架构的镜像
FROM --platform=$BUILDPLATFORM golang:1.21-alpine AS builder

ARG TARGETOS TARGETARCH
WORKDIR /app

# 根据目标架构编译
RUN GOOS=$TARGETOS GOARCH=$TARGETARCH go build -o /app/myapp .

# 多架构运行镜像
FROM --platform=$TARGETPLATFORM alpine:3.18
COPY --from=builder /app/myapp /app/myapp
CMD ["/app/myapp"]

构建命令： ​

bash
# 创建构建器实例
docker buildx create --name multiarch --use

# 构建多架构镜像
docker buildx build \
  --platform linux/amd64,linux/arm64 \
  -t username/myapp:latest \
  --push .

4.2 使用BuildKit高级特性 ​

dockerfile
# syntax=docker/dockerfile:1.4
FROM alpine:3.18 AS base

# 1. 缓存挂载（加速依赖安装）
RUN --mount=type=cache,target=/var/cache/apk \
    apk add --update --no-cache nodejs npm

# 2. 秘密挂载（安全处理敏感信息）
RUN --mount=type=secret,id=npmrc,target=/root/.npmrc \
    npm install

# 3. SSH挂载（从私有仓库拉取代码）
RUN --mount=type=ssh \
    git clone git@github.com:user/private-repo.git

# 4. 绑定挂载（构建上下文外部的文件）
RUN --mount=type=bind,source=/host/path,target=/container/path \
    cp /container/path/config.json /app/

启用BuildKit构建： ​

bash
# 方法1：环境变量
export DOCKER_BUILDKIT=1
docker build -t myapp .

# 方法2：使用docker buildx
docker buildx build -t myapp .

# 完整构建命令示例
docker build \
  --secret id=npmrc,src=$HOME/.npmrc \
  --ssh default \
  -t myapp:latest .

4.3 动态多阶段构建 ​

dockerfile
# 根据参数选择不同的构建阶段
ARG BUILD_TYPE=production

FROM alpine:3.18 AS base
# 基础配置...

# 开发构建阶段
FROM base AS development-build
RUN apk add --no-cache \
    git \

    debug-tools

# 生产构建阶段
FROM base AS production-build

    curl \

# 最终阶段，根据BUILD_TYPE选择
FROM ${BUILD_TYPE}-build AS final

# 根据环境配置应用
COPY docker/${BUILD_TYPE}/config /app/config
COPY docker/${BUILD_TYPE}/entrypoint.sh /entrypoint.sh

CMD ["/entrypoint.sh"]

五、性能优化策略 ​

dockerfile

FROM node:18-alpine
COPY . .
RUN npm install && npm run build  # 任何文件变动都会导致npm install重新执行

# 1. 单独复制package文件

# 3. 复制源代码（依赖安装被缓存）
COPY . .

# 4. 构建应用
RUN npm run build

# 并行构建前端和后端
FROM node:18-alpine AS frontend-builder
WORKDIR /frontend
COPY frontend/package*.json ./
RUN npm ci
COPY frontend/ .
RUN npm run build

FROM golang:1.21-alpine AS backend-builder
WORKDIR /backend
COPY backend/go.mod backend/go.sum ./
RUN go mod download
COPY backend/ .
RUN CGO_ENABLED=0 go build -o app .

# 合并构建结果
FROM nginx:alpine
COPY --from=frontend-builder /frontend/dist /usr/share/nginx/html
COPY --from=backend-builder /backend/app /app/
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80

六、安全最佳实践 ​

6.1 最小权限原则 ​

dockerfile
# 第一阶段：构建（需要root权限）
FROM golang:1.21-alpine AS builder
RUN apk add --no-cache git ca-certificates

# 第二阶段：运行（非root用户）
FROM scratch

# 从builder复制CA证书
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/

# 从builder复制编译好的二进制文件
COPY --from=builder /go/bin/app /app

# 创建非root用户（在scratch中需要特殊处理）
# 使用静态编译时指定的用户ID
USER 10001:10001

CMD ["/app"]

name: Docker Build and Push

  push:
    branches: [main]

    branches: [main]

  build:

      id: meta
      uses: docker/metadata-action@v4

          type=ref,event=branch
          type=ref,event=pr
          type=semver,pattern={{version}}
          type=semver,pattern={{major}}.{{minor}}
    
    - name: Build and push
      uses: docker/build-push-action@v4
      with:
        context: .
        file: ./Dockerfile
        push: ${{ github.event_name != 'pull_request' }}
        tags: ${{ steps.meta.outputs.tags }}
        labels: ${{ steps.meta.outputs.labels }}
        cache-from: type=gha
        cache-to: type=gha,mode=max

8.2 常见问题解决 ​

dockerfile
# 问题1：COPY --from找不到阶段
# 解决方案：确保阶段名称正确，或使用阶段索引

# 问题2：scratch镜像中缺少库文件
# 解决方案：静态编译或从其他阶段复制必要文件
FROM alpine:3.18 AS libs
RUN apk add --no-cache libc6-compat

FROM scratch
COPY --from=libs /lib/ld-musl-x86_64.so.1 /lib/

# 问题3：权限问题
# 解决方案：在复制文件时设置权限
COPY --chown=appuser:appuser --from=builder /app /app

# 问题4：时区问题
# 解决方案：从基础镜像复制时区文件
COPY --from=builder /usr/share/zoneinfo /usr/share/zoneinfo
ENV TZ=Asia/Shanghai

九、最佳实践总结 ​

9.1 多阶段构建检查清单 ​

  • [ ] 分离构建与运行时环境

    • 使用不同的基础镜像
    • 仅复制必要的运行时文件

  • [ ] 优化构建缓存

    • 分层安装依赖
    • 利用Docker构建缓存

  • [ ] 安全加固

    • 使用非root用户运行
    • 删除敏感信息和构建工具
    • 定期扫描安全漏洞

  • [ ] 镜像最小化

    • 使用轻量级基础镜像（alpine、scratch、distroless）
    • 删除不必要的文件和缓存
    • 合并RUN指令减少层数

  • [ ] 可观测性

    • 添加健康检查
    • 设置适当的元数据标签
    • 配置适当的日志输出
