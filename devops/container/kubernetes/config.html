一、配置管理基础概念 ​

1.1 配置管理的重要性 ​

在云原生环境中，配置管理需要解决：

  • 环境差异性：开发、测试、生产环境配置分离
  • 配置一致性：确保不同实例使用相同配置
  • 配置安全性：敏感信息（密码、密钥）保护
  • 配置动态性：运行时配置更新能力
  • 配置版本化：跟踪配置变更历史

二、ConfigMap详解 ​

2.1 ConfigMap基础 ​

2.1.1 ConfigMap定义 ​

yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: default
  labels:
    app: myapp
    environment: production
  annotations:
    description: "Application configuration"
    version: "1.0.0"
data:
  # 键值对格式
  APP_NAME: "My Application"
  LOG_LEVEL: "INFO"
  MAX_CONNECTIONS: "100"
  
  # 文件格式内容
  application.properties: |
    server.port=8080
    server.host=0.0.0.0
    db.url=jdbc:mysql://db-host:3306/appdb
    cache.ttl=3600
    
  nginx.conf: |
    server {
      listen 80;
      server_name localhost;
      
      location / {
        proxy_pass http://backend:8080;
        proxy_set_header Host $host;
      }
    }
  
binaryData:
  # 二进制数据（base64编码）
  icon.png: "iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8/5+hHgAHggJ/PchI7wAAAABJRU5ErkJggg=="

2.1.2 ConfigMap创建方式 ​

bash
# 1. 从字面值创建
kubectl create configmap game-config \
  --from-literal=player_initial_lives="3" \
  --from-literal=ui_properties_file_name="user-interface.properties"

# 2. 从文件创建
kubectl create configmap game-config \
  --from-file=game.properties \
  --from-file=ui.properties

# 3. 从目录创建
kubectl create configmap game-config \
  --from-file=configs/

# 4. 从.env文件创建
kubectl create configmap env-config \
  --from-env-file=.env

# 5. 从YAML文件创建
kubectl apply -f configmap.yaml

2.2 ConfigMap使用方式 ​

2.2.1 作为环境变量 ​

yaml
apiVersion: v1
kind: Pod
metadata:
  name: configmap-env-pod
spec:
  containers:
  - name: test-container
    image: busybox
    command: ["/bin/sh", "-c", "env"]
    
    # 单个环境变量引用
    env:
    - name: LOG_LEVEL
      valueFrom:
        configMapKeyRef:
          name: app-config
          key: LOG_LEVEL
          optional: true  # 可选配置，ConfigMap不存在时不报错
    
    # 批量注入环境变量
    envFrom:
    - configMapRef:
        name: app-config
        optional: true
    - prefix: "DB_"  # 添加前缀
      configMapRef:
        name: db-config

2.2.2 作为命令行参数 ​

yaml
apiVersion: v1
kind: Pod
metadata:
  name: configmap-args-pod
spec:
  containers:
  - name: test-container
    image: busybox
    command: ["/bin/sh", "-c", "echo $(APP_NAME) $(LOG_LEVEL)"]
    env:
    - name: APP_NAME
      valueFrom:
        configMapKeyRef:
          name: app-config
          key: APP_NAME
    - name: LOG_LEVEL
      valueFrom:
        configMapKeyRef:
          name: app-config
          key: LOG_LEVEL

2.2.3 作为卷挂载 ​

yaml
apiVersion: v1
kind: Pod
metadata:
  name: configmap-volume-pod
spec:
  containers:
  - name: test-container
    image: nginx
    volumeMounts:
    - name: config-volume
      mountPath: /etc/config
      readOnly: true
      
    - name: app-config-volume
      mountPath: /etc/application.properties
      subPath: application.properties  # 挂载单个文件
      readOnly: true
  
  volumes:
  - name: config-volume
    configMap:
      name: app-config
      
  - name: app-config-volume
    configMap:
      name: app-config
      items:
      - key: application.properties
        path: application.properties
      defaultMode: 0644  # 设置文件权限

2.2.4 多种挂载模式对比 ​

yaml
volumes:
- name: config-volume
  configMap:
    name: app-config
    
    # 模式1：挂载所有键作为文件
    # 目录结构：
    # /etc/config/APP_NAME
    # /etc/config/LOG_LEVEL
    # /etc/config/application.properties
    
    # 模式2：选择性挂载
    items:
    - key: application.properties
      path: app.properties  # 重命名
    
    # 模式3：设置文件权限
    defaultMode: 0644
    
    # 模式4：可选配置（1.21+）
    optional: true

2.3 ConfigMap高级特性 ​

2.3.1 不可变ConfigMap ​

yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: immutable-config
immutable: true  # 设置为不可变
data:
  config.json: |
    {
      "featureFlags": {
        "newUI": true,
        "experimental": false
      }
    }

不可变ConfigMap优势：

  • 防止意外修改
  • 减少apiserver负载
  • 提高安全性
  • 性能优化（减少watch操作）

2.3.2 ConfigMap热更新 ​

yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: hot-reload-app
spec:
  replicas: 3
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
      
  template:
    metadata:
      annotations:
        # 添加ConfigMap摘要，触发Pod重启
        checksum/config: "{{ include (print $.Template.BasePath "/configmap.yaml") . | sha256sum }}"
    
    spec:
      containers:
      - name: app
        image: myapp:latest
        lifecycle:
          postStart:
            exec:
              # 监控配置变化脚本
              command: ["/bin/sh", "-c", "inotifywait -m /etc/config -e create,modify,delete | while read; do reload-app; done"]
        
        volumeMounts:
        - name: config-volume
          mountPath: /etc/config
          readOnly: true
  
  volumes:
  - name: config-volume
    configMap:
      name: app-config

热更新策略：

  1. Sidecar监控模式：使用sidecar容器监控配置变化
  2. 信号通知模式：通过发送信号通知应用重载
  3. 应用内监控模式：应用自身监控文件变化
  4. 滚动更新模式：修改ConfigMap触发Pod重启

2.3.3 ConfigMap大小限制 ​

yaml
# 最佳实践：分拆大ConfigMap
apiVersion: v1
kind: ConfigMap
metadata:
  name: large-config-part1
data:
  part1.json: |
    { /* 第一部分配置，小于1MB */ }

---
apiVersion: v1
kind: ConfigMap
metadata:
  name: large-config-part2
data:
  part2.json: |
    { /* 第二部分配置，小于1MB */ }

限制说明：

  • 单个ConfigMap最大1MB（etcd限制）
  • 考虑分拆或使用外部存储
  • 使用ConfigMap投影（Projected Volume）

kubectl get events --field-selector involvedObject.kind=Secret --watch

四、高级配置管理方案 ​

4.1 Downward API ​

4.1.1 环境变量方式 ​

yaml
apiVersion: v1
kind: Pod
metadata:
  name: downward-api-env-pod
  labels:
    zone: us-east-1a
    app: myapp
  annotations:
    build: "2024.01.15-1234"
    commit: "abc123def"
spec:
  containers:
  - name: client-container
    image: busybox
    command: ["sh", "-c", "printenv && sleep 3600"]
    
    # 注入Pod字段
    env:
    - name: POD_NAME
      valueFrom:
        fieldRef:
          fieldPath: metadata.name
    - name: POD_NAMESPACE
      valueFrom:
        fieldRef:
          fieldPath: metadata.namespace
    - name: POD_IP
      valueFrom:
        fieldRef:
          fieldPath: status.podIP
    - name: NODE_NAME
      valueFrom:
        fieldRef:
          fieldPath: spec.nodeName
    - name: SERVICE_ACCOUNT
      valueFrom:
        fieldRef:
          fieldPath: spec.serviceAccountName
    
    # 注入资源字段
    - name: MY_CPU_REQUEST
      valueFrom:
        resourceFieldRef:
          containerName: client-container
          resource: requests.cpu
          divisor: "1m"  # 可选的除数
    
    - name: MY_MEMORY_LIMIT
      valueFrom:
        resourceFieldRef:
          containerName: client-container
          resource: limits.memory
          divisor: 1Mi
    
    # 注入标签和注解
    - name: POD_LABELS
      valueFrom:
        fieldRef:
          fieldPath: metadata.labels
    - name: POD_ANNOTATIONS
      valueFrom:
        fieldRef:
          fieldPath: metadata.annotations
  
  restartPolicy: Never

    # 4. 检查配置文件
    echo -e "\n4. 配置文件:"
    kubectl -n $NAMESPACE exec $POD_NAME -- find /etc/config -type f 2>/dev/null || echo "未找到配置目录"
    
    # 5. 检查配置内容
    echo -e "\n5. 配置内容示例:"
    kubectl -n $NAMESPACE exec $POD_NAME -- sh -c 'for f in $(find /etc/config -type f 2>/dev/null | head -5); do echo "=== $f ==="; cat $f; echo; done' 2>/dev/null
    
    # 6. 检查Secret挂载
    echo -e "\n6. Secret文件权限:"
    kubectl -n $NAMESPACE exec $POD_NAME -- sh -c 'find /etc/secrets -type f -exec ls -la {} \; 2>/dev/null | head -5'
}

九、总结与最佳实践 ​

9.1 配置管理黄金法则 ​

  1. 分离原则

    • 配置与代码分离
    • 敏感与非敏感配置分离
    • 环境配置分离

  2. 安全原则

    • 最小权限访问
    • 加密存储敏感数据
    • 定期轮换密钥

  3. 可观测性原则

    • 配置变更追踪
    • 配置漂移检测
    • 配置健康监控

  4. 可靠性原则

    • 配置验证与校验
    • 回滚机制
    • 备份与恢复
