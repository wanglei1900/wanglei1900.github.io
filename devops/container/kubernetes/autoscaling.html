二、Horizontal Pod Autoscaler (HPA) ​

2.1 HPA基础原理 ​

2.1.1 HPA架构 ​

┌─────────────────────────────────────────────────┐
│                   HPA控制器                      │
├─────────────────────────────────────────────────┤
│ 1. 查询Metrics API获取指标                      │
│ 2. 计算期望副本数                               │
│ 3. 更新Deployment/StatefulSet副本数             │
└─────────────────────────────────────────────────┘
        ↓
┌─────────────────────────────────────────────────┐
│                Metrics API                       │
├─────────────────────────────────────────────────┤
│ 资源指标 ← Metrics Server                       │
│ 自定义指标 ← Prometheus Adapter                 │
│ 外部指标 ← 外部适配器                           │
└─────────────────────────────────────────────────┘

2.1.2 HPA核心算法 ​

go
// HPA计算公式
期望副本数 = ceil[当前副本数 × (当前指标值 / 目标指标值)]

// 多指标计算
对于每个指标：
    desiredReplicas[i] = ceil(currentReplicas * (currentMetricValue[i] / targetMetricValue[i]))
最终副本数 = max(desiredReplicas[1], desiredReplicas[2], ...)

2.2 HPA配置详解 ​

2.2.1 基础HPA配置 ​

yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: php-apache
  namespace: default
  labels:
    app: php-apache
    type: hpa
  annotations:
    description: "HPA for PHP Apache application"
    version: "2.0"
spec:
  # 目标伸缩对象
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: php-apache
    
  # 副本数范围
  minReplicas: 1
  maxReplicas: 10
  
  # 指标配置
  metrics:
  # 1. 资源指标 - CPU
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization  # 或 AverageValue
        averageUtilization: 50  # 目标CPU使用率50%
        # averageValue: 200m  # 或使用绝对值
  
  # 2. 资源指标 - 内存
  - type: Resource
    resource:
      name: memory
      target:
        type: AverageValue
        averageValue: 500Mi  # 目标平均内存使用量
  
  # 3. Pod指标 - 自定义Pod指标
  - type: Pods
    pods:
      metric:
        name: packets-per-second
      target:
        type: AverageValue
        averageValue: 1000
  
  # 4. 对象指标 - 基于Kubernetes对象
  - type: Object
    object:
      metric:
        name: requests-per-second
      describedObject:
        apiVersion: networking.k8s.io/v1
        kind: Ingress
        name: main-route
      target:
        type: Value
        value: 10000
  
  # 5. 外部指标 - 来自外部系统
  - type: External
    external:
      metric:
        name: queue_messages_ready
        selector:
          matchLabels:
            queue: "worker_tasks"
      target:
        type: AverageValue
        averageValue: "30"
  
  # 行为配置（Kubernetes 1.18+）
  behavior:
    # 扩容行为
    scaleUp:
      stabilizationWindowSeconds: 0
      policies:
      - type: Pods
        value: 4
        periodSeconds: 15
      - type: Percent
        value: 100
        periodSeconds: 15
      selectPolicy: Max  # 选择最大变化值
    
    # 缩容行为  
    scaleDown:
      stabilizationWindowSeconds: 300  # 5分钟稳定窗口
      policies:
      - type: Pods
        value: 1
        periodSeconds: 60
      - type: Percent
        value: 10
        periodSeconds: 60
      selectPolicy: Min  # 选择最小变化值

2.2.2 HPA行为配置详解 ​

yaml
behavior:
  # 扩容配置
  scaleUp:
    # 稳定窗口：指标波动时防止频繁扩容
    stabilizationWindowSeconds: 0
    
    # 策略列表
    policies:
    - type: Pods          # 按Pod数量
      value: 4            # 每次最多增加4个Pod
      periodSeconds: 15   # 每15秒评估一次
    
    - type: Percent       # 按百分比
      value: 100          # 每次最多翻倍
      periodSeconds: 15
    
    # 选择策略
    selectPolicy: Max     # 取两个策略中的最大值
    
  # 缩容配置  
  scaleDown:
    # 稳定窗口：防止短时下降导致缩容
    stabilizationWindowSeconds: 300
    
    policies:
    - type: Pods
      value: 1            # 每次最多减少1个Pod
      periodSeconds: 60   # 每60秒评估一次
    
    - type: Percent
      value: 10           # 每次最多减少10%
      periodSeconds: 60
    
    selectPolicy: Min     # 取两个策略中的最小值

2.4.2 HPA故障排查 ​

bash
#!/bin/bash
# HPA故障排查脚本
hpa_troubleshoot() {
    local HPA_NAME=$1
    local NAMESPACE=${2:-default}
    
    echo "=== HPA故障排查: $HPA_NAME ==="
    
    # 1. 检查HPA配置
    echo -e "\n1. HPA配置:"
    kubectl -n $NAMESPACE get hpa $HPA_NAME -o yaml
    
    # 2. 检查目标Deployment
    echo -e "\n2. 目标Deployment状态:"
    TARGET=$(kubectl -n $NAMESPACE get hpa $HPA_NAME -o jsonpath='{.spec.scaleTargetRef.name}')
    kubectl -n $NAMESPACE get deployment $TARGET
    
    # 3. 检查指标可用性
    echo -e "\n3. 检查Metrics API:"
    kubectl get --raw "/apis/metrics.k8s.io/v1beta1" > /dev/null 2>&1 && echo "✓ Metrics API可用" || echo "✗ Metrics API不可用"
    
    # 4. 检查Pod资源请求
    echo -e "\n4. Pod资源请求:"
    kubectl -n $NAMESPACE get pods -l app=$TARGET -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.spec.containers[*].resources.requests}{"\n"}{end}'
    
    # 5. 检查实际资源使用
    echo -e "\n5. 实际资源使用:"
    kubectl -n $NAMESPACE top pods -l app=$TARGET
    
    # 6. 检查HPA事件
    echo -e "\n6. HPA事件:"
    kubectl -n $NAMESPACE get events --field-selector involvedObject.name=$HPA_NAME,involvedObject.kind=HorizontalPodAutoscaler --sort-by='.lastTimestamp'
}

三、Vertical Pod Autoscaler (VPA) ​

3.1 VPA架构原理 ​

3.1.1 VPA组件架构 ​

┌─────────────────────────────────────────────────┐
│               VPA控制器                          │
├─────────────────────────────────────────────────┤
│ 1. Recommender - 计算推荐值                      │
│ 2. Updater - 驱逐Pod应用新资源                   │
│ 3. Admission Controller - 注入新Pod资源         │
└─────────────────────────────────────────────────┘
        ↓
┌─────────────────────────────────────────────────┐
│            Metrics Server                        │
│            Prometheus                            │
└─────────────────────────────────────────────────┘

3.1.2 VPA工作流程 ​

1. Recommender持续监控Pod资源使用
2. 基于历史数据计算资源推荐值
3. Updater检测到需要更新的Pod
4. 优雅驱逐Pod（遵循PDB规则）
5. Admission Controller为新Pod注入推荐资源
6. 新Pod以正确资源启动

3.2 VPA配置详解 ​

3.2.1 VPA资源定义 ​

yaml
apiVersion: autoscaling.k8s.io/v1
kind: VerticalPodAutoscaler
metadata:
  name: recommendation-engine-vpa
  namespace: production
  labels:
    app: recommendation-engine
    component: vpa
  annotations:
    vpa-autoscaling.kubernetes.io/update-mode: "Auto"
    vpa-autoscaling.kubernetes.io/resource-policy: "container-memory"
spec:
  # 目标工作负载
  targetRef:
    apiVersion: "apps/v1"
    kind: "Deployment"
    name: "recommendation-engine"
  
  # 更新策略
  updatePolicy:
    updateMode: "Auto"  # Off, Initial, Auto, Recreate
    minReplicas: 2      # 最小副本数（Auto模式）
    
    # 更新窗口
    updateWindow:
      startTime: "02:00"
      duration: "2h"
  
  # 资源策略
  resourcePolicy:
    containerPolicies:
    # 容器特定策略
    - containerName: "app"
      mode: "Auto"
      controlledResources: ["cpu", "memory"]
      controlledValues: "RequestsAndLimits"  # 或 RequestsOnly
      
      # 最小允许资源
      minAllowed:
        cpu: "100m"
        memory: "250Mi"
      
      # 最大允许资源  
      maxAllowed:
        cpu: "2"
        memory: "4Gi"
      
      # 资源限制比例
      limitCPUToMemoryPercent: 200  # CPU限制是内存的200%
      
    # 通配符匹配所有容器
    - containerName: "*"
      mode: "Auto"
      minAllowed:
        cpu: "50m"
        memory: "100Mi"
      maxAllowed:
        cpu: "1"
        memory: "2Gi"
  
  # 推荐配置
  recommendation:
    # CPU推荐配置
    cpu:
      baseRecommendation:
        target:
          cpu: "500m"
        lowerBound:
          cpu: "300m"
        upperBound:
          cpu: "800m"
      confidenceLevel: 0.95  # 置信水平
    
    # 内存推荐配置  
    memory:
      baseRecommendation:
        target:
          memory: "1Gi"
        lowerBound:
          memory: "512Mi"
        upperBound:
          memory: "2Gi"
      confidenceLevel: 0.90
