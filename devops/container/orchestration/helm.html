第一部分：容器化技术核心概念 ​

1.1 容器技术演进 ​

物理机时代 → 虚拟机时代 → 容器时代
  • 传统部署问题：环境不一致、资源隔离差、部署效率低
  • 虚拟机缺点：资源占用大（每个VM需完整OS）、启动慢
  • 容器优势：
    • 轻量级（共享主机内核）
    • 秒级启动
    • 一致的运行环境
    • 高效的资源利用

1.2 Docker核心技术 ​

yaml
# Docker架构核心组件：
1. Docker Client     # 客户端
2. Docker Daemon    # 守护进程
3. Registry         # 镜像仓库
4. Image            # 镜像（只读模板）
5. Container        # 容器（运行实例）
6. Network          # 网络
7. Volume           # 数据卷

Namespaces（命名空间） - 实现隔离 ​

  • PID Namespace：进程隔离
  • Net Namespace：网络隔离
  • IPC Namespace：进程间通信隔离
  • Mount Namespace：文件系统挂载点隔离
  • UTS Namespace：主机名隔离
  • User Namespace：用户权限隔离

Cgroups（控制组） - 实现资源限制 ​

  • CPU限制
  • 内存限制
  • 磁盘I/O限制
  • 网络带宽限制

UnionFS（联合文件系统） ​

  • 分层镜像结构
  • 写时复制（Copy-on-Write）
  • 镜像复用机制

1.3 容器化实践要点 ​

dockerfile
# Dockerfile最佳实践示例
FROM alpine:3.18 AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci --only=production

FROM alpine:3.18
RUN addgroup -g 1001 -S nodejs && \
    adduser -S nodejs -u 1001
USER nodejs
WORKDIR /app
COPY --from=builder --chown=nodejs:nodejs /app/node_modules ./node_modules
COPY --chown=nodejs:nodejs . .
EXPOSE 3000
CMD ["node", "server.js"]

第二部分：容器编排技术 ​

2.1 为什么需要容器编排？ ​

单容器问题：

  • 单点故障
  • 扩缩容困难
  • 服务发现复杂
  • 网络管理繁琐
  • 存储管理复杂

2.2 Kubernetes核心架构 ​

Kubernetes架构：
控制平面 (Control Plane)
├── API Server（所有操作入口）
├── etcd（集群状态存储）
├── Scheduler（Pod调度）
├── Controller Manager（控制器管理）
└── Cloud Controller Manager（云厂商扩展）

工作节点 (Worker Node)
├── Kubelet（节点代理）
├── Kube-proxy（网络代理）
├── Container Runtime（容器运行时）
└── Pod（最小调度单元）

第三部分：Helm包管理 ​

3.1 Helm解决的问题 ​

原生Kubernetes资源管理痛点：

  • 多环境配置管理复杂
  • 资源文件分散、难以复用
  • 版本控制困难
  • 依赖管理缺失
  • 部署过程缺少生命周期管理

3.2 Helm核心概念 ​

Helm架构：
├── Chart：软件包（包含所有K8s资源定义）
├── Release：Chart的运行实例
├── Repository：Chart仓库
└── Tiller（Helm 2） / 无Tiller（Helm 3）

Helm 2 vs Helm 3 重大变化 ​

特性Helm 2Helm 3
架构客户端/服务器（Tiller）纯客户端
安全性Tiller拥有集群权限RBAC集成
发布管理ConfigMaps中存储Secrets中存储
升级策略Three-way strategic mergeThree-way JSON patch merge
API版本支持多种API版本仅支持最新稳定API

3.3 Helm Chart结构详解 ​

my-chart/
├── Chart.yaml          # Chart元数据

3.4 Helm模板引擎 ​

模板语法基础 ​

yaml
# templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ include "my-chart.fullname" . }}
  labels:
    {{- include "my-chart.labels" . | nindent 4 }}
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      {{- include "my-chart.selectorLabels" . | nindent 6 }}
  template:
    metadata:
      labels:
        {{- include "my-chart.labels" . | nindent 8 }}
        {{- with .Values.podLabels }}
        {{ toYaml . | nindent 8 }}
        {{- end }}
    spec:
      containers:
        - name: {{ .Chart.Name }}
          image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
          imagePullPolicy: {{ .Values.image.pullPolicy }}
          ports:
            - containerPort: {{ .Values.service.targetPort }}
          env:
            {{- range $key, $value := .Values.env }}
            - name: {{ $key }}
              value: {{ $value | quote }}
            {{- end }}
          resources:
            {{- toYaml .Values.resources | nindent 12 }}

模板函数和管道 ​

yaml
# 常用函数示例
name: {{ .Values.name | upper | trunc 20 }}           # 大写并截断
port: {{ .Values.port | default "8080" | int }}       # 默认值并转整数
config: {{ .Values.config | toYaml | indent 2 }}      # 转YAML并缩进
time: {{ now | date "2006-01-02" }}                   # 日期格式化
secret: {{ randAlphaNum 16 | b64enc }}                # 生成随机密钥

控制流语句 ​

yaml
{{- if .Values.ingress.enabled -}}
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: {{ include "my-chart.fullname" . }}
spec:
  {{- if .Values.ingress.className }}
  ingressClassName: {{ .Values.ingress.className }}
  {{- end }}
{{- end }}

{{- range .Values.servers }}
- name: {{ .name }}
  port: {{ .port }}
{{- end }}

{{- with .Values.nodeSelector }}
nodeSelector:
  {{- toYaml . | nindent 2 }}
{{- end }}

命名模板 (_helpers.tpl) ​

yaml
{{/*
生成全名
*/}}
{{- define "my-chart.fullname" -}}
{{- if .Values.fullnameOverride }}
{{- .Values.fullnameOverride | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- $name := default .Chart.Name .Values.nameOverride }}
{{- if contains $name .Release.Name }}
{{- .Release.Name | trunc 63 | trimSuffix "-" }}
{{- else }}
{{- printf "%s-%s" .Release.Name $name | trunc 63 | trimSuffix "-" }}
{{- end }}
{{- end }}
{{- end }}

{{/*
通用标签
*/}}
{{- define "my-chart.labels" -}}
helm.sh/chart: {{ include "my-chart.chart" . }}
{{ include "my-chart.selectorLabels" . }}
{{- if .Chart.AppVersion }}
app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}
{{- end }}
app.kubernetes.io/managed-by: {{ .Release.Service }}
{{- end }}

3.6 Helm实战操作 ​

基础命令 ​

bash
# 仓库操作
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update
helm repo list

# Chart操作
helm search repo nginx                    # 搜索Chart
helm show values bitnami/nginx > values.yaml  # 导出默认值
helm install my-nginx bitnami/nginx -f values.yaml
helm upgrade my-nginx bitnami/nginx -f values.yaml
helm rollback my-nginx 1                  # 回滚到版本1
helm uninstall my-nginx                   # 卸载（Helm 3）
helm list -A                              # 列出所有发布

# 本地开发
helm create mychart                       # 创建新Chart
helm lint mychart                         # 语法检查
helm template mychart --debug             # 渲染模板预览
helm package mychart                      # 打包Chart
helm install myrelease ./mychart --dry-run  # 干跑测试

多环境部署策略 ​

bash
# 开发环境
helm install myapp ./chart -f values.yaml -f env/dev.yaml -n dev

# 生产环境
helm upgrade myapp ./chart -f values.yaml -f env/prod.yaml -n prod

# 使用--set覆盖特定值
helm upgrade myapp ./chart --set replicaCount=5 --set image.tag=v2.0.0

3.8 Helm最佳实践 ​

1. 版本管理策略 ​

yaml
# Chart.yaml版本遵循SemVer
version: 1.2.3  # MAJOR.MINOR.PATCH
# MAJOR: 不兼容的API变更
# MINOR: 向后兼容的功能性新增
# PATCH: 向后兼容的问题修复

2. 值文件组织 ​

chart/
├── values.yaml          # 默认值
├── values-dev.yaml      # 开发环境
├── values-staging.yaml  # 预发布环境
├── values-prod.yaml     # 生产环境
└── secrets/             # 加密值文件（使用secrets-manager）

3. 模板设计原则 ​

  • 保持模板DRY（Don't Repeat Yourself）
  • 使用命名模板复用代码
  • 模板中避免复杂逻辑
  • 提供合理的默认值

4. 安全最佳实践 ​

bash
# 使用secrets管理敏感信息
helm install myapp . --set database.password=$DB_PASSWORD

# 使用外部secret存储
helm install myapp . --set-file ssl.certificate=./cert.pem

# 定期更新依赖
helm dependency update

工具集成：

  - test
  - package
  - deploy

lint-chart:
  stage: lint
  script:
    - helm lint ./chart
    - helm template ./chart --debug

package-chart:
  stage: package
  script:
    - helm package ./chart --version ${CI_COMMIT_TAG}
    - helm push webapp-${CI_COMMIT_TAG}.tgz oci://${REGISTRY}/charts

deploy-dev:
  stage: deploy
  script:
    - helm upgrade --install webapp-dev ./chart -f values-dev.yaml -n dev

deploy-prod:
  stage: deploy
  when: manual
  script:
    - helm upgrade --install webapp-prod ./chart -f values-prod.yaml -n prod

  4. Chart拆分策略：核心应用与依赖分离
  5. 缓存策略：使用稳定的镜像标签
