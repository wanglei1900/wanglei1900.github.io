第一部分：Kustomize 基础概念 ​

1.1 Kustomize 是什么？ ​

定义：Kubernetes 原生的配置管理工具，采用"声明式"、"无模板"的方式管理 Kubernetes 资源配置。

核心理念：

  • 纯 YAML 驱动：无需学习新的模板语言
  • 叠加（Overlay）模式：基础配置 + 环境特定修改
  • GitOps 友好：配置即代码，版本控制友好
  • 声明式操作：描述"应该是什么状态"

1.2 Kustomize vs Helm 对比 ​

维度KustomizeHelm
哲学配置组合、补丁模板渲染、包管理
语法纯 YAML + KustomizationGo 模板 + Values
复杂性低（Kubernetes 原生）中（需学习模板语法）
场景多环境配置管理应用打包分发
集成已集成到 kubectl (v1.14+)独立工具
复用性通过 base/overlay 复用通过模板参数化

1.3 为什么选择 Kustomize？ ​

解决的问题：

yaml
# 问题：多环境配置文件重复
├── deployment-dev.yaml    # 90%内容相同
├── deployment-stg.yaml    # 90%内容相同
└── deployment-prod.yaml   # 90%内容相同

# 方案：使用 Kustomize
├── base/                  # 通用配置（100%）
└── overlays/              
    ├── dev/              # 仅环境差异配置（10%）
    ├── stg/              # 仅环境差异配置（10%）
    └── prod/             # 仅环境差异配置（10%）

第二部分：Kustomize 核心概念详解 ​

2.1 核心架构 ​

Kustomize 工作流：
Base（基础配置）
├── kustomization.yaml    # 入口文件
├── deployment.yaml       # 通用 Deployment
├── service.yaml         # 通用 Service
└── configmap.yaml       # 通用 ConfigMap

Overlay（环境覆盖）
├── kustomization.yaml    # 引用 base + 环境补丁
├── patch-deployment.yaml # 环境特定修改
└── patch-configmap.yaml  # 环境特定修改

2.2 kustomization.yaml 结构解析 ​

yaml
# kustomization.yaml 核心字段
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

# 1. 资源引用
resources:
  - ../base                     # 引用目录
  - deployment.yaml            # 引用文件
  - github.com/owner/repo?ref=main  # 远程资源

# 2. 生成器
configMapGenerator:           # 动态生成 ConfigMap
secretGenerator:              # 动态生成 Secret

# 3. 转换器
patchesStrategicMerge:        # 策略合并补丁
patchesJson6902:              # JSON 补丁
images:                       # 镜像修改
replacements:                 # 字段替换（v4.5+）
namePrefix:                   # 名称前缀
nameSuffix:                   # 名称后缀
namespace:                    # 命名空间
commonLabels:                 # 通用标签
commonAnnotations:            # 通用注解

# 4. 校验和生成器
generators:                   # 自定义生成器
transformers:                 # 自定义转换器
validators:                   # 自定义校验器

第三部分：Kustomize 核心功能详解 ​

3.1 资源组合（Resources） ​

yaml
# 组合多个资源文件
resources:
  - deployment.yaml
  - service.yaml
  - ingress.yaml
  - ../another-base        # 引用另一个 base
  - github.com/org/repo/deploy?ref=v1.0  # 远程资源
  - https://example.com/manifest.yaml    # URL 资源

3.2 名称变换（Name Prefix/Suffix） ​

yaml
# 为所有资源添加前缀/后缀
namePrefix: dev-           # 添加前缀：dev-<资源名>
nameSuffix: -v1           # 添加后缀：<资源名>-v1
namespace: my-namespace   # 设置命名空间

# 变换效果：
# deployment.yaml → dev-deployment-v1.yaml
# 在 my-namespace 命名空间中

3.3 标签和注解（Labels & Annotations） ​

yaml
# 1. 通用标签和注解（添加到所有资源）
commonLabels:
  app.kubernetes.io/name: myapp
  app.kubernetes.io/version: v1.0
  environment: production

commonAnnotations:
  owner: team-a
  description: "Production deployment"

# 2. 为特定资源添加标签
labels:
  - pairs:
      custom-label: special-value
    includeSelectors: true    # 是否添加到 selector
    includeTemplates: true    # 是否添加到 pod template
    fields:
      - kind: Deployment
        name: my-deployment

3.4 镜像修改（Images） ​

yaml
# 修改容器镜像（支持多种格式）
images:
  # 格式1：完整格式
  - name: nginx
    newName: myregistry/nginx
    newTag: v1.21
    digest: sha256:abc123...
  
  # 格式2：简写格式
  - nginx=myregistry/nginx:v1.21
  
  # 格式3：仅修改tag
  - name: app
    newTag: v2.0
  
  # 格式4：通配符匹配
  - name: "postgres:*"
    newName: internal-registry/postgres

3.5 配置生成器（Generators） ​

ConfigMapGenerator ​

yaml
configMapGenerator:
  # 方式1：从文件生成
  - name: app-config
    files:
      - config.properties
      - ui-config.json
    options:
      labels:
        app: myapp
      annotations:
        description: "Application configuration"
  
  # 方式2：从字面值生成
  - name: env-config
    literals:
      - LOG_LEVEL=DEBUG
      - MAX_CONNECTIONS=100
  
  # 方式3：从.env文件生成
  - name: dotenv-config
    envs:
      - .env
      - .env.production
  
  # 方式4：行为控制
  - name: auto-update-config
    behavior: merge        # create/merge/replace
    files:
      - config.yaml

SecretGenerator ​

yaml
secretGenerator:
  # 方式1：从文件生成（自动base64编码）
  - name: tls-secret
    files:
      - tls.crt
      - tls.key
    type: kubernetes.io/tls
  
  # 方式2：从字面值生成（自动base64编码）
  - name: db-secret
    literals:
      - username=admin
      - password=secret123
    type: Opaque
  
  # 方式3：从.env文件生成
  - name: app-secrets
    envs:
      - secrets.env
  
  # 方式4：禁用自动base64编码
  - name: plain-secret
    literals:
      - text=plain-text-content
    type: Opaque
    options:
      disableNameSuffixHash: true

3.6 变量替换（Replacements）- v4.5+ 新特性 ​

yaml
replacements:
  # 1. 简单字段替换
  - source:
      kind: ConfigMap
      name: app-config
      fieldPath: data.version
    targets:
      - select:
          kind: Deployment
          name: my-app
        fieldPaths:
          - spec.template.spec.containers.[name=app].image
  
  # 2. 多目标替换
  - source:
      kind: Secret
      name: db-secret
      fieldPath: data.host
    targets:
      - select:
          kind: Deployment
        fieldPaths:
          - spec.template.spec.containers.*.env.[name=DB_HOST].value
  
  # 3. 正则表达式替换
  - source:
      kind: ConfigMap
      name: metadata
      fieldPath: data.domain
    targets:
      - select:
          kind: Ingress
        fieldPaths:
          - spec.rules.*.host
        options:
          delimiter: "."
          index: 0
  
  # 4. 复杂转换
  - source:
      value: production
    targets:
      - select:
          kind: Deployment
        fieldPaths:
          - spec.replicas
        options:
          create: true

3.7 补丁（Patches） ​

Strategic Merge Patch ​

yaml
# patchesStrategicMerge：策略合并补丁
patchesStrategicMerge:
  # 文件形式
  - increase-replicas.yaml
  - add-sidecar.yaml
  
  # 内联形式
  - |
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: my-app
    spec:
      replicas: 5
      template:
        spec:
          containers:
          - name: app
            resources:
              requests:
                memory: "256Mi"

补丁文件示例：

yaml
# increase-replicas.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 5  # 修改副本数

# add-sidecar.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  template:
    spec:
      containers:
      - name: sidecar
        image: busybox:latest
        command: ["sh", "-c", "echo Sidecar running"]

JSON 6902 Patch ​

yaml
# patchesJson6902：更精确的JSON补丁
patchesJson6902:
  # 补丁组1
  - target:
      group: apps
      version: v1
      kind: Deployment
      name: my-app
    path: patch/add-label.json  # 文件路径
    
  # 补丁组2（内联）
  - target:
      group: ""
      version: v1
      kind: Service
      name: my-service
    patch: |  # 内联补丁
      - op: replace
        path: /spec/type
        value: LoadBalancer
      - op: add
        path: /metadata/labels/environment
        value: production

JSON 补丁操作类型：

json
{
  "op": "操作类型",
  "path": "JSON路径",
  "value": "新值"
}
  • add：添加字段
  • remove：删除字段
  • replace：替换字段
  • move：移动字段
  • copy：复制字段
  • test：测试字段值

JSON 路径示例：

/spec/replicas                          # 直接路径
/spec/template/spec/containers/0/image  # 数组索引
/spec/template/spec/containers/[name=app]/image  # 名称选择器

3.8 组件（Components）- v4.0+ 新特性 ​

yaml
# components/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1alpha1
kind: Component

# 组件可包含的功能（与普通kustomization类似）
namePrefix: comp-
patches:
  - target:
      kind: Deployment
    patch: |
      - op: add
        path: /spec/template/spec/containers/-
        value:
          name: component-sidecar
          image: component:latest

# 在 overlay 中引用组件
components:
  - ../../components/monitoring
  - ../../components/logging

4.2 基础命令 ​

bash
# 1. 构建配置（预览）
kustomize build ./overlays/dev
kubectl kustomize ./overlays/dev  # 等效命令

# 2. 构建并应用
kubectl apply -k ./overlays/dev

# 3. 差异比较
kubectl diff -k ./overlays/dev

# 4. 删除资源
kubectl delete -k ./overlays/dev

# 5. 验证配置
kustomize build ./overlays/dev --load-restrictor LoadRestrictionsNone | kubectl apply --dry-run=client -f -

# 6. 输出到文件
kustomize build ./overlays/prod > all-resources.yaml

# 7. 启用 Alpha 功能（v4+）
kustomize build --enable-alpha-plugins ./overlays/dev

bash

bash

5.4 自定义插件开发 ​

go
// 简单插件示例：添加注解
package main

import (
  "sigs.k8s.io/kustomize/api/filters/annotations"
  "sigs.k8s.io/kustomize/api/resmap"
  "sigs.k8s.io/yaml"
)

type plugin struct {
  Annotations map[string]string `json:"annotations,omitempty" yaml:"annotations,omitempty"`
}

func (p *plugin) Config(ldr *loader.Loader, rf *resmap.Factory, config []byte) error {
  return yaml.Unmarshal(config, p)
}

func (p *plugin) Transform(m resmap.ResMap) error {
  for _, res := range m.Resources() {
    res.SetAnnotations(mergeMaps(res.GetAnnotations(), p.Annotations))
  }
  return nil
}

- |
  apiVersion: mycompany.com/v1
  kind: AddAnnotations
  metadata:
    name: notImportantHere
  annotations:
    owner: team-a
    deployed-by: kustomize

7.2 配置管理原则 ​

  1. 单一职责：每个 overlay 只负责一个环境的差异
  2. 最小变更：base 应尽可能通用，overlay 只做必要修改
  3. 版本同步：所有环境使用相同的 base 版本
  4. 秘密分离：敏感数据使用 SecretGenerator 或外部 Secret 管理
  5. 资源命名：使用 namePrefix/nameSuffix 避免冲突

7.3 补丁策略选择指南 ​

场景推荐补丁类型示例
简单字段修改Strategic Merge Patch修改 replicas、image
数组元素操作JSON 6902 Patch添加 sidecar、修改环境变量
跨资源修改Replacements (v4.5+)同步版本号、配置值
复杂转换自定义插件特殊格式转换

9.1 从传统 YAML 迁移 ​

bash
# 步骤1：创建 base
mkdir -p base
cp deployment.yaml service.yaml configmap.yaml base/

# 步骤2：创建 kustomization.yaml
cat > base/kustomization.yaml <<EOF
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - deployment.yaml
  - service.yaml
  - configmap.yaml
EOF

# 步骤3：创建环境覆盖
mkdir -p overlays/dev
cat > overlays/dev/kustomization.yaml <<EOF
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - ../../base
patchesStrategicMerge:
  - patch-deployment.yaml
namePrefix: dev-
namespace: dev
EOF

第十部分：常见问题排查 ​

10.1 常见错误与解决方案 ​

bash
# 错误1：资源重复
# 错误：Resource ... already deployed
# 解决：检查是否有重复的 resources 条目

# 错误2：补丁不匹配
# 错误：no matches for ... 
# 解决：确保补丁的 apiVersion/kind/name 完全匹配

# 错误3：无限递归
# 错误：cycle detected
# 解决：检查 resources 引用是否形成循环

# 错误4：变量替换失败
# 错误：field not found
# 解决：确保 source 资源存在且字段路径正确

# 错误5：哈希后缀变化
# 现象：ConfigMap 名称频繁变化导致滚动更新
# 解决：设置 options.disableNameSuffixHash: true
