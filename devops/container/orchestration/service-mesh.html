第一部分：服务网格基础概念 ​

1.1 什么是服务网格？ ​

定义：服务网格是一个专门的基础设施层，用于处理服务间通信。它是一个可配置的、低延迟的网络架构，旨在实现微服务间的可靠、快速和安全的通信。

核心特性：

  • 透明通信：对应用代码无侵入
  • 网络抽象：解耦应用逻辑与网络通信
  • 可观察性：提供详细的流量指标和追踪
  • 流量管理：细粒度的流量控制能力
  • 安全性：内置的通信安全保障

1.2 微服务架构的挑战 ​

yaml
# 传统微服务通信问题：
1. 服务发现：硬编码IP/端口 vs 动态发现
2. 负载均衡：客户端实现 vs 统一策略
3. 故障处理：每个服务重复实现重试、熔断
4. 安全通信：每个服务单独处理TLS、认证
5. 监控追踪：分布式追踪实现复杂
6. 配置管理：动态配置更新困难

1.3 服务网格 vs 传统方案对比 ​

维度传统方案服务网格
通信逻辑应用代码内实现Sidecar 代理处理
语言依赖每种语言单独实现语言无关
部署复杂度每个服务单独配置统一配置管理
升级维护需要重构应用Sidecar 独立升级
可观察性需要集成监控SDK自动收集指标

1.4 服务网格的核心组件 ​

服务网格架构：
├── 数据平面 (Data Plane)
│   └── Sidecar 代理 (如Envoy) - 处理所有入站/出站流量
│
└── 控制平面 (Control Plane)
    ├── 配置管理
    ├── 证书管理
    └── 策略执行

第二部分：Istio 架构深度解析 ​

2.1 Istio 整体架构 ​

Istio 1.8+ 简化架构：
控制平面 (istiod)
├── Pilot - 流量管理和服务发现
├── Citadel - 安全和身份管理
└── Galley - 配置验证和分发

数据平面
└── Envoy 代理 (Sidecar) - 实际处理流量

2.2 数据平面：Envoy 代理详解 ​

Envoy 核心功能：

yaml
# Envoy 代理职责：
1. 动态服务发现
2. 负载均衡 (HTTP/2, gRPC, TCP)
3. TLS 终止和发起
4. HTTP/2 和 gRPC 代理
5. 断路器
6. 健康检查
7. 基于百分比流量分割的分阶段发布
8. 故障注入
9. 丰富的指标收集

Sidecar 注入模式：

bash
# 手动注入
kubectl apply -f <(istioctl kube-inject -f deployment.yaml)

# 自动注入（基于命名空间）
kubectl label namespace default istio-injection=enabled

# 自动注入（基于Pod注解）
annotations:
  sidecar.istio.io/inject: "true"

2.3 控制平面组件详解 ​

Pilot - 流量管理大脑 ​

yaml
功能分解：
1. 服务发现：集成各种注册中心（Kubernetes、Consul等）
2. 流量管理：将高级路由规则转换为Envoy配置
3. 负载均衡：配置负载均衡策略
4. 故障恢复：配置超时、重试、熔断器
5. 配置分发：通过xDS API向Envoy下发配置

xDS API类型：
- CDS: Cluster Discovery Service
- EDS: Endpoint Discovery Service
- LDS: Listener Discovery Service
- RDS: Route Discovery Service

Citadel - 安全核心 ​

yaml
安全功能：
1. 身份管理：为每个工作负载颁发身份
2. 证书管理：自动证书颁发和轮换
3. 认证策略：服务间认证策略管理
4. 凭证管理：存储和分发TLS证书

工作流程：
1. 工作负载启动时向Citadel请求身份
2. Citadel颁发SPIFFE格式的身份证书
3. 证书自动轮换（默认90天）
4. Envoy使用证书进行mTLS通信

Galley - 配置验证与分发 ​

yaml
职责：
1. 配置摄取：从各种源读取配置
2. 配置验证：验证配置语法和语义
3. 配置分发：将验证后的配置分发给其他组件
4. 配置转换：将用户配置转换为内部表示

支持的配置源：
- Kubernetes Custom Resources
- MCP (Mesh Configuration Protocol) 服务器
- 文件系统

2.4 Istio 1.5+ 架构演进 ​

演进方向：
Istio 1.4 及之前：多组件架构 (Pilot、Galley、Citadel、Mixer)
Istio 1.5：单体架构 (istiod，整合所有控制平面功能)
Istio 1.8+：移除Mixer，遥测功能集成到Envoy

优势：
- 简化部署和维护
- 减少资源消耗
- 提高性能
- 降低复杂度

3.1 流量管理 ​

虚拟服务 (VirtualService) ​

yaml
apiVersion: networking.istio.io/v1beta1
kind: VirtualService
metadata:
  name: reviews-vs
spec:
  hosts:
  - reviews  # 服务名称（K8s Service）
  http:
  - match:
    - headers:
        end-user:
          exact: jason
    route:
    - destination:
        host: reviews
        subset: v2
  - route:  # 默认路由
    - destination:
        host: reviews
        subset: v1
      weight: 80
    - destination:
        host: reviews
        subset: v2
      weight: 20

目标规则 (DestinationRule) ​

yaml
apiVersion: networking.istio.io/v1beta1
kind: DestinationRule
metadata:
  name: reviews-dr
spec:
  host: reviews
  subsets:
  - name: v1
    labels:
      version: v1
  - name: v2
    labels:
      version: v2
    trafficPolicy:
      loadBalancer:
        simple: LEAST_CONN  # 最少连接
      connectionPool:
        tcp:
          maxConnections: 100
        http:
          http1MaxPendingRequests: 1
          http2MaxRequests: 10
      outlierDetection:
        consecutive5xxErrors: 5
        interval: 30s
        baseEjectionTime: 30s
        maxEjectionPercent: 100

网关 (Gateway) ​

yaml
apiVersion: networking.istio.io/v1beta1
kind: Gateway
metadata:
  name: bookinfo-gateway
spec:
  selector:
    istio: ingressgateway  # 使用ingressgateway pod
  servers:
  - port:
      number: 80
      name: http
      protocol: HTTP
    hosts:
    - "*"
    tls:
      httpsRedirect: true  # HTTP重定向到HTTPS
  - port:
      number: 443
      name: https
      protocol: HTTPS
    hosts:
    - bookinfo.example.com
    tls:
      mode: SIMPLE
      credentialName: bookinfo-tls-cert

服务入口 (ServiceEntry) ​

yaml
apiVersion: networking.istio.io/v1beta1
kind: ServiceEntry
metadata:
  name: external-api
spec:
  hosts:
  - api.example.com
  ports:
  - number: 443
    name: https
    protocol: HTTPS
  resolution: DNS
  location: MESH_EXTERNAL
  
  # 流量策略
  trafficPolicy:
    tls:
      mode: SIMPLE  # 启用TLS
    loadBalancer:
      simple: ROUND_ROBIN

3.2 安全功能 ​

对等认证 (PeerAuthentication) ​

yaml
apiVersion: security.istio.io/v1beta1
kind: PeerAuthentication
metadata:
  name: default
  namespace: istio-system
spec:
  mtls:
    mode: STRICT  # 严格mTLS
---
# 命名空间级别
apiVersion: security.istio.io/v1beta1
kind: PeerAuthentication
metadata:
  name: backend-auth
  namespace: backend
spec:
  mtls:
    mode: STRICT
---
# 工作负载级别
apiVersion: security.istio.io/v1beta1
kind: PeerAuthentication
metadata:
  name: productpage-auth
spec:
  selector:
    matchLabels:
      app: productpage
  mtls:
    mode: PERMISSIVE  # 允许明文和TLS

请求认证 (RequestAuthentication) ​

yaml
apiVersion: security.istio.io/v1beta1
kind: RequestAuthentication
metadata:
  name: jwt-auth
  namespace: frontend
spec:
  selector:
    matchLabels:
      app: frontend
  jwtRules:
  - issuer: "https://accounts.google.com"
    jwksUri: "https://www.googleapis.com/oauth2/v3/certs"
    audiences:
    - "bookinfo.apps.example.com"
    jwtHeaders:
    - "x-goog-iap-jwt-assertion"
    jwtParams:
    - "access_token"

授权策略 (AuthorizationPolicy) ​

yaml
apiVersion: security.istio.io/v1beta1
kind: AuthorizationPolicy
metadata:
  name: httpbin-policy
spec:
  selector:
    matchLabels:
      app: httpbin
  action: DENY  # 默认拒绝
  rules:
  - from:
    - source:
        principals: ["cluster.local/ns/default/sa/sleep"]
    to:
    - operation:
        methods: ["GET"]
        paths: ["/info*"]
    when:
    - key: request.headers[user-agent]
      values: ["curl/*"]
  
  # 允许规则
  - from:
    - source:
        namespaces: ["trusted-ns"]
    to:
    - operation:
        methods: ["GET", "POST"]

指标类型： ​

yaml
# 标准指标（自动收集）：
1. 请求计数 (istio_requests_total)
2. 请求持续时间 (istio_request_duration_milliseconds)
3. 请求大小 (istio_request_bytes)
4. 响应大小 (istio_response_bytes)
5. TCP 指标 (istio_tcp_sent_bytes_total等)

# 自定义指标：

  name: custom-metrics
spec:
  metrics:
  - providers:
    - name: prometheus
    overrides:
    - match:
        metric: ALL_METRICS
      tagOverrides:
        custom_tag:
          value: "source.workload.name"

总结表：Istio核心概念速查 ​

概念作用关键配置
VirtualService流量路由hosts, http.match, route
DestinationRule服务子集和策略subsets, trafficPolicy
Gateway入口网关selector, servers, port
ServiceEntry外部服务注册hosts, ports, location
SidecarSidecar配置范围egress.hosts, ingress
PeerAuthentication服务间认证mtls.mode
RequestAuthentication终端用户认证jwtRules
AuthorizationPolicy访问控制action, rules
Telemetry遥测配置metrics, tracing, accessLogging
