GitLab CI/CD 多阶段流水线深度指南 ​

一、多阶段流水线基础架构 ​

1.1 流水线阶段概念 ​

阶段分类 ​

yaml
# 完整的阶段生命周期
stages:
  - .pre                    # 前置阶段：环境检查、权限验证
  - validate               # 验证阶段：代码质量、配置检查
  - build                  # 构建阶段：编译、打包
  - quality                # 质量检查：安全扫描、依赖检查
  - test                   # 测试阶段：单元测试、集成测试
  - security               # 安全阶段：安全测试、漏洞扫描
  - performance            # 性能阶段：性能测试、负载测试
  - staging                # 预发布阶段：部署到预发布环境
  - production             # 生产发布阶段
  - rollback               # 回滚阶段（可选）
  - cleanup                # 清理阶段：资源回收
  - .post                  # 后置阶段：通知、报告生成

流水线可视化架构 ​

二、阶段配置详解 ​

2.1 预定义阶段 ​

.pre 阶段（强制验证） ​

yaml
.pre_template:
  stage: .pre
  when: always  # 始终执行，不受失败影响

pre_env_check:
  extends: .pre_template
  script:
    - |
      # 检查必需的环境变量
      required_vars="CI_PROJECT_ID CI_COMMIT_SHA CI_REGISTRY"
      for var in $required_vars; do
        if [ -z "${!var}" ]; then
          echo "❌ 缺少必需的环境变量: $var"
          exit 1
        fi
      done
    - echo "✅ 环境检查通过"
  artifacts:
    reports:
      dotenv: pre-check.env

pre_permission_check:
  extends: .pre_template
  script:
    - |
      # 检查执行权限
      if [ "$CI_COMMIT_BRANCH" == "main" ] && [ "$CI_COMMIT_REF_PROTECTED" != "true" ]; then
        echo "❌ 对受保护分支的提交需要保护分支权限"
        exit 1
      fi
    - echo "✅ 权限检查通过"
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'

pre_resource_check:
  extends: .pre_template
  script:
    - |
      # 检查系统资源
      if [ $(df --output=pcent / | tail -1 | tr -d '% ') -gt 90 ]; then
        echo "⚠️ 磁盘空间不足"
        exit 1
      fi
      if [ $(free -m | awk '/^Mem:/{print int($3/$2*100)}') -gt 85 ]; then
        echo "⚠️ 内存使用率过高"
        exit 1
      fi
    - echo "✅ 资源检查通过"

.post 阶段（清理和通知） ​

yaml
.post_template:
  stage: .post
  when: always
  allow_failure: true

post_cleanup:
  extends: .post_template
  needs: []  # 不依赖任何作业，始终执行
  script:
    - |
      # 清理临时文件
      find . -name "*.tmp" -type f -delete
      find . -name "__pycache__" -type d -exec rm -rf {} + 2>/dev/null || true
      docker system prune -f 2>/dev/null || true
    - echo "✅ 清理完成"

post_notification:
  extends: .post_template
  script:
    - |
      # 根据流水线状态发送通知
      if [ "$CI_PIPELINE_SOURCE" == "merge_request_event" ]; then
        MR_URL="${CI_PROJECT_URL}/-/merge_requests/${CI_MERGE_REQUEST_IID}"
        STATUS=$(curl -s --header "PRIVATE-TOKEN: $GITLAB_TOKEN" \
          "${CI_API_V4_URL}/projects/${CI_PROJECT_ID}/merge_requests/${CI_MERGE_REQUEST_IID}" \
          | jq -r '.merge_status')
        
        if [ "$CI_PIPELINE_STATUS" == "success" ]; then
          curl -X POST -H "Content-Type: application/json" \
            -d "{\"text\":\"✅ MR #${CI_MERGE_REQUEST_IID} 流水线通过: ${MR_URL}\"}" \
            $SLACK_WEBHOOK_URL
        else
          curl -X POST -H "Content-Type: application/json" \
            -d "{\"text\":\"❌ MR #${CI_MERGE_REQUEST_IID} 流水线失败: ${MR_URL}\"}" \
            $SLACK_WEBHOOK_URL
        fi
      fi

post_metrics:
  extends: .post_template
  script:
    - |
      # 收集流水线指标
      DURATION=$(( $(date +%s) - $(date -d "$CI_PIPELINE_CREATED_AT" +%s) ))
      echo "pipeline_duration_seconds $DURATION" >> metrics.txt
      echo "pipeline_jobs_total $(curl -s --header "PRIVATE-TOKEN: $GITLAB_TOKEN" \
        "${CI_API_V4_URL}/projects/${CI_PROJECT_ID}/pipelines/${CI_PIPELINE_ID}/jobs" \
        | jq '. | length')" >> metrics.txt
      
      # 推送到Prometheus Pushgateway
      cat metrics.txt | curl -X POST --data-binary @- \
        http://prometheus-pushgateway:9091/metrics/job/gitlab_ci/instance/$CI_PROJECT_NAME

复杂的阶段依赖关系 ​

yaml
stages:
  - init
  - prepare
  - build
  - analyze
  - test
  - package
  - deploy
  - verify
  - teardown

# 初始化阶段
init_env:
  stage: init
  script:
    - echo "初始化构建环境"
    - mkdir -p artifacts reports coverage
    - export BUILD_ID="${CI_PIPELINE_ID}-${CI_COMMIT_SHORT_SHA}"
  artifacts:
    paths:
      - artifacts/
      - reports/
    expire_in: 1 week

# 并行准备阶段
prepare_dependencies:
  stage: prepare
  script:
    - echo "安装依赖..."
    - npm ci --cache .npm --prefer-offline
  cache:
    key: ${CI_COMMIT_REF_SLUG}
    paths:
      - node_modules/
      - .npm/
    policy: pull-push
  artifacts:
    paths:
      - node_modules/

prepare_config:
  stage: prepare
  script:
    - echo "生成配置..."
    - cp config/$CI_ENVIRONMENT_NAME.env .env
    - ./scripts/generate-config.sh
  artifacts:
    paths:
      - .env
      - config/
    expire_in: 1 hour

# 构建矩阵
build_matrix:
  stage: build
  parallel:
    matrix:
      - PLATFORM: [linux, windows, macos]
        ARCH: [amd64, arm64]
  script:
    - echo "为 $PLATFORM/$ARCH 构建..."
    - GOOS=$PLATFORM GOARCH=$ARCH go build -o artifacts/app-$PLATFORM-$ARCH
  artifacts:
    paths:
      - artifacts/app-*
    expire_in: 1 week

# 分析阶段（并行执行）
analyze_static:
  stage: analyze
  script:
    - echo "静态代码分析..."
    - sonar-scanner -Dsonar.projectKey=$CI_PROJECT_NAME
  artifacts:
    reports:
      codequality: gl-code-quality-report.json

analyze_dependencies:
  stage: analyze
  script:
    - echo "依赖安全检查..."
    - npm audit --audit-level=high
    - trivy fs --severity HIGH,CRITICAL .
  artifacts:
    reports:
      dependency_scanning: gl-dependency-scanning-report.json

analyze_security:
  stage: analyze
  script:
    - echo "安全扫描..."
    - gosec ./...
    - bandit -r .
  artifacts:
    reports:
      sast: gl-sast-report.json

三、高级流水线模式 ​

3.1 条件阶段执行 ​

基于规则的阶段控制 ​

yaml
# 条件阶段配置模板
.conditional_stage:
  rules:
    # 规则1：合并请求到特定分支
    - if: '$CI_PIPELINE_SOURCE == "merge_request_event"'
      exists:
        - src/**/*.js
      changes:
        - package.json
        - webpack.config.js
      when: always
    
    # 规则2：主分支提交
    - if: '$CI_COMMIT_BRANCH == "main" && $CI_COMMIT_TAG == null'
      when: on_success
      variables:
        DEPLOY_ENV: "production"
    
    # 规则3：标签发布
    - if: '$CI_COMMIT_TAG =~ /^v\d+\.\d+\.\d+$/'
      when: manual
      variables:
        RELEASE: "true"
    
    # 规则4：计划任务
    - if: '$CI_PIPELINE_SOURCE == "schedule"'
      when: always
      variables:
        SCHEDULED: "true"
    
    # 默认规则：不执行
    - when: never

# 应用条件阶段
security_scan:
  extends: .conditional_stage
  stage: security
  script:
    - |
      if [ -n "$RELEASE" ]; then
        echo "执行发布版本的安全扫描..."
        ./security-scan.sh --release
      else
        echo "执行常规安全扫描..."
        ./security-scan.sh
      fi

动态阶段生成 ​

yaml
# 生成动态测试阶段
generate_test_matrix:
  stage: prepare
  script:
    - |
      # 根据代码变化生成测试矩阵
      CHANGED_FILES=$(git diff --name-only $CI_MERGE_REQUEST_TARGET_BRANCH_SHA...$CI_COMMIT_SHA)
      
      # 生成测试配置
      cat > test-matrix.json << EOF
      {
        "include": [
          $(if echo "$CHANGED_FILES" | grep -q ".*\.py$"; then
            echo '{"type": "python", "command": "pytest tests/python"}',
          fi)
          $(if echo "$CHANGED_FILES" | grep -q ".*\.js$"; then
            echo '{"type": "javascript", "command": "npm test"}',
          fi)
          $(if echo "$CHANGED_FILES" | grep -q ".*\.go$"; then
            echo '{"type": "golang", "command": "go test ./..."}',
          fi)
          {"type": "integration", "command": "./integration-test.sh"}
        ]
      }
      EOF
      
      # 生成子流水线配置
      cat > .dynamic-tests.yml << EOF
      stages:
        - dynamic_test
      
      include:
        - local: /templates/test-job.yml
      
      variables:
        DYNAMIC_TESTS: "true"
      
      $(jq -r '.include[] | 
        "test_\(.type):\n  extends: .test_template\n  variables:\n    TEST_TYPE: \"\(.type)\"\n    TEST_COMMAND: \"\(.command)\"\n"' test-matrix.json)
      EOF
  artifacts:
    paths:
      - .dynamic-tests.yml
    expire_in: 1 hour

# 触发动态测试流水线
trigger_dynamic_tests:
  stage: test
  trigger:
    include:
      - artifact: .dynamic-tests.yml
        job: generate_test_matrix
    strategy: depend

3.2 手动审批阶段 ​

多级审批流程 ​

yaml
stages:
  - build
  - test
  - approval_stage_1
  - approval_stage_2
  - deploy_staging
  - approval_stage_3
  - deploy_production

# 第一阶段审批（技术负责人）
approval_tech_lead:
  stage: approval_stage_1
  script:
    - echo "等待技术负责人审批..."
    - sleep 1  # 防止作业立即完成
  when: manual
  allow_failure: false
  needs: ["test_unit", "test_integration"]
  
  # 审批表单
  environment:
    name: approval/tech
    action: prepare
  
  # 审批超时
  interruptible: true
  timeout: 2 hours

# 第二阶段审批（产品经理）
approval_product_owner:
  stage: approval_stage_2
  script:
    - echo "等待产品经理审批..."
    - sleep 1
  when: manual
  allow_failure: false
  needs: ["approval_tech_lead"]
  environment:
    name: approval/product
    action: prepare

# 部署到预发布环境
deploy_staging:
  stage: deploy_staging
  script:
    - echo "部署到预发布环境..."
    - ./deploy.sh staging
  environment:
    name: staging
    url: https://staging.example.com
  needs: ["approval_product_owner"]

# 第三阶段审批（业务验收）
approval_business:
  stage: approval_stage_3
  script:
    - echo "等待业务验收..."
    - sleep 1
  when: manual
  allow_failure: false
  needs: ["deploy_staging"]
  environment:
    name: approval/business
    action: prepare

# 生产部署
deploy_production:
  stage: deploy_production
  script:
    - echo "部署到生产环境..."
    - ./deploy.sh production
  environment:
    name: production
    url: https://example.com
  when: manual
  needs: ["approval_business"]
  
  # 部署策略配置
  rules:
    - if: '$CI_COMMIT_BRANCH == "main"'
      when: manual
      allow_failure: false
    - when: never

智能并行执行 ​

yaml
stages:
  - analyze
  - build
  - test
  - deploy

# 分析阶段 - 完全并行
analyze:
  stage: analyze
  parallel: 4
  script:
    - |
      # 根据作业索引分配任务
      case $CI_NODE_INDEX in
        0) ./analyze-sonarqube.sh ;;
        1) ./analyze-dependencies.sh ;;
        2) ./analyze-security.sh ;;
        3) ./analyze-performance.sh ;;
      esac
  artifacts:
    reports:
      codequality: reports/code-quality-$CI_NODE_INDEX.json
  cache:
    key: analysis-cache-$CI_NODE_INDEX
    paths:
      - reports/

# 构建阶段 - 矩阵并行
build_matrix:
  stage: build
  parallel:
    matrix:
      - BUILD_TYPE: [debug, release]
        PLATFORM: [linux, windows]
  script:
    - echo "构建 $BUILD_TYPE 版本，平台: $PLATFORM"
    - ./build.sh --type=$BUILD_TYPE --platform=$PLATFORM
  artifacts:
    paths:
      - artifacts/$PLATFORM-$BUILD_TYPE/

# 测试阶段 - 动态并行
run_tests:
  stage: test
  parallel:
    matrix:
      # 从文件读取测试套件
      - TEST_SUITE: 
          - unit
          - integration
          - e2e
          - performance
      - BROWSER: [chrome, firefox, safari]
  script:
    - echo "运行 $TEST_SUITE 测试，浏览器: $BROWSER"
    - npm run test:$TEST_SUITE --browser=$BROWSER
  artifacts:
    paths:
      - test-results/$TEST_SUITE-$BROWSER/
    reports:
      junit: test-results/$TEST_SUITE-$BROWSER/junit.xml

analyze_changes:
  stage: analyze
  script:
    - |
      # 分析代码变化
      git fetch origin $CI_MERGE_REQUEST_TARGET_BRANCH_NAME
      CHANGED_FILES=$(git diff --name-only origin/$CI_MERGE_REQUEST_TARGET_BRANCH_NAME...HEAD)
      
      # 分类变化类型
      echo "CHANGED_PYTHON=$(echo "$CHANGED_FILES" | grep -c '\.py$')" >> changed.env
      echo "CHANGED_JS=$(echo "$CHANGED_FILES" | grep -c '\.js$\|\.ts$\|\.jsx$\|\.tsx$')" >> changed.env
      echo "CHANGED_DOCKER=$(echo "$CHANGED_FILES" | grep -c 'Dockerfile\|\.dockerfile')" >> changed.env
      echo "CHANGED_INFRA=$(echo "$CHANGED_FILES" | grep -c '\.tf$\|\.yml$\|\.yaml$')" >> changed.env
      
      # 检测破坏性变更
      if git diff --name-only origin/$CI_MERGE_REQUEST_TARGET_BRANCH_NAME...HEAD | \
         xargs -I {} git diff --no-color origin/$CI_MERGE_REQUEST_TARGET_BRANCH_NAME...HEAD -- {} | \
         grep -q "^--- a/.*\.py$"; then
        echo "BREAKING_CHANGES=true" >> changed.env
      fi
  artifacts:
    reports:
      dotenv: changed.env

  stage: generate
  script:
    - |
      # 读取分析结果
      source changed.env
      
      # 生成动态流水线配置
      cat > dynamic-pipeline.yml << 'EOF'
      stages:
        - security
        - test
        - build
        - deploy
      
      variables:
        GENERATED_PIPELINE: "true"
      
      # 安全扫描（始终执行）
      security_scan:
        stage: security
        script:
          - ./security-scan.sh
        artifacts:
          reports:
            sast: gl-sast-report.json
      
      EOF
      
      # 根据变化添加测试作业
      if [ "$CHANGED_PYTHON" -gt 0 ]; then
        cat >> dynamic-pipeline.yml << 'EOF'
      
      test_python:
        stage: test
        image: python:3.9
        script:
          - pip install -r requirements.txt
          - pytest tests/ --junitxml=test-results/pytest.xml
        artifacts:
          reports:
            junit: test-results/pytest.xml
      
        EOF
      fi
      
      if [ "$CHANGED_JS" -gt 0 ]; then
        cat >> dynamic-pipeline.yml << 'EOF'
      
      test_javascript:
        stage: test
        image: node:16
        script:
          - npm ci
          - npm test -- --coverage
        artifacts:

            junit: test-results/jest.xml
            coverage_report:
              coverage_format: cobertura
              path: coverage/cobertura-coverage.xml

      fi

      breaking_change_approval:

          - sleep 1
        when: manual
        allow_failure: false

      fi

        when: manual
        needs: ["build_application"]

      cat dynamic-pipeline.yml

optimize_parallelization:
  stage: .pre
  script:
    - |
      # 分析可并行化的作业
      TOTAL_JOBS=$(yq eval '. | length' .gitlab-ci.yml 2>/dev/null || echo "0")
      PARALLEL_JOBS=0
      
      # 识别独立作业
      for job in $(yq eval 'keys | .[]' .gitlab-ci.yml); do
        NEEDS=$(yq eval ".$job.needs | .[]" .gitlab-ci.yml 2>/dev/null || echo "")
        if [ -z "$NEEDS" ]; then
          PARALLEL_JOBS=$((PARALLEL_JOBS + 1))
          echo "$job 可以并行执行"
        fi
      done
      
      echo "PARALLEL_JOBS=$PARALLEL_JOBS" >> optimization.env
      echo "TOTAL_JOBS=$TOTAL_JOBS" >> optimization.env
      
      # 根据资源计算最优并行度
      CPU_CORES=$(nproc)
      OPTIMAL_PARALLELISM=$((CPU_CORES * 2))
      
      if [ $PARALLEL_JOBS -gt $OPTIMAL_PARALLELISM ]; then
        echo "建议分批执行，每批 $OPTIMAL_PARALLELISM 个作业"
      fi

  script:
    - |
      # 根据批次分配测试
      TOTAL_TESTS=$(find tests/ -name "*.spec.js" | wc -l)
      TESTS_PER_BATCH=$((TOTAL_TESTS / 4))
      START=$(( (BATCH - 1) * TESTS_PER_BATCH + 1 ))
      END=$(( BATCH * TESTS_PER_BATCH ))
      
      # 执行分配的测试
      TEST_FILES=$(find tests/ -name "*.spec.js" | sed -n "${START},${END}p")
      npm test -- $TEST_FILES
  artifacts:
    paths:
      - test-results/batch-$BATCH/

      - .cache/

# 错误处理模板
.error_handling_template:
  retry:
    max: 3
    when:
      - runner_system_failure
      - stuck_or_timeout_failure
      - api_failure
      - runner_unavailable
    exit_codes:
      - 137  # OOM
      - 143  # SIGTERM
  timeout: 30 minutes
  interruptible: true
  allow_failure: ${ALLOW_FAILURE}
  
  # 重试策略
  retry_config:
    exponential_backoff: true
    max_interval: 600  # 10分钟
    base_interval: 30  # 30秒

# 优雅降级
deploy_with_fallback:
  stage: deploy
  extends: .error_handling_template
  script:
    - |
      # 主部署策略
      if ./deploy-primary.sh; then
        echo "主部署成功"
        exit 0
      fi
      
      # 主部署失败，尝试备选方案
      echo "主部署失败，尝试备选方案..."
      
      if ./deploy-fallback.sh; then
        echo "备选部署成功"
        exit 0
      fi
      
      # 最终回退
      echo "所有部署策略失败，回滚到上一个版本"
      ./rollback-to-stable.sh
      exit 1
  variables:
    ALLOW_FAILURE: false

# 断路器模式
circuit_breaker:
  stage: deploy
  script:
    - |
      # 检查断路器状态
      if [ -f "/tmp/circuit-open" ]; then
        echo "断路器已打开，跳过部署"
        exit 0
      fi
      
      # 尝试部署
      if ./deploy.sh; then
        echo "部署成功，重置失败计数"
        rm -f /tmp/failure-count
      else
        # 记录失败
        FAILURE_COUNT=$(( $(cat /tmp/failure-count 2>/dev/null || echo "0") + 1 ))
        echo $FAILURE_COUNT > /tmp/failure-count
        
        if [ $FAILURE_COUNT -ge 3 ]; then
          echo "连续失败3次，打开断路器"
          touch /tmp/circuit-open
          
          # 30分钟后自动恢复
          (
            sleep 1800
            rm -f /tmp/circuit-open /tmp/failure-count
          ) &
        fi
        exit 1
      fi

# 指标收集阶段
collect_metrics:
  stage: .post
  when: always
  script:
    - |
      # 收集流水线执行时间
      PIPELINE_START=$(date -d "$CI_PIPELINE_CREATED_AT" +%s)
      PIPELINE_END=$(date +%s)
      DURATION=$((PIPELINE_END - PIPELINE_START))
      
      # 收集作业统计
      JOBS_TOTAL=0
      JOBS_SUCCESS=0
      JOBS_FAILED=0
      
      for status in created waiting_for_resource preparing pending running success failed canceled skipped manual; do
        COUNT=$(curl -s --header "PRIVATE-TOKEN: $GITLAB_TOKEN" \
          "$CI_API_V4_URL/projects/$CI_PROJECT_ID/pipelines/$CI_PIPELINE_ID/jobs?scope[]=$status" \
          | jq '. | length')
        
        case $status in
          success) JOBS_SUCCESS=$COUNT ;;
          failed) JOBS_FAILED=$COUNT ;;
        esac
        JOBS_TOTAL=$((JOBS_TOTAL + COUNT))
      done
      
      # 生成指标
      cat > pipeline-metrics.prom << EOF
      # HELP gitlab_pipeline_duration_seconds Pipeline execution duration
      # TYPE gitlab_pipeline_duration_seconds gauge
      gitlab_pipeline_duration_seconds{project="$CI_PROJECT_NAME", ref="$CI_COMMIT_REF_NAME"} $DURATION
      
      # HELP gitlab_pipeline_jobs_total Total jobs in pipeline
      # TYPE gitlab_pipeline_jobs_total gauge
      gitlab_pipeline_jobs_total{project="$CI_PROJECT_NAME", ref="$CI_COMMIT_REF_NAME"} $JOBS_TOTAL
      
      # HELP gitlab_pipeline_jobs_success Successful jobs count
      # TYPE gitlab_pipeline_jobs_success gauge
      gitlab_pipeline_jobs_success{project="$CI_PROJECT_NAME", ref="$CI_COMMIT_REF_NAME"} $JOBS_SUCCESS
      
      # HELP gitlab_pipeline_jobs_failed Failed jobs count
      # TYPE gitlab_pipeline_jobs_failed gauge

      # HELP gitlab_pipeline_success Whether pipeline succeeded
      # TYPE gitlab_pipeline_success gauge
      gitlab_pipeline_success{project="$CI_PROJECT_NAME", ref="$CI_COMMIT_REF_NAME"} $([ "$CI_PIPELINE_STATUS" = "success" ] && echo 1 || echo 0)
      EOF
      
      # 推送到监控系统
      curl -X POST --data-binary @pipeline-metrics.prom \
        http://prometheus-pushgateway:9091/metrics/job/gitlab_pipeline/instance/$CI_PROJECT_NAME
  artifacts:

# 质量门禁检查
quality_gates:
  stage: quality
  script:
    - |
      # 收集质量指标
      QUALITY_PASSED=true
      QUALITY_REPORT="## 质量门禁报告\n\n"
      
      # 1. 测试覆盖率检查
      COVERAGE=$(cat coverage/coverage-summary.json | jq '.total.lines.pct')
      if [ $(echo "$COVERAGE < 80" | bc) -eq 1 ]; then
        QUALITY_PASSED=false
        QUALITY_REPORT+="❌ **测试覆盖率不足**: $COVERAGE% (要求: ≥80%)\n"
      else
        QUALITY_REPORT+="✅ **测试覆盖率**: $COVERAGE%\n"
      fi
      
      # 2. 代码质量检查
      BUGS=$(cat sonar-report.json | jq '.bugs')
      VULNERABILITIES=$(cat sonar-report.json | jq '.vulnerabilities')
      CODE_SMELLS=$(cat sonar-report.json | jq '.code_smells')
      
      if [ $BUGS -gt 0 ]; then
        QUALITY_REPORT+="⚠️ **Bugs**: $BUGS\n"
      fi
      if [ $VULNERABILITIES -gt 0 ]; then
        QUALITY_PASSED=false
        QUALITY_REPORT+="❌ **安全漏洞**: $VULNERABILITIES\n"
      fi
      if [ $CODE_SMELLS -gt 50 ]; then
        QUALITY_REPORT+="⚠️ **代码异味过多**: $CODE_SMELLS\n"
      fi
      
      # 3. 性能指标
      PERFORMANCE_SCORE=$(cat lighthouse-report.json | jq '.categories.performance.score * 100')
      if [ $(echo "$PERFORMANCE_SCORE < 90" | bc) -eq 1 ]; then
        QUALITY_REPORT+="⚠️ **性能评分低**: $PERFORMANCE_SCORE\n"
      fi
      
      # 4. 依赖安全
      if grep -q "HIGH\|CRITICAL" trivy-report.json; then
        QUALITY_PASSED=false
        QUALITY_REPORT+="❌ **发现高危依赖漏洞**\n"
      fi
      
      # 生成报告
      echo "$QUALITY_REPORT" > quality-report.md
      echo "QUALITY_PASSED=$QUALITY_PASSED" >> quality.env
      
      if [ "$QUALITY_PASSED" = "false" ]; then
        echo "质量门禁未通过"
        exit 1
      fi
  artifacts:
    paths:
      - quality-report.md
    reports:
      dotenv: quality.env

8.1 阶段设计原则 ​

  1. 单一职责原则：每个阶段专注于一个特定目标
  2. 最小依赖原则：尽量减少阶段间的依赖关系
  3. 失败快速原则：将关键检查放在流水线前端
  4. 资源优化原则：合理使用并行和缓存
  5. 可观测性原则：每个阶段都应有明确的输出和指标
