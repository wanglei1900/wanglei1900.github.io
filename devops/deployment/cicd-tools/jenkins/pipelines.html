Jenkins流水线设计：完整学习笔记 ​

1. Jenkins流水线概述 ​

1.1 CI/CD与流水线的意义 ​

持续集成（CI）：开发人员频繁地将代码集成到共享仓库，每次集成都通过自动化构建和测试验证。

持续交付/部署（CD）：确保代码变更可以安全、快速地部署到生产环境。

流水线（Pipeline）：将软件交付过程建模为一系列阶段的可自动化流程，包括构建、测试、部署等步骤。

1.2 Jenkins流水线的优势 ​

  • 代码化配置：流水线作为代码存储在版本控制中
  • 可视化：Blue Ocean界面提供清晰的阶段视图
  • 可恢复性：可以从失败点继续执行
  • 并行执行：支持并行阶段提高效率
  • 可扩展性：丰富的插件生态系统

2. Jenkins流水线类型 ​

2.1 声明式流水线（Declarative Pipeline） ​

groovy
pipeline {
    agent any
    stages {
        stage('Build') {
            steps {
                echo 'Building...'
            }
        }
    }
}

2.2 脚本式流水线（Scripted Pipeline） ​

groovy
node {
    stage('Build') {
        echo 'Building...'
    }
}

3. 核心语法元素详解 ​

3.1 基本结构 ​

groovy
pipeline {
    // 1. 全局配置部分
    agent any
    options {
        timeout(time: 1, unit: 'HOURS')
    }
    triggers {
        cron('H */4 * * *')
    }
    parameters {
        string(name: 'VERSION', defaultValue: '1.0.0')
    }
    environment {
        NODE_VERSION = '16.14.0'
    }
    tools {
        maven 'Maven-3.8.6'
    }
    
    // 2. 阶段定义
    stages {
        stage('代码检出') {
            steps {
                git branch: 'main', 
                    url: 'https://github.com/example/repo.git'
            }
        }
        
        stage('构建') {
            steps {
                sh 'mvn clean compile'
            }
            post {
                success {
                    echo '构建成功!'
                }
                failure {
                    echo '构建失败!'
                }
            }
        }
    }
    
    // 3. 后置动作
    post {
        always {
            junit '**/target/surefire-reports/*.xml'
            archiveArtifacts artifacts: 'target/*.jar'
        }
        success {
            emailext subject: '构建成功',
                      body: '${env.JOB_NAME}构建成功',
                      to: 'team@example.com'
        }
    }
}

4. 流水线阶段设计 ​

4.1 典型阶段划分 ​

groovy
stages {
    // 阶段1：准备
    stage('初始化') {
        steps {
            script {
                currentBuild.displayName = "#${BUILD_NUMBER}-${params.BRANCH_NAME}"
                currentBuild.description = "构建分支: ${params.BRANCH_NAME}"
            }
        }
    }
    
    // 阶段2：代码质量检查
    stage('代码检查') {
        parallel {
            stage('SonarQube分析') {
                steps {
                    withSonarQubeEnv('sonar-server') {
                        sh 'mvn sonar:sonar'
                    }
                }
            }
            stage('安全检查') {
                steps {
                    dependencyCheck additionalArguments: '--scan ./', 
                                   odcInstallation: 'OWASP-DC'
                    dependencyCheckPublisher pattern: '**/dependency-check-report.xml'
                }
            }
        }
    }
    
    // 阶段3：构建
    stage('编译构建') {
        steps {
            dir('backend') {
                sh 'mvn clean package -DskipTests'
            }
            dir('frontend') {
                sh 'npm ci'
                sh 'npm run build'
            }
        }
    }
    
    // 阶段4：测试
    stage('自动化测试') {
        parallel {
            stage('单元测试') {
                steps {
                    sh 'mvn test'
                    junit '**/target/surefire-reports/*.xml'
                }
            }
            stage('集成测试') {
                steps {
                    sh 'mvn verify -Pintegration-tests'
                    junit '**/target/failsafe-reports/*.xml'
                }
            }
            stage('前端测试') {
                steps {
                    sh 'npm run test:ci'
                    junit '**/test-results/**/*.xml'
                }
            }
        }
    }
    
    // 阶段5：制品管理
    stage('制品打包') {
        steps {
            // Docker镜像构建
            script {
                dockerImage = docker.build("${APP_NAME}:${BUILD_ID}")
            }
            
            // 版本化制品
            sh """
                echo "${BUILD_ID}" > version.txt
                tar -czf ${APP_NAME}-${BUILD_ID}.tar.gz target/*.jar version.txt
            """
            
            archiveArtifacts artifacts: "**/*.tar.gz, **/*.jar"
        }
    }
    
    // 阶段6：部署
    stage('部署') {
        when {
            expression { 
                params.DEPLOY_ENV != 'none' && 
                currentBuild.resultIsBetterOrEqualTo('SUCCESS')
            }
        }
        steps {
            script {
                switch(params.DEPLOY_ENV) {
                    case 'dev':
                        sh "kubectl apply -f k8s/dev-deployment.yaml"
                        break
                    case 'staging':
                        sh "ansible-playbook deploy-staging.yml"
                        break
                    case 'prod':
                        input message: '确认部署到生产环境?', 
                              ok: '确认部署'
                        sh "./deploy-production.sh"
                        break
                }
            }
        }
    }
    
    // 阶段7：验证
    stage('健康检查') {
        steps {
            script {
                timeout(time: 5, unit: 'MINUTES') {
                    waitUntil {
                        def response = sh(
                            script: "curl -s -o /dev/null -w '%{http_code}' ${APP_URL}/health",
                            returnStdout: true
                        ).trim()
                        return response == '200'
                    }
                }
                echo '应用健康检查通过'
            }
        }
    }
}

5.4 错误处理和通知 ​

groovy
post {
    // 根据状态执行不同操作
    always {
        script {
            // 清理工作空间
            cleanWs()
            
            // 记录构建指标
            recordIssues(
                tools: [checkStyle(), pmdParser()],
                filters: [excludeFile('.*Test\\.java')]
            )
        }
    }
    
    success {
        script {
            // 成功通知
            slackSend(
                color: 'good',
                message: "构建成功: ${env.JOB_NAME} #${env.BUILD_NUMBER}"
            )
            
            // 更新Dashboard
            updateGitHubCommitStatus(
                state: 'SUCCESS',
                context: 'jenkins/ci'
            )
        }
    }
    
    failure {
        script {
            // 失败通知
            emailext(
                subject: "构建失败: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                body: "请检查构建日志: ${env.BUILD_URL}",
                to: 'dev-team@example.com',
                attachLog: true
            )
            
            // 自动创建Issue
            withCredentials([string(credentialsId: 'github-token', 
                                  variable: 'GITHUB_TOKEN')]) {
                sh """
                    curl -X POST \
                    -H "Authorization: token \$GITHUB_TOKEN" \
                    -d '{"title":"构建失败 #${BUILD_NUMBER}", 
                         "body":"自动生成的Issue"}' \
                    https://api.github.com/repos/owner/repo/issues
                """
            }
        }
    }
    
    unstable {
        // 不稳定状态处理
        echo '构建结果不稳定'
    }
    
    cleanup {
        // 无论成功失败都执行
        echo '执行清理操作...'
    }
}

6.1 完整的Java微服务流水线 ​

groovy
pipeline {
    agent {
        kubernetes {
            label 'jenkins-agent-java'
            yaml '''
apiVersion: v1
kind: Pod
spec:
  containers:
  - name: maven
    image: maven:3.8.6-jdk-11
    command: ['cat']
    tty: true
    volumeMounts:
    - name: maven-cache
      mountPath: /root/.m2
  volumes:
  - name: maven-cache
    persistentVolumeClaim:
      claimName: maven-cache-pvc
'''
        }
    }
    
    options {
        buildDiscarder(logRotator(numToKeepStr: '10'))
        disableConcurrentBuilds()
        timeout(time: 2, unit: 'HOURS')
        timestamps()
    }
    
    parameters {
        choice(
            name: 'DEPLOY_TO',
            choices: ['none', 'dev', 'staging', 'prod'],
            description: '选择部署环境'
        )
        booleanParam(
            name: 'SKIP_TESTS',
            defaultValue: false,
            description: '跳过测试阶段'
        )
    }
    
    environment {
        REGISTRY = 'registry.example.com'
        PROJECT = 'myproject'
        SERVICE = 'user-service'
        DOCKER_IMAGE = "${REGISTRY}/${PROJECT}/${SERVICE}:${BUILD_ID}"
        KUBE_CONFIG = credentials('k8s-cluster-config')
        SONAR_TOKEN = credentials('sonar-token')
    }
    
    stages {
        stage('代码质量门控') {
            steps {
                checkout scm
                
                script {
                    // 检查代码规范
                    sh 'mvn checkstyle:check'
                    
                    // 运行Sonar分析
                    withSonarQubeEnv('sonarqube') {
                        sh "mvn sonar:sonar -Dsonar.projectKey=${SERVICE}"
                    }
                    
                    // 质量门控检查
                    timeout(time: 1, unit: 'MINUTES') {
                        waitForQualityGate abortPipeline: true
                    }
                }
            }
        }
        
        stage('构建和测试') {
            when {
                expression { !params.SKIP_TESTS }
            }
            stages {
                stage('单元测试') {
                    steps {
                        sh 'mvn test -DskipITs'
                    }
                    post {
                        always {
                            junit '**/target/surefire-reports/*.xml'
                        }
                    }
                }
                
                stage('集成测试') {
                    steps {
                        sh 'mvn verify -Dit.test=*IT'
                    }
                    post {
                        always {
                            junit '**/target/failsafe-reports/*.xml'
                        }
                    }
                }
                
                stage('性能测试') {
                    steps {
                        sh 'mvn gatling:test'
                    }
                    post {
                        always {
                            gatlingArchive()
                        }
                    }
                }
            }
        }
        
        stage('构建Docker镜像') {
            steps {
                script {
                    // 构建应用
                    sh 'mvn clean package -DskipTests'
                    
                    // 构建并推送Docker镜像
                    docker.withRegistry("https://${REGISTRY}", 'docker-registry-creds') {
                        dockerImage = docker.build(DOCKER_IMAGE)
                        dockerImage.push()
                        dockerImage.push('latest')
                    }
                }
            }
        }
        
        stage('安全扫描') {
            steps {
                script {
                    // 镜像漏洞扫描
                    sh """
                        trivy image --exit-code 1 \
                        --severity HIGH,CRITICAL \
                        ${DOCKER_IMAGE}
                    """
                    
                    // 依赖漏洞检查
                    dependencyCheck additionalArguments: '--scan . --format ALL'
                    dependencyCheckPublisher(
                        pattern: '**/dependency-check-report.xml',
                        unstableTotalHigh: 0,
                        unstableTotalCritical: 0
                    )
                }
            }
        }
        
        stage('部署到环境') {
            when {
                expression { params.DEPLOY_TO != 'none' }
            }
            steps {
                script {
                    // 准备Kubernetes清单文件
                    sh """
                        sed -i 's|__IMAGE_TAG__|${DOCKER_IMAGE}|g' k8s/deployment.yaml
                        sed -i 's|__ENV__|${params.DEPLOY_TO}|g' k8s/configmap.yaml
                    """
                    
                    // 使用kubectl部署
                    withKubeConfig([credentialsId: 'k8s-cluster', 
                                  serverUrl: 'https://k8s-cluster.example.com']) {
                        sh 'kubectl apply -f k8s/'
                        
                        // 等待部署完成
                        sh """
                            kubectl rollout status deployment/${SERVICE} \
                            -n ${params.DEPLOY_TO} \
                            --timeout=300s
                        """
                    }
                }
            }
        }
        
        stage('自动化验收测试') {
            when {
                expression { params.DEPLOY_TO in ['staging', 'prod'] }
            }
            steps {
                script {
                    // 运行API测试
                    sh 'newman run tests/api-collection.json'
                    
                    // 运行UI测试
                    sh 'npm run e2e'
                }
            }
        }
    }
    
    post {
        always {
            // 生成测试报告
            allure([
                includeProperties: false,
                jdk: '',
                properties: [],
                reportBuildPolicy: 'ALWAYS',
                results: [[path: 'target/allure-results']]
            ])
            
            // 清理资源
            script {
                if (params.DEPLOY_TO == 'dev') {
                    sh 'kubectl delete -f k8s/ --ignore-not-found=true'
                }
            }
        }
        
        success {
            script {
                // 更新部署记录
                withCredentials([string(credentialsId: 'slack-token', 
                                      variable: 'SLACK_TOKEN')]) {
                    sh """
                        curl -X POST \
                        -H 'Authorization: Bearer \$SLACK_TOKEN' \
                        -H 'Content-type: application/json' \
                        --data '{
                            "channel": "#deployments",
                            "text": "${SERVICE} v${BUILD_ID} 已部署到 ${params.DEPLOY_TO}"
                        }' \
                        https://slack.com/api/chat.postMessage
                    """
                }

// Jenkinsfile (在代码仓库根目录)
pipeline {
    agent any
    
    triggers {
        // GitHub Webhook触发
        githubPush()
        
        // 定期构建
        pollSCM('H/15 * * * *')
    }
    
    stages {
        stage('检查PR状态') {
            when {
                changeRequest()
            }
            steps {
                script {
                    // 检查PR是否可合并
                    def pr = githubPr.getProperty('pullRequest')
                    if (pr.mergeable) {
                        echo "PR #${pr.number} 可合并"
                    } else {
                        error "PR #${pr.number} 存在冲突"
                    }
                }
            }
        }
        
        stage('运行特定测试集') {
            when {
                branch 'release/*'
            }
            steps {
                // 发布分支运行完整测试
                sh 'mvn verify -Pfull-suite'
            }
        }
    }
}

8.1 常见问题解决 ​

groovy
// 1. 调试模式
pipeline {
    options {
        // 启用调试日志
        disableResume()
        // 打印步骤执行时间
        timestamps()
        // 保留失败的工作空间
        preserveStashes(buildCount: 5)
    }
    
    stages {
        stage('调试示例') {
            steps {
                script {
                    // 打印环境变量
                    sh 'env | sort'
                    
                    // 条件调试
                    if (env.DEBUG_MODE == 'true') {
                        sh 'set -x' // 启用bash调试
                    }
                    
                    // 使用try-catch处理异常
                    try {
                        sh '可能会失败的命令'
                    } catch (Exception e) {
                        echo "命令失败: ${e.getMessage()}"
                        // 记录到文件
                        writeFile file: 'error.log', text: e.toString()
                        // 继续执行
                        currentBuild.result = 'UNSTABLE'
                    }
                }
            }
        }
    }
}

// 2. 资源清理
post {
    always {
        script {
            // 清理Docker资源
            sh '''
                docker system prune -f || true
                docker volume prune -f || true
            '''
            
            // 清理临时文件

        }

10. 总结 ​

10.1 关键要点 ​

  1. Pipeline as Code：所有配置都应版本控制
  2. 模块化设计：使用共享库和函数
  3. 失败快速：尽早发现和报告问题
  4. 安全性：凭据管理和安全扫描
  5. 可观测性：监控和日志记录

10.2 持续改进 ​

  • 定期审查流水线性能
  • 收集团队反馈进行优化
  • 跟踪构建指标和趋势
  • 及时更新插件和工具链
