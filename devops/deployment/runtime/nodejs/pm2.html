📘 PM2 进程管理：Node.js 应用运行时部署（裸机/VM）完整指南 ​

PM2 是 Node.js 生态中最流行的进程管理器和守护进程工具。它能确保你的 Node.js、Python、Ruby 等应用在服务器（无论是物理裸机还是云虚拟机）上持久化运行，具备自动重启、负载均衡、日志管理等生产级特性，是保障服务稳定性的核心工具。

一、 核心价值：为什么生产环境需要 PM2？ ​

在裸机或虚拟机（VM）上直接运行 node app.js，进程会随着 SSH 会话结束而终止，且遇到错误会直接崩溃。PM2 解决了这些问题：

  • 进程守护与持久化：将应用转化为后台守护进程，异常退出时自动重启，服务器重启后也能自动恢复。
  • 集群模式与负载均衡：内置零配置负载均衡器，能一键启动多个应用实例（Cluster模式），充分利用多核CPU，提升并发能力和吞吐量。
  • 高效的运维管理：提供统一的命令行界面，用于启动、停止、重启、监控所有应用，极大简化运维。
  • 集中的日志管理：自动收集所有应用的标准输出和错误日志到文件，支持实时查看和历史回溯。

二、 环境准备与 PM2 安装 ​

1. 基础环境：Node.js ​

在部署PM2前，需确保服务器已安装Node.js。推荐使用 NVM 或 n 进行版本管理，避免系统全局安装的权限问题。

bash
# 使用NVM安装（示例）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.1/install.sh | bash
source ~/.bashrc
nvm install 18 # 安装LTS版本
nvm use 18

2. 安装 PM2 ​

通过 npm 全局安装 PM2。对于鲲鹏 ARM 架构等特定服务器，需确保Node.js二进制包匹配。

bash
npm install pm2@latest -g

安装后，创建软链接到 /usr/local/bin/ 以确保全局可用。

bash
ln -s /opt/node-v12.12.0-linux-arm64/bin/pm2 /usr/local/bin/pm2 # 根据实际路径调整
pm2 -v # 验证安装

三、 核心概念与快速上手 ​

1. 进程列表（Process List） ​

PM2 维护一个所有托管应用的列表，这是所有管理的核心。

bash
pm2 start app.js              # 启动应用并加入列表
pm2 ls                        # 查看列表状态（显示App名称、ID、状态、CPU/内存等）
pm2 stop app_name             # 停止应用（保持在该表中）
pm2 restart app_name          # 重启应用
pm2 delete app_name           # 从列表中删除应用
pm2 save                      # 将当前进程列表持久化到磁盘 (~/.pm2/dump.pm2)
pm2 resurrect                 # 恢复之前保存的列表

2. 启动脚本（Startup Script） ​

确保服务器重启后，PM2及其管理的应用能自动启动，这是生产环境必须的步骤。

bash
pm2 startup                   # 生成并配置适合当前系统的启动脚本（systemd/upstart等）
# 执行完上条命令后，会输出一行需要以root权限运行的命令，复制执行。
pm2 save                      # 保存当前进程列表，以便开机时恢复

3. 支持多语言应用 ​

PM2 不仅限于 Node.js，通过文件扩展名自动识别解释器。

bash
pm2 start api.py              # 启动Python应用
pm2 start bashscript.sh       # 启动Shell脚本

四、 核心配置：Ecosystem File（生态配置文件） ​

对于生产环境，使用配置文件（通常名为 ecosystem.config.js）是最佳实践。它提供了声明式的管理方式，可版本控制。

bash
pm2 ecosystem                 # 生成一个默认的配置文件模板

一个详细的生产环境配置示例如下（以 Node.js 应用为例）：

javascript
module.exports = {
  apps: [{
    // ===================== 基础标识配置 =====================
    name: 'MyAPI',                    // 应用唯一名称，用于命令操作
    script: './app.js',               // 应用入口脚本
    cwd: '/var/www/myapp',            // 应用运行目录（绝对路径更可靠）
    interpreter: 'node',              // 解释器，默认是node，可选其他如python

    // ===================== 进程模型与性能配置 =====================
    exec_mode: 'cluster',             // 模式：'cluster'（集群）或 'fork'（单进程）
    instances: 'max',                 // 实例数：'max'（按CPU核数）或具体数字（如2）
    max_memory_restart: '1G',         // 内存超过此阈值则自动重启，防止内存泄漏

    // ===================== 环境变量配置（关键） =====================
    env: {                            // 默认环境变量（开发环境）
      NODE_ENV: 'development',
      PORT: 3000,
    },
    env_production: {                 // 生产环境变量，通过 --env production 指定加载
      NODE_ENV: 'production',
      PORT: 8080,
      DATABASE_URL: 'prodmysql://...', // 生产数据库等敏感信息
    },

    // ===================== 日志管理配置 =====================
    log_date_format: 'YYYY-MM-DD HH:mm:ss',
    error_file: '/var/log/pm2/myapp-error.log',   // 错误日志路径
    out_file: '/var/log/pm2/myapp-out.log',       // 标准输出日志路径
    combine_logs: true,                            // 集群模式下合并日志
    log_rotate: {                                 // 日志轮转（PM2 v6+）
      size: '10M',                                 // 单个文件最大10M
      keep: 30,                                    // 保留最近30个日志文件
      compress: true,                              // 压缩历史日志
    },

    // ===================== 稳定性与监控配置 =====================
    autorestart: true,                // 应用崩溃后自动重启
    watch: false,                     // 生产环境关闭文件监听，避免误重启
    restart_delay: 5000,              // 异常重启前延迟毫秒数
    max_restarts: 10,                 // 最大连续异常重启次数
    min_uptime: '10s',                // 小于此运行时间的重启被视为异常

    // ===================== 高级功能配置 =====================
    listen_timeout: 3000,             // 应用启动后，等待此毫秒数确认为成功
    kill_timeout: 5000,               // 发送SIGKILL信号前等待优雅退出的时间
  }]
};

启动配置：

bash
pm2 start ecosystem.config.js --env production  # 使用生产环境变量启动

五、 集群模式（Cluster Mode）详解 ​

这是 PM2 最强大的特性之一。通过启动多个应用实例（工作进程），并让它们共享同一个端口，PM2 作为主进程在它们之间进行负载均衡。

  • 优势：零停机重载（pm2 reload），充分利用多核CPU，提升应用吞吐量和容错能力。
  • 配置：设置 exec_mode: 'cluster' 和 instances（如 2, 'max'）。
  • 操作：
    bash
    pm2 scale MyAPI +2        # 动态增加2个工作实例
pm2 scale MyAPI 4         # 将工作实例总数调整为4个
pm2 reload MyAPI          # 零停机、依次重启所有实例（用于更新代码）

六、 监控、日志与问题排查 ​

1. 实时监控 ​

  • 终端仪表板：pm2 monit 提供实时的 CPU、内存占用、环路延迟等监控。
  • 状态查看：pm2 status 或 pm2 ls 查看概要。
  • 进程详情：pm2 describe 0 （0为应用ID）查看详细元数据。

2. 日志管理 ​

  • 实时日志：pm2 logs MyAPI （--lines 200 查看历史）。
  • 日志文件：所有日志默认保存在 ~/.pm2/logs/ 下，可按配置轮转。

3. 集成高级监控（可选） ​

对于大规模部署，可集成 Prometheus + Grafana 或 APM工具（如 New Relic），获取代码级性能分析和更丰富的可视化图表。

七、 部署策略对比与最佳实践 ​

以下是裸机/VM、容器化等不同部署环境下使用PM2的策略对比：

特性/考量维度裸机物理服务器部署虚拟机（VM）部署容器化部署（Docker）
PM2角色核心进程管理器，负责守护、集群、自启。同裸机，是VM内部的进程管理器。通常每个容器运行单进程，PM2可用于开发或特定多进程场景（使用pm2-runtime）。
环境隔离依赖系统包和版本，隔离性差。操作系统级隔离，优于裸机。应用级别隔离，环境高度一致。
资源利用直接使用硬件，性能最好。有虚拟化开销，资源可超售。轻量，启动快，资源利用率高。
配置管理通过PM2生态文件管理，需关注系统启动脚本。同裸机，镜像可包含PM2配置。配置注入（环境变量、ConfigMap），与镜像解耦。
扩缩容垂直扩展（升级硬件）为主，水平扩展复杂。可克隆镜像快速水平扩展。天然适合水平扩展，K8s等编排工具自动化。
日志管理PM2管理应用日志，系统日志需额外配置。同裸机。容器日志驱动，集中收集（如EFK栈）。
典型场景对性能有极致要求、硬件绑定的传统应用。主流云服务器，业务隔离，灵活的资源规划。微服务架构，持续集成/持续部署，弹性云原生应用。

生产环境最佳实践总结： ​

  1. 始终使用配置文件：将应用配置（环境变量、实例数）代码化。
  2. 启用集群模式：除非应用有特殊状态（如WebSocket连接需特殊处理），生产环境应用使用Cluster模式。
  3. 妥善管理环境变量：敏感信息（密钥、数据库连接）绝不硬编码在配置文件中，应通过 env_production 或服务器环境变量传入。
  4. 配置日志轮转：防止日志占满磁盘。
  5. 设置内存重启阈值：利用 max_memory_restart 应对潜在的内存泄漏。
  6. 配置系统启动脚本：确保服务在意外重启后能自动恢复。
  7. 结合反向代理：使用 Nginx 或 HAProxy 在PM2集群前提供SSL终止、静态文件服务和负载均衡。

PM2 在裸机/VM部署场景下，以其简单、稳定、功能全面的特点，成为保障Node.js应用高可用的基石。掌握其核心配置与运维命令，是每一位Node.js后端开发者与运维人员的必备技能。
