1. 测试策略 ​

1.1 测试策略定义 ​

测试策略是描述测试活动的总体方法和目标的高级文档，定义了测试什么、如何测试、何时测试。

1.2 测试策略组成要素 ​

mermaid
graph TD
    A[测试策略] --> B[测试目标]
    A --> C[测试范围]
    A --> D[测试方法]
    A --> E[测试环境]
    A --> F[资源分配]
    A --> G[风险评估]
    A --> H[交付物]

1.2.1 测试目标 ​

  • 验证软件满足需求规格
  • 发现缺陷
  • 评估软件质量
  • 提供发布决策依据

1.2.2 测试范围 ​

  • 功能测试范围
  • 非功能测试范围（性能、安全、兼容性等）
  • 排除范围（明确不测试的内容）

1.2.3 测试级别 ​

mermaid
graph TD
    A[测试级别] --> B[单元测试]
    A --> C[集成测试]
    A --> D[系统测试]
    A --> E[验收测试]
    
    B --> B1[开发者执行]
    C --> C1[模块间接口]
    D --> D1[完整系统]
    E --> E1[用户验收]

1.3 测试策略类型 ​

策略类型适用场景特点
分析型策略需求明确的项目基于需求分析设计测试用例
模型型策略复杂系统使用模型指导测试
方法型策略标准化项目遵循预定义方法学
过程兼容策略敏捷项目与开发过程紧密结合
反应式策略需求频繁变更基于实际软件行为

2. 单元测试 ​

2.1 单元测试定义 ​

单元测试是针对软件最小可测试单元（通常是函数、方法）进行的测试。

2.2 单元测试特点 ​

  • 隔离性：每个测试独立运行
  • 快速性：执行速度快
  • 自动化：可自动执行和验证
  • 可重复：结果一致

2.3 单元测试框架示例 ​

2.3.1 JUnit (Java) ​

java
import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorTest {
    private Calculator calculator;
    
    @BeforeEach
    void setUp() {
        calculator = new Calculator();
    }
    
    @Test
    @DisplayName("加法测试")
    void testAddition() {
        assertEquals(5, calculator.add(2, 3));
        assertEquals(0, calculator.add(-2, 2));
    }
    
    @Test
    @DisplayName("除法测试 - 异常情况")
    void testDivisionByZero() {
        assertThrows(ArithmeticException.class, () -> {
            calculator.divide(10, 0);
        });
    }
    
    @Test
    @DisplayName("参数化测试")
    void testWithParameters() {
        assertAll("多个断言",
            () -> assertEquals(4, calculator.multiply(2, 2)),
            () -> assertEquals(0, calculator.multiply(0, 5))
        );
    }
}

2.3.2 pytest (Python) ​

python
import pytest

class TestCalculator:
    @pytest.fixture
    def calculator(self):
        return Calculator()
    
    def test_addition(self, calculator):
        assert calculator.add(2, 3) == 5
        assert calculator.add(-2, 2) == 0
    
    def test_division_by_zero(self, calculator):
        with pytest.raises(ZeroDivisionError):
            calculator.divide(10, 0)
    
    @pytest.mark.parametrize("a,b,expected", [
        (2, 2, 4), (0, 5, 0), (-3, 3, -9)
    ])
    def test_multiplication(self, calculator, a, b, expected):
        assert calculator.multiply(a, b) == expected

2.4 测试替身 (Test Doubles) ​

mermaid
graph LR
    A[测试替身] --> B[Mock对象]
    A --> C[Stub]
    A --> D[Fake]
    A --> E[Spy]
    A --> F[Dummy]

2.4.1 各种测试替身比较 ​

类型目的示例
Dummy填充参数，不被使用new Object()
Stub提供预设响应返回固定数据的对象
Spy记录调用信息记录方法调用次数的包装器
Mock验证交互行为验证特定方法是否被调用
Fake简化功能实现内存数据库替代真实数据库

2.4.2 Mockito示例 ​

java
import static org.mockito.Mockito.*;

public class UserServiceTest {
    @Test
    public void testUserRegistration() {
        // 创建mock对象
        UserRepository userRepository = mock(UserRepository.class);
        EmailService emailService = mock(EmailService.class);
        
        UserService userService = new UserService(userRepository, emailService);
        
        // 设置stub行为
        when(userRepository.save(any(User.class))).thenReturn(true);
        
        // 执行测试
        boolean result = userService.registerUser("test@example.com", "password");
        
        // 验证行为
        assertTrue(result);
        verify(userRepository).save(any(User.class));
        verify(emailService).sendWelcomeEmail(anyString());
    }
}

2.5 单元测试最佳实践 ​

2.5.1 FIRST原则 ​

  • Fast (快速)：测试应该快速执行
  • Independent (独立)：测试之间不依赖
  • Repeatable (可重复)：在任何环境结果一致
  • Self-validating (自验证)：自动判断通过/失败
  • Timely (及时)：在代码编写前或同时编写测试

2.5.2 测试命名规范 ​

java
// 方法1：Should_When_格式
@Test
void shouldReturnTrue_WhenUserIsAuthenticated()

// 方法2：Given_When_Then格式
@Test
void givenValidCredentials_whenAuthenticate_thenReturnTrue()

// 方法3：简单描述
@Test
void testSuccessfulAuthentication()

3. 测试覆盖率 ​

3.1 测试覆盖率定义 ​

测试覆盖率是衡量测试对源代码覆盖程度的指标，反映测试的完整性。

3.2 覆盖率类型 ​

mermaid
graph TD
    A[测试覆盖率类型] --> B[代码覆盖率]
    A --> C[功能覆盖率]
    
    B --> B1[语句覆盖率]
    B --> B2[分支覆盖率]
    B --> B3[路径覆盖率]
    B --> B4[条件覆盖率]
    
    C --> C1[需求覆盖率]
    C --> C2[业务场景覆盖率]

3.2.1 代码覆盖率类型详解 ​

覆盖率类型计算方式目标值优点缺点
语句覆盖率已执行语句/总语句70-80%容易测量覆盖不全
分支覆盖率已覆盖分支/总分支80-90%检测逻辑遗漏复杂度高
条件覆盖率布尔条件真假覆盖85-95%更细致组合爆炸
路径覆盖率已覆盖路径/总路径60-70%最完整几乎不可行

3.3 覆盖率计算示例 ​

3.3.1 示例代码 ​

java
public class CoverageExample {
    public String calculateGrade(int score, boolean isMakeup) {
        String grade;
        
        if (score >= 90) {
            grade = "A";
        } else if (score >= 80) {
            grade = "B";
        } else if (score >= 70) {
            grade = "C";
        } else if (score >= 60) {
            grade = "D";
        } else {
            grade = "F";
        }
        
        if (isMakeup && !grade.equals("A")) {
            grade += "+";
        }
        
        return grade;
    }
}

3.3.2 覆盖率分析 ​

java
public class CoverageExampleTest {
    private CoverageExample example = new CoverageExample();
    
    @Test
    void testScore95() {
        // 覆盖: score >= 90 分支
        // 覆盖: isMakeup = false 分支
        assertEquals("A", example.calculateGrade(95, false));
    }
    
    @Test
    void testScore85WithMakeup() {
        // 覆盖: score >= 80 分支  
        // 覆盖: isMakeup = true 且 grade != "A" 分支
        assertEquals("B+", example.calculateGrade(85, true));
    }
    
    // 语句覆盖率分析
    // 已执行语句: 所有if判断 + grade = "A", grade = "B", grade += "+", return
    // 未执行语句: grade = "C", grade = "D", grade = "F"
    // 语句覆盖率: ~70%
}

3.6 覆盖率最佳实践 ​

3.6.1 合理设定目标 ​

  • 新项目：初始目标80%语句覆盖率
  • 遗留系统：逐步提升，每次迭代提高2-5%
  • 关键模块：要求95%以上覆盖率

3.6.2 避免覆盖率陷阱 ​

java
// 错误示例：为了覆盖率而测试
@Test
void testGetterSetter() {
    User user = new User();
    user.setName("John");  // 设置值
    assertEquals("John", user.getName());  // 验证getter
    // 这种测试价值有限，只是提高了覆盖率数字
}

// 正确做法：测试业务逻辑
@Test
void testUserAgeValidation() {
    User user = new User();
    assertThrows(ValidationException.class, () -> {
        user.setAge(-5);  // 测试边界条件和验证逻辑
    });
}

4.2 完整的测试流水线 ​

yaml
# .github/workflows/test-pipeline.yml
name: Test Pipeline

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  unit-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - name: Run unit tests with coverage
        run: |
          mvn test jacoco:report
      - name: Upload coverage report
        uses: codecov/codecov-action@v2
        
  quality-gate:
    needs: unit-test
    runs-on: ubuntu-latest
    steps:
      - name: Check coverage quality gate
        run: |
          # 检查覆盖率是否达标
          coverage=$(curl -s https://codecov.io/api/gh/${{ github.repository }}/branch/${{ github.ref }} | jq '.commit.totals.c')
          if (( $(echo "$coverage < 80" | bc -l) )); then
            echo "覆盖率未达标: $coverage%"
            exit 1
          fi

5. 总结 ​

5.1 关键要点 ​

  1. 测试策略为测试活动提供方向和框架
  2. 单元测试是质量保证的基础，应该快速、独立、全面
  3. 测试覆盖率是重要的质量指标，但要避免盲目追求数字
  4. 结合适当的工具和实践，构建有效的测试体系

5.2 持续改进 ​

  • 定期评审测试策略的有效性
  • 监控覆盖率趋势而非绝对数值
  • 平衡测试投入与回报
  • 培养团队的测试文化

通过系统化的测试策略、高质量的单元测试和合理的覆盖率目标，可以显著提升软件质量和开发效率。
