二、算法优化策略 ​

2.1 时间复杂度优化 ​

原操作优化后时间复杂度变化
列表线性搜索字典/集合查找O(n)→O(1)
冒泡排序Timsort(内置sort)O(n²)→O(n log n)
双重循环使用itertools.product减少嵌套层次

2.2 空间换时间 ​

python
# 斐波那契数列的递归 vs 动态规划
def fib_recursive(n):
    if n <= 1: return n
    return fib_recursive(n-1) + fib_recursive(n-2)  # O(2^n)

def fib_dp(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b  # O(n)
    return a

五、并发与并行 ​

5.1 多线程（I/O密集型） ​

python
from concurrent.futures import ThreadPoolExecutor
import requests

urls = [...]  # 大量URL列表

def fetch(url):
    return requests.get(url).content

# 顺序执行（慢）
results = [fetch(url) for url in urls]

# 线程池优化
with ThreadPoolExecutor(max_workers=20) as executor:
    results = list(executor.map(fetch, urls))

5.2 多进程（CPU密集型） ​

python
from concurrent.futures import ProcessPoolExecutor
import math

def is_prime(n):
    # 计算密集型任务
    if n < 2: return False
    for i in range(2, int(math.sqrt(n)) + 1):
        if n % i == 0: return False
    return True

numbers = large_numbers_list  # 大型数字列表

# 顺序执行
results = [is_prime(n) for n in numbers]

# 进程池优化
with ProcessPoolExecutor() as executor:
    results = list(executor.map(is_prime, numbers))

6.2 Cython混合编程 ​

md
# cython: language_level=3
# filename: fastmath.pyx

def compute_pi(int n):
    cdef double pi = 0
    cdef int i
    cdef double sign = 1
    
    for i in range(1, n*2, 2):
        pi += sign * (4.0 / i)
        sign = -sign
    return pi

7.2 slots减少内存 ​

python
class RegularUser:
    def __init__(self, name, user_id):
        self.name = name
        self.user_id = user_id
        # 动态字典：占用更多内存

class OptimizedUser:
    __slots__ = ('name', 'user_id')  # 固定属性
    def __init__(self, name, user_id):
        self.name = name
        self.user_id = user_id
        
# 内存节省：40-50%

十、优化原则总结 ​

  1. 测量优先：优化前先使用profiler定位瓶颈
  2. 二八定律：关注消耗80%时间的20%代码
  3. 避免过度优化：清晰性 > 微小性能提升
  4. 架构优化：算法改进 > 微观优化
  5. 资源权衡：时间 vs 内存 vs 代码复杂度

优化格言："过早优化是万恶之源" - Donald Knuth
应在保证正确性和可维护性的前提下进行性能优化
