🌐 Envoy代理架构模式学习笔记 ​

1️⃣ Envoy概述与核心定位 ​

1.1 什么是Envoy ​

Envoy是一个开源的高性能代理和通信总线，专为云原生应用设计。它是服务网格数据平面的核心组件，为服务间通信提供了统一的基础设施层。

1.2 设计哲学 ​

  • 透明性：对应用程序透明，无需修改代码
  • 通用性：支持多种协议和部署模式
  • 可观测性：内置丰富的监控和跟踪能力
  • 动态配置：支持运行时配置更新

3️⃣ 核心架构组件 ​

3.1 监听器（Listener） ​

负责接收网络流量，支持多种协议和传输方式。

配置示例：

yaml
listeners:
- name: http_listener
  address:
    socket_address:
      address: 0.0.0.0
      port_value: 8080
  filter_chains:
  - filters:
    - name: envoy.filters.network.http_connection_manager
      typed_config:
        "@type": type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
        stat_prefix: ingress_http
        http_filters:
        - name: envoy.filters.http.router

3.2 过滤器（Filter） ​

Envoy的核心处理单元，形成过滤器链处理请求和响应。

3.2.1 网络层过滤器 ​

处理原始TCP/UDP流量：

  • TLS检查器：识别TLS流量
  • TCP代理：基本的TCP流量转发
  • HTTP连接管理器：将HTTP流量转换为内部HTTP格式

3.2.2 HTTP层过滤器 ​

处理HTTP协议流量：

  • 路由器过滤器：路由HTTP请求到上游集群
  • CORS过滤器：处理跨域资源共享
  • 限流过滤器：实现速率限制
  • 故障注入过滤器：模拟故障场景

3.3 集群（Cluster） ​

定义上游服务的逻辑分组和负载均衡策略。

yaml
clusters:
- name: service_a
  connect_timeout: 5s
  type: EDS
  lb_policy: ROUND_ROBIN
  http2_protocol_options: {}
  health_checks:
    - timeout: 5s
      interval: 10s
      unhealthy_threshold: 3
      healthy_threshold: 2
      http_health_check:
        path: "/health"

4️⃣ 关键架构模式 ​

4.1 线程模型 ​

Envoy使用多线程架构，每个线程独立处理连接，实现高性能。

mermaid
graph TB
    subgraph Envoy Process
        A[主线程] --> B[管理接口]
        A --> C[配置加载]
        A --> D[统计聚合]
        
        E[工作线程1] --> F[监听器1]
        E --> G[连接1]
        E --> H[连接2]
        
        I[工作线程2] --> J[监听器2]
        I --> K[连接3]
        I --> L[连接4]
        
        M[工作线程N] --> N[监听器N]
        M --> O[连接M]
    end

特点：

  • 每个工作线程独立运行事件循环
  • 线程间无共享状态，减少锁竞争
  • 连接生命周期绑定到单个线程

4.2 配置发现服务（xDS） ​

Envoy通过xDS API从控制平面动态获取配置。

4.2.1 xDS协议类型 ​

  • LDS：监听器发现服务
  • RDS：路由发现服务
  • CDS：集群发现服务
  • EDS：端点发现服务
  • SDS：密钥发现服务
mermaid
sequenceDiagram
    participant E as Envoy
    participant CP as Control Plane
    
    Note over E, CP: 初始引导阶段
    E->>CP: LDS - 获取监听器配置
    CP->>E: 返回监听器列表

    E->>CP: CDS - 获取集群配置
    CP->>E: 返回集群定义
    
    E->>CP: EDS - 获取端点信息
    CP->>E: 返回服务实例列表
    
    Note over E, CP: 运行时更新
    CP->>E: 推送配置更新
    E->>E: 热重载配置

4.3 负载均衡策略 ​

Envoy支持多种负载均衡算法：

策略类型适用场景特点
轮询通用场景均匀分发请求
最少连接长连接服务考虑后端负载
一致性哈希缓存亲和性相同键的请求到相同后端
随机测试场景简单随机选择
区域感知多区域部署优先本区域后端

5️⃣ 请求处理流程 ​

5.1 完整请求生命周期 ​

mermaid
sequenceDiagram
    participant C as Downstream Client
    participant E as Envoy Proxy
    participant U as Upstream Service
    
    Note over C, U: 连接建立阶段
    C->>E: TCP连接请求
    E->>E: 监听器接受连接
    E->>E: 网络过滤器链处理
    E->>E: TLS握手（如启用）
    
    Note over C, U: 请求处理阶段
    C->>E: 发送HTTP请求
    E->>E: HTTP连接管理器解码
    E->>E: HTTP过滤器链处理
    E->>E: 路由匹配
    E->>E: 负载均衡选择端点
    E->>U: 建立到上游连接
    E->>U: 转发请求
    
    Note over C, U: 响应处理阶段
    U->>E: 返回响应
    E->>E: 上游HTTP过滤器链
    E->>E: 下游HTTP过滤器链
    E->>C: 发送响应到客户端
    
    Note over C, U: 连接清理阶段
    C->>E: 关闭连接
    E->>U: 关闭上游连接
    E->>E: 更新统计信息

6️⃣ 高级特性 ​

6.1 熔断器模式 ​

Envoy提供多种熔断机制保护后端服务：

yaml
circuit_breakers:
  thresholds:
    - priority: DEFAULT
      max_connections: 1000
      max_requests: 10000
      max_pending_requests: 500
    - priority: HIGH
      max_connections: 2000

6.2 健康检查 ​

支持主动和被动健康检查：

yaml
health_checks:
  - timeout: 5s
    interval: 10s
    interval_jitter: 2s
    unhealthy_threshold: 3
    healthy_threshold: 2
    http_health_check:
      path: "/health"
      expected_statuses:
        start: 200
        end: 299

6.3 可观测性 ​

  • 统计信息：丰富的计数器、直方图和指标
  • 访问日志：详细的请求/响应日志
  • 分布式追踪：支持Jaeger、Zipkin等
  • 运行时配置：动态功能标记控制

9️⃣ 总结 ​

Envoy作为现代服务网格的数据平面核心，其架构设计体现了以下关键原则：

  1. 高性能：基于C++和现代异步编程模型
  2. 可扩展性：通过过滤器链支持丰富功能扩展
  3. 动态配置：通过xDS实现零停机配置更新
  4. 可观测性：内置全面的监控和追踪能力
  5. 协议透明：支持HTTP/1.1、HTTP/2、gRPC等多种协议

掌握Envoy的架构模式对于构建可靠、可观测和高性能的微服务系统至关重要。
