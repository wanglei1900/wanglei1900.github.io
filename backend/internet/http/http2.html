HTTP/2 协议特性学习笔记 ​

1. HTTP/2 概述 ​

1.1 发展背景 ​

  • HTTP/1.1 问题：队头阻塞、头部冗余、并发限制
  • SPDY 协议：Google 开发的实验性协议，HTTP/2 的基础
  • 标准化：2015年发布为 RFC 7540 和 RFC 7541

1.2 设计目标 ​

mermaid
graph TD
    A[HTTP/2设计目标] --> B[减少延迟]
    A --> C[提高性能]
    A --> D[保持兼容性]
    
    B --> B1[多路复用]
    B --> B2[头部压缩]
    C --> C1[二进制分帧]
    C --> C2[服务器推送]
    D --> D1[语义不变]
    D --> D2[API兼容]

2. 核心特性详解 ​

2.1 二进制分帧层 ​

2.1.1 帧结构 ​

+-----------------------------------------------+
|                 Length (24)                   |
+---------------+---------------+---------------+
|   Type (8)    |   Flags (8)   |R|     Stream Identifier (31)  |
+=+=============+===============+===============================+
|                   Frame Payload (0...)                      ...
+---------------------------------------------------------------+

帧字段说明：

  • Length：帧负载长度（24位）
  • Type：帧类型（8位）
  • Flags：帧标志（8位）
  • R：保留位（1位）
  • Stream Identifier：流标识符（31位）
  • Frame Payload：帧数据

2.1.2 帧类型 ​

类型值说明
DATA0x0传输数据帧
HEADERS0x1打开流或携带头部
PRIORITY0x2设置流优先级
RST_STREAM0x3立即终止流
SETTINGS0x4连接配置参数
PUSH_PROMISE0x5服务器推送资源
PING0x6测量RTT和检测连接
GOAWAY0x7停止创建流
WINDOW_UPDATE0x8流量控制窗口更新
CONTINUATION0x9继续头部块片段

2.2 多路复用 ​

2.2.1 流的概念 ​

  • 流：连接中的双向字节流
  • 流ID：31位无符号整数，客户端发起为奇数，服务器为偶数
  • 流状态：复杂的状态机管理
mermaid
stateDiagram-v2
    [*] --> idle
    idle --> reserved : send/receive HEADERS
    idle --> open : send/receive HEADERS
    open --> half_closed_local : send END_STREAM
    open --> half_closed_remote : receive END_STREAM
    open --> closed : send/receive RST_STREAM
    half_closed_local --> closed : receive END_STREAM
    half_closed_remote --> closed : send END_STREAM
    reserved --> half_closed_remote : send HEADERS
    reserved --> closed : send/receive RST_STREAM
    closed --> [*]

2.3 头部压缩（HPACK） ​

2.3.1 HPACK 原理 ​

+-----------+----------------+----------------+
| 索引引用  | 字面量编码     | 霍夫曼编码     |
+-----------+----------------+----------------+
| 静态表    | 带索引或不带索引 | 字符串压缩    |
| 动态表    | 增量索引       | 减少传输大小   |
+-----------+----------------+----------------+

2.3.2 静态表（部分） ​

索引头部名称头部值
1:authority
2:methodGET
3:methodPOST
4:path/
5:path/index.html
6:schemehttp
7:schemehttps
8:status200
.........
61:status500

2.3.3 编码示例 ​

http
# HTTP/1.1 头部
GET /index.html HTTP/1.1
Host: www.example.com
User-Agent: browser
Accept: text/html

# HPACK 编码可能表示
[0x82, 0x86, 0x84]  # :method GET, :scheme https, :path /index.html
[0x40, 0x0a]        # 字面量头部，霍夫曼编码的"www.example.com"

2.4 服务器推送 ​

2.4.1 推送流程 ​

mermaid
sequenceDiagram
    participant C as Client
    participant S as Server
    
    C->>S: GET /index.html
    S->>S: 分析需要推送的资源
    S->>C: PUSH_PROMISE (stream id=2, path=/style.css)
    S->>C: PUSH_PROMISE (stream id=4, path=/script.js)
    S->>C: HEADERS + DATA (index.html)
    S->>C: HEADERS + DATA (style.css, stream=2)
    S->>C: HEADERS + DATA (script.js, stream=4)

2.4.2 推送条件 ​

  • 客户端可以拒绝推送（RST_STREAM）
  • 推送的资源必须在权威范围内
  • 推送需要缓存验证

2.5 流量控制 ​

2.5.1 窗口管理 ​

  • 连接级流量控制：整个连接的窗口大小
  • 流级流量控制：单个流的窗口大小
  • WINDOW_UPDATE帧：更新窗口大小

2.5.2 窗口更新示例 ​

初始窗口: 65535 字节
客户端消耗: 10000 字节
剩余窗口: 55535 字节
发送 WINDOW_UPDATE: 增加 10000
新窗口: 65535 字节

2.6 优先级 ​

2.6.1 优先级帧结构 ​

+--+-------------+--------------+----------------+
|E| Stream Dep  |   Weight     |
+--+-------------+--------------+----------------+
  • E：独占标志
  • Stream Dep：依赖的流ID
  • Weight：权重（1-256）

5. 实际部署考虑 ​

5.1 浏览器支持 ​

  • Chrome: 40+ 版本支持
  • Firefox: 36+ 版本支持
  • Safari: 9+ 版本支持
  • Edge: 12+ 版本支持

5.2 服务器配置 ​

5.2.1 Nginx 配置 ​

nginx
server {
    listen 443 ssl http2;
    server_name example.com;
    
    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;
    
    # HTTP/2 优化
    http2_max_field_size 16k;
    http2_max_header_size 32k;
    http2_max_requests 1000;
    http2_max_concurrent_streams 128;
}

5.2.2 Apache 配置 ​

apache
<VirtualHost *:443>
    ServerName example.com
    Protocols h2 http/1.1
    
    SSLEngine on
    SSLCertificateFile "/path/to/cert.pem"
    SSLCertificateKeyFile "/path/to/key.pem"
    
    # HTTP/2 配置
    H2Push on
    H2PushPriority * after
</VirtualHost>

7. 限制和挑战 ​

7.1 TCP 层限制 ​

  • 队头阻塞：TCP 包丢失影响所有流
  • 慢启动：影响连接建立性能
  • 拥塞控制：可能不如 QUIC 灵活

7.2 实现复杂性 ​

  • 状态机管理：复杂的流状态转换
  • 优先级处理：实现质量参差不齐
  • 内存使用：动态表管理需要谨慎

8. 与 HTTP/3 的关系 ​

mermaid
graph TD
    A[HTTP/1.1] --> B[HTTP/2]
    B --> C[HTTP/3]
    
    B --> B1[TCP传输]
    B --> B2[TLS 1.2+]
    B --> B3[二进制分帧]
    
    C --> C1[QUIC传输]
    C --> C2[内置TLS]
    C --> C3[改进的多路复用]

总结 ​

HTTP/2 通过二进制分帧、多路复用、头部压缩等特性显著提升了 Web 性能。虽然它解决了 HTTP/1.1 的许多问题，但仍然受到 TCP 协议的限制，这为 HTTP/3 的发展奠定了基础。
