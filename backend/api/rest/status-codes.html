REST API 状态码完整学习笔记 ​

1. HTTP状态码基础概念 ​

1.1 状态码定义 ​

  • 作用: 表示HTTP请求的处理结果
  • 结构: 3位数字代码 + 原因短语
  • 分类: 5个类别（1xx-5xx）

1.2 状态码分类 ​

1xx - 信息性状态码 (Informational)
2xx - 成功状态码 (Success)
3xx - 重定向状态码 (Redirection)
4xx - 客户端错误状态码 (Client Error)
5xx - 服务器错误状态码 (Server Error)

2. 1xx - 信息性状态码 ​

2.1 100 Continue ​

http
HTTP/1.1 100 Continue

使用场景:

  • 客户端发送大文件前，先询问服务器是否接受
  • 客户端发送Expect: 100-continue头

请求流程:

客户端 → 服务器: POST /upload | Expect: 100-continue
服务器 → 客户端: 100 Continue
客户端 → 服务器: 文件数据
服务器 → 客户端: 201 Created

2.2 101 Switching Protocols ​

http
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade

使用场景:

  • WebSocket升级协议
  • HTTP/2协议升级

2.3 102 Processing (WebDAV) ​

http
HTTP/1.1 102 Processing

使用场景:

  • 服务器需要长时间处理请求
  • 防止客户端超时

3. 2xx - 成功状态码 ​

3.1 200 OK ​

http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 123,
  "name": "示例资源",
  "status": "active"
}

使用场景:

  • 标准成功响应
  • GET请求获取资源
  • POST请求创建资源后的返回

变体:

http
# 200 OK with 空body
HTTP/1.1 200 OK
Content-Length: 0

# 200 OK with 自定义状态
HTTP/1.1 200 OK
Content-Type: application/json

{
  "status": "success",
  "data": {...},
  "message": "操作成功"
}

3.2 201 Created ​

http
HTTP/1.1 201 Created
Location: /api/users/123
Content-Type: application/json

{
  "id": 123,
  "name": "新用户",
  "createdAt": "2024-01-01T00:00:00Z"
}

使用场景:

  • 资源创建成功
  • 必须包含Location头指向新资源
  • 响应体可包含创建的资源

RESTful最佳实践:

java
@PostMapping("/users")
public ResponseEntity<User> createUser(@RequestBody User user) {
    User created = userService.create(user);
    URI location = ServletUriComponentsBuilder
        .fromCurrentRequest()
        .path("/{id}")
        .buildAndExpand(created.getId())
        .toUri();
    
    return ResponseEntity.created(location).body(created);
}

3.3 202 Accepted ​

http
HTTP/1.1 202 Accepted
Location: /api/queue/processing/456
Content-Type: application/json

{
  "taskId": "456",
  "status": "processing",
  "estimatedCompletion": "2024-01-01T00:05:00Z"
}

使用场景:

  • 请求已接受，但处理尚未完成
  • 异步处理、批处理操作
  • 应该包含状态查询端点

3.4 204 No Content ​

http
HTTP/1.1 204 No Content

使用场景:

  • 请求成功，但无内容返回
  • DELETE操作成功
  • PUT/PATCH更新成功，无需返回完整资源

示例:

java
@DeleteMapping("/users/{id}")
public ResponseEntity<Void> deleteUser(@PathVariable Long id) {
    userService.delete(id);
    return ResponseEntity.noContent().build();
}

@PatchMapping("/users/{id}/status")
public ResponseEntity<Void> updateStatus(@PathVariable Long id, 
                                        @RequestBody StatusUpdate update) {
    userService.updateStatus(id, update.getStatus());
    return ResponseEntity.noContent().build();
}

HTTP/1.1 205 Reset Content

4.4 303 See Other ​

http
HTTP/1.1 303 See Other
Location: /api/orders/456/status

使用场景:

  • POST操作后重定向到GET请求
  • 防止表单重复提交

RESTful模式:

java
@PostMapping("/orders")
public ResponseEntity<Void> createOrder(@RequestBody Order order) {
    Order created = orderService.create(order);
    return ResponseEntity.status(HttpStatus.SEE_OTHER)
        .location(URI.create("/api/orders/" + created.getId()))
        .build();
}

5. 4xx - 客户端错误状态码 ​

5.1 400 Bad Request ​

http
HTTP/1.1 400 Bad Request
Content-Type: application/problem+json

{
  "type": "https://example.com/errors/invalid-request",
  "title": "请求参数无效",
  "status": 400,
  "detail": "email字段格式不正确",
  "instance": "/api/users",
  "errors": [
    {
      "field": "email",
      "message": "必须是有效的邮箱地址"
    }
  ]
}

使用场景:

  • 通用客户端错误
  • 请求语法错误
  • 参数验证失败

验证错误示例:

java
@PostMapping("/users")
public ResponseEntity<?> createUser(@Valid @RequestBody UserCreateRequest request,
                                   BindingResult bindingResult) {
    if (bindingResult.hasErrors()) {
        Map<String, String> errors = new HashMap<>();
        bindingResult.getFieldErrors().forEach(error -> 
            errors.put(error.getField(), error.getDefaultMessage()));
        
        return ResponseEntity.badRequest()
            .body(ErrorResponse.builder()
                .code("VALIDATION_ERROR")
                .message("请求参数验证失败")
                .details(errors)
                .build());
    }
    // ... 正常处理
}

http
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="example", error="invalid_token", error_description="访问令牌已过期"
Content-Type: application/json

{
  "error": "unauthorized",
  "error_description": "访问令牌已过期",
  "code": "TOKEN_EXPIRED"
}

5.3 403 Forbidden ​

http
HTTP/1.1 403 Forbidden
Content-Type: application/json

{
  "error": "forbidden",
  "message": "您没有权限执行此操作",
  "requiredPermissions": ["USER_DELETE"],
  "userPermissions": ["USER_READ"]
}

使用场景:

  • 身份认证成功，但权限不足
  • 访问被策略拒绝

与401的区别:

java
// 401 - 未认证
if (authentication == null || !authentication.isAuthenticated()) {
    return ResponseEntity.status(HttpStatus.UNAUTHORIZED).build();
}

// 403 - 已认证但无权限
if (!hasPermission(authentication, resource, "DELETE")) {
    return ResponseEntity.status(HttpStatus.FORBIDDEN).build();
}

public ResponseEntity<?> updateArticle(@PathVariable Long id,

        return ResponseEntity.ok(updated);

        return ResponseEntity.status(HttpStatus.CONFLICT)

}

错误处理示例:

java
@ControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(Exception.class)
    public ResponseEntity<ErrorResponse> handleGenericException(Exception ex) {
        String requestId = MDC.get("requestId");
        ErrorResponse error = ErrorResponse.builder()
            .code("INTERNAL_ERROR")
            .message("服务器内部错误")
            .requestId(requestId)
            .timestamp(Instant.now())
            .build();
        
        // 记录完整异常日志
        log.error("Unhandled exception [requestId: {}]", requestId, ex);
        
        return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR)
            .body(error);
    }
}

// 标准错误响应体
public class ErrorResponse {
    private String code;        // 业务错误码
    private String message;     // 用户可读消息
    private String requestId;   // 请求追踪ID
    private Instant timestamp;  // 错误时间
    private Map<String, Object> details; // 错误详情
    
    // 工厂方法
    public static ErrorResponse of(String code, String message) {
        return new ErrorResponse(code, message, 
            MDC.get("requestId"), Instant.now());
    }
}

    public ResponseEntity<Void> deleteUser(@PathVariable Long id) {
        if (userService.delete(id)) {
            return ResponseEntity.noContent().build();
        }
        return ResponseEntity.notFound().build();
    }
}

@Component
public class StatusCodeMetrics {
    private final MeterRegistry meterRegistry;
    private final Counter[] statusCounters;
    
    public void recordStatusCode(String method, String path, int status) {
        String statusClass = status / 100 + "xx";
        Counter counter = meterRegistry.counter("http.requests",
            "method", method,
            "path", path,
            "status", String.valueOf(status),
            "statusClass", statusClass);
        counter.increment();
    }
}

总结 ​

正确使用HTTP状态码是构建高质量RESTful API的关键：

  1. 语义明确: 状态码应该准确反映操作结果
  2. 一致性: 相同类型的错误使用相同的状态码
  3. 信息丰富: 结合错误响应体提供详细错误信息
  4. 遵循标准: 严格遵守HTTP规范定义的状态码语义
  5. 可监控: 通过状态码统计监控API健康状态

通过合理使用状态码，可以大大提高API的可用性、可维护性和用户体验。
