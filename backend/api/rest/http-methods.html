RESTful API - HTTP方法 学习笔记 ​

1. REST架构风格概述 ​

1.1 REST核心原则 ​

  • 客户端-服务器分离：关注点分离
  • 无状态：每个请求包含所有必要信息
  • 可缓存：响应必须明确标识是否可缓存
  • 统一接口：标准化交互方式
  • 分层系统：架构可分层
  • 按需代码（可选）：客户端可下载执行代码

1.2 HTTP在REST中的角色 ​

HTTP是REST架构风格最常用的应用协议，提供：

  • 标准化的请求方法
  • 状态码
  • 头部信息
  • 缓存机制

2. HTTP方法详解 ​

2.1 GET - 获取资源 ​

2.1.1 定义与特性 ​

  • 安全：不应改变服务器状态
  • 幂等：多次调用结果相同
  • 可缓存：响应通常可被缓存

2.1.2 使用场景 ​

http
GET /api/users
GET /api/users/123
GET /api/users?page=2&limit=20
GET /api/users/123/orders

2.1.3 代码示例 ​

java
@RestController
@RequestMapping("/api/users")
public class UserController {
    
    @GetMapping
    public ResponseEntity<List<User>> getUsers(
            @RequestParam(defaultValue = "0") int page,
            @RequestParam(defaultValue = "20") int limit) {
        List<User> users = userService.findUsers(page, limit);
        return ResponseEntity.ok(users);
    }
    
    @GetMapping("/{id}")
    public ResponseEntity<User> getUser(@PathVariable Long id) {
        User user = userService.findById(id);
        return user != null ? 
            ResponseEntity.ok(user) : 
            ResponseEntity.notFound().build();
    }
    
    @GetMapping("/{id}/orders")
    public ResponseEntity<List<Order>> getUserOrders(@PathVariable Long id) {
        List<Order> orders = orderService.findByUserId(id);
        return ResponseEntity.ok(orders);
    }
}

2.2 POST - 创建资源 ​

2.2.1 定义与特性 ​

  • 不安全：改变服务器状态
  • 不幂等：多次调用产生不同结果
  • 不可缓存：响应通常不可缓存

2.2.2 使用场景 ​

http
POST /api/users

2.2.3 代码示例 ​

@PostMapping
public ResponseEntity<User> createUser(@Valid @RequestBody CreateUserRequest request) {
    try {
        User newUser = userService.createUser(request);
        
        // 返回201 Created，包含Location头部
        URI location = ServletUriComponentsBuilder
            .fromCurrentRequest()
            .path("/{id}")
            .buildAndExpand(newUser.getId())
            .toUri();
            
        return ResponseEntity.created(location).body(newUser);
    } catch (DuplicateUserException e) {
        return ResponseEntity.status(HttpStatus.CONFLICT).build();
    }
}

        .path("/api/orders/{id}")

}

2.3 PUT - 替换资源 ​

2.3.1 定义与特性 ​

  • 不安全：改变服务器状态
  • 幂等：多次调用结果相同
  • 完整更新：替换整个资源

2.3.2 使用场景 ​

http
PUT /api/users/123
PUT /api/products/456

2.3.3 代码示例 ​

java
@PutMapping("/{id}")
public ResponseEntity<User> updateUser(
        @PathVariable Long id,
        @Valid @RequestBody UpdateUserRequest request) {
    
    try {
        User updatedUser = userService.updateUser(id, request);
        return ResponseEntity.ok(updatedUser);
    } catch (UserNotFoundException e) {
        // PUT可以用于创建资源（如果客户端知道ID）
        if (request.isAllowCreate()) {
            User newUser = userService.createUser(id, request);
            URI location = ServletUriComponentsBuilder
                .fromCurrentRequest()
                .build().toUri();
            return ResponseEntity.created(location).body(newUser);
        }
        return ResponseEntity.notFound().build();
    }
}

2.3.4 完整替换模式 ​

java
public class UserService {
    public User updateUser(Long id, UpdateUserRequest request) {
        User existingUser = userRepository.findById(id)
            .orElseThrow(() -> new UserNotFoundException(id));
        
        // 完整替换：创建新对象或完全更新
        User updatedUser = User.builder()
            .id(existingUser.getId())
            .username(request.getUsername())
            .email(request.getEmail())
            .firstName(request.getFirstName())
            .lastName(request.getLastName())
            .createdAt(existingUser.getCreatedAt()) // 保留创建时间
            .updatedAt(LocalDateTime.now())
            .build();
            
        return userRepository.save(updatedUser);
    }
}

2.4 PATCH - 部分更新资源 ​

2.4.1 定义与特性 ​

  • 不安全：改变服务器状态
  • 幂等（应该）：多次调用结果相同
  • 部分更新：只更新提供的字段

2.4.2 使用场景 ​

http
PATCH /api/users/123
Content-Type: application/json-patch+json

[
    { "op": "replace", "path": "/email", "value": "new@email.com" }
]

2.4.3 代码示例 ​

java
// JSON Patch格式
@PatchMapping(path = "/{id}", consumes = "application/json-patch+json")
public ResponseEntity<User> patchUser(
        @PathVariable Long id,
        @RequestBody JsonPatch patch) {
    
    try {
        User user = userService.findById(id);
        User patchedUser = applyPatch(user, patch);
        User updatedUser = userService.save(patchedUser);
        return ResponseEntity.ok(updatedUser);
    } catch (UserNotFoundException e) {
        return ResponseEntity.notFound().build();
    }
}

// 自定义部分更新格式
@PatchMapping(path = "/{id}", consumes = "application/merge-patch+json")
public ResponseEntity<User> partialUpdateUser(
        @PathVariable Long id,
        @RequestBody Map<String, Object> updates) {
    
    User updatedUser = userService.partialUpdate(id, updates);
    return ResponseEntity.ok(updatedUser);
}

2.4.4 服务层实现 ​

java
@Service
public class UserService {
    
    @Transactional
    public User partialUpdate(Long id, Map<String, Object> updates) {
        User user = userRepository.findById(id)
            .orElseThrow(() -> new UserNotFoundException(id));
        
        // 使用反射或工具类进行部分更新
        updates.forEach((key, value) -> {
            switch (key) {
                case "email":
                    user.setEmail((String) value);
                    break;
                case "firstName":
                    user.setFirstName((String) value);
                    break;
                case "lastName":
                    user.setLastName((String) value);
                    break;
                // 处理其他字段...
            }
        });
        
        user.setUpdatedAt(LocalDateTime.now());
        return userRepository.save(user);
    }
}

public class UserService {

        // 物理删除
        userRepository.deleteById(id);
    }
}

4.2 状态码映射 ​

java
public class ResponseHelper {
    
    public static <T> ResponseEntity<T> createResponse(OperationResult<T> result) {
        switch (result.getStatus()) {
            case SUCCESS:
                if (result.isCreated()) {
                    return ResponseEntity.status(HttpStatus.CREATED).body(result.getData());
                } else if (result.hasData()) {
                    return ResponseEntity.ok(result.getData());
                } else {
                    return ResponseEntity.noContent().build();
                }
                
            case NOT_FOUND:
                return ResponseEntity.notFound().build();
                
            case CONFLICT:
                return ResponseEntity.status(HttpStatus.CONFLICT).body(result.getData());
                
            case VALIDATION_ERROR:
                return ResponseEntity.badRequest().body(result.getData());
                
            case UNAUTHORIZED:
                return ResponseEntity.status(HttpStatus.UNAUTHORIZED).build();
                
            default:
                return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).build();
        }
    }
}

java
@GetMapping("/{id}")
public ResponseEntity<User> getUser(
        @PathVariable Long id,
        WebRequest request) {
    
    User user = userService.findById(id);
    if (user == null) {
        return ResponseEntity.notFound().build();
    }
    
    // 检查ETag
    String eTag = computeETag(user);
    if (request.checkNotModified(eTag)) {
        return ResponseEntity.status(HttpStatus.NOT_MODIFIED).build();
    }
    
    return ResponseEntity.ok()
        .eTag(eTag)
        .lastModified(user.getUpdatedAt().toEpoch(ZoneOffset.UTC))
        .body(user);
}

@PutMapping("/{id}")
public ResponseEntity<User> updateUser(
        @PathVariable Long id,
        @Valid @RequestBody UpdateUserRequest userRequest,
        @RequestHeader(value = "If-Match", required = false) String ifMatch) {
    
    // 乐观锁检查
    if (ifMatch != null) {
        User existing = userService.findById(id);
        String currentETag = computeETag(existing);
        if (!currentETag.equals(ifMatch)) {
            return ResponseEntity.status(HttpStatus.PRECONDITION_FAILED).build();
        }
    }
    
    User updated = userService.updateUser(id, userRequest);
    return ResponseEntity.ok()
        .eTag(computeETag(updated))
        .body(updated);
}

6. 错误处理与验证 ​

6.1 统一的错误响应 ​

java
@ControllerAdvice
public class GlobalExceptionHandler {
    
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidationErrors(MethodArgumentNotValidException ex) {
        List<FieldError> fieldErrors = ex.getBindingResult().getFieldErrors();
        List<ValidationError> errors = fieldErrors.stream()
            .map(fieldError -> new ValidationError(
                fieldError.getField(),
                fieldError.getDefaultMessage()))
            .collect(Collectors.toList());
            
        ErrorResponse errorResponse = ErrorResponse.builder()
            .status(HttpStatus.BAD_REQUEST.value())
            .message("Validation failed")
            .errors(errors)
            .timestamp(Instant.now())
            .build();
            
        return ResponseEntity.badRequest().body(errorResponse);
    }
    
    @ExceptionHandler(ResourceNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(ResourceNotFoundException ex) {
        ErrorResponse errorResponse = ErrorResponse.builder()
            .status(HttpStatus.NOT_FOUND.value())
            .message(ex.getMessage())
            .timestamp(Instant.now())
            .build();
            
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body(errorResponse);
    }
    
    @ExceptionHandler(ConcurrentModificationException.class)
    public ResponseEntity<ErrorResponse> handleConcurrentModification(ConcurrentModificationException ex) {
        ErrorResponse errorResponse = ErrorResponse.builder()
            .status(HttpStatus.CONFLICT.value())
            .message("Resource was modified by another request")
            .timestamp(Instant.now())
            .build();
            
        return ResponseEntity.status(HttpStatus.CONFLICT).body(errorResponse);
    }
}

    User user = userService.findById(id);
    if (user == null) {
        return ResponseEntity.notFound().build();
    }
    
    return ResponseEntity.ok()
        .cacheControl(CacheControl.maxAge(1, TimeUnit.HOURS).cachePublic())
        .eTag(computeETag(user))
        .lastModified(user.getUpdatedAt().toInstant())
        .body(user);
}

@GetMapping("/public")
public ResponseEntity<List<User>> getPublicUsers() {
    List<User> users = userService.findPublicUsers();
    
    return ResponseEntity.ok()
        .cacheControl(CacheControl.maxAge(30, TimeUnit.MINUTES))
        .body(users);
}

7.2 条件请求处理 ​

java
@GetMapping("/{id}")
public ResponseEntity<User> getUser(
        @PathVariable Long id,
        WebRequest request) {
    
    User user = userService.findById(id);
    if (user == null) {
        return ResponseEntity.notFound().build();
    }
    
    // 基于最后修改时间的条件请求
    long lastModified = user.getUpdatedAt().toEpochSecond();
    if (request.checkNotModified(lastModified)) {
        return null; // Spring会自动返回304
    }
    
    // 基于ETag的条件请求
    String eTag = computeETag(user);
    if (request.checkNotModified(eTag)) {
        return null;
    }
    
    return ResponseEntity.ok()
        .lastModified(lastModified)
        .eTag(eTag)
        .body(user);
}

10. 总结与最佳实践 ​

10.1 HTTP方法选择指南 ​

操作类型HTTP方法路径示例说明
获取集合GET/api/users可带查询参数
获取单个GET/api/users/{id}
创建POST/api/users返回201 Created
完整更新PUT/api/users/{id}替换整个资源
部分更新PATCH/api/users/{id}只更新提供字段
删除DELETE/api/users/{id}返回204 No Content
子资源创建POST/api/users/{id}/orders
操作执行POST/api/users/{id}/activateRPC风格操作

10.2 最佳实践清单 ​

  • [ ] 使用正确的HTTP方法：GET用于读取，POST用于创建，PUT用于替换，PATCH用于部分更新
  • [ ] 使用合适的HTTP状态码：200 OK, 201 Created, 204 No Content, 400 Bad Request, 404 Not Found等
  • [ ] 提供一致的错误响应：统一的错误格式和消息
  • [ ] 实现正确的幂等性：GET、PUT、DELETE应该是幂等的
  • [ ] 使用HATEOAS：提供资源链接关系
  • [ ] 支持条件请求：ETag和Last-Modified头部
  • [ ] 实现适当的缓存：Cache-Control头部
  • [ ] 验证所有输入：请求参数和请求体验证
  • [ ] 处理并发：乐观锁机制
  • [ ] 提供API文档：OpenAPI/Swagger文档

10.3 常见反模式 ​

java
// 错误：错误使用HTTP方法
