操作系统知识 - 内存管理 - 垃圾回收 ​

1. 内存管理基础 ​

1.1 内存管理的目的 ​

  • 地址空间抽象：为每个进程提供独立的虚拟地址空间
  • 内存保护：防止进程间相互干扰
  • 内存共享：允许进程间安全地共享内存
  • 虚拟内存：使用磁盘扩展物理内存

1.2 关键概念 ​

  • 物理地址：内存硬件实际使用的地址
  • 逻辑地址：程序使用的地址，需要转换为物理地址
  • 地址绑定：将逻辑地址映射到物理地址的过程
  • 分页：将内存划分为固定大小的块
  • 分段：按逻辑单元划分内存

2. 垃圾回收概述 ​

2.1 什么是垃圾回收 ​

垃圾回收（Garbage Collection, GC）是自动内存管理的一种形式，自动识别和回收不再被程序使用的内存。

2.2 手动内存管理的问题 ​

c
// C语言中的典型内存泄漏
void memory_leak() {
    int *ptr = (int*)malloc(sizeof(int) * 100);
    // 使用ptr...
    // 忘记调用free(ptr) - 内存泄漏
}

2.3 垃圾回收的优势 ​

  • 防止内存泄漏
  • 避免悬空指针
  • 减少程序复杂度
  • 提高开发效率

3. 垃圾回收算法 ​

3.1 引用计数法（Reference Counting） ​

基本原理 ​

  • 每个对象维护一个引用计数器
  • 引用增加时计数器加1
  • 引用减少时计数器减1
  • 计数器为0时立即回收对象

伪代码示例 ​

class Object:
    ref_count = 0
    
    def add_reference():
        ref_count += 1
        
    def remove_reference():
        ref_count -= 1
        if ref_count == 0:
            reclaim_memory()

优缺点 ​

优点：

  • 实时回收，无暂停
  • 实现简单
  • 内存使用可预测

缺点：

  • 无法处理循环引用
  • 计数器操作开销大
  • 内存局部性差

3.2 标记-清除算法（Mark and Sweep） ​

算法步骤 ​

  1. 标记阶段：从根对象开始，标记所有可达对象
  2. 清除阶段：遍历堆，回收未标记的对象

伪代码实现 ​

// 标记阶段
function mark():
    roots = get_root_references()
    worklist = empty_stack()
    
    for each ref in roots:
        worklist.push(ref)
        
    while not worklist.empty():
        obj = worklist.pop()
        if not obj.marked:
            obj.marked = true
            for each child in obj.references:
                worklist.push(child)

// 清除阶段
function sweep():
    for each object in heap:
        if object.marked:
            object.marked = false
        else:
            heap.reclaim(object)

优缺点 ​

优点：

  • 能处理循环引用
  • 实现相对简单

缺点：

  • 内存碎片化
  • 暂停时间较长
  • 需要停止整个程序（Stop-the-World）

3.3 复制算法（Copying GC） ​

算法原理 ​

  • 将堆分为两个半空间：From-space和To-space
  • 只使用From-space分配对象
  • GC时将所有存活对象复制到To-space
  • 交换From-space和To-space的角色

伪代码实现 ​

function copy_gc():
    to_space = get_to_space()
    from_space = get_from_space()
    
    // 复制根对象
    for each root in roots:
        root = copy_object(root, to_space)
    
    // 更新引用
    scan = to_space.start
    while scan < to_space.used:
        obj = object_at(scan)
        for each reference in obj:
            if reference points to from_space:
                reference = copy_object(reference, to_space)
        scan += obj.size
    
    swap_spaces()

function copy_object(obj, to_space):
    if obj already copied:
        return forwarding_address
    
    new_obj = allocate_in_to_space(obj.size)
    copy_memory(obj, new_obj)
    set_forwarding_address(obj, new_obj)
    return new_obj

优缺点 ​

优点：

  • 无内存碎片
  • 分配速度快（指针碰撞）
  • 局部性好

缺点：

  • 内存利用率只有50%
  • 复制大对象开销大

3.4 标记-压缩算法（Mark-Compact） ​

算法步骤 ​

  1. 标记阶段：同标记-清除算法
  2. 压缩阶段：将所有存活对象移动到堆的一端

压缩策略 ​

  • 任意顺序：不考虑对象间的引用关系
  • 线性顺序：保持对象在内存中的分配顺序
  • 滑动顺序：保持对象在堆中的相对顺序

伪代码实现 ​

function mark_compact():
    // 标记阶段
    mark()
    
    // 计算新位置
    compute_locations()
    
    // 更新引用
    update_references()
    
    // 移动对象
    move_objects()

function compute_locations():
    free = heap.start
    for each object in heap:
        if object.marked:
            object.new_location = free
            free += object.size

function update_references():
    for each object in heap:
        if object.marked:
            for each reference in object:
                reference = referenced_object.new_location

function move_objects():
    for each object in heap:
        if object.marked:
            copy_object(object, object.new_location)
            object.marked = false

优缺点 ​

优点：

  • 消除内存碎片
  • 内存利用率高

缺点：

  • 三次遍历堆，开销大
  • 实现复杂

3.5 分代垃圾回收（Generational GC） ​

理论基础 ​

  • 弱代假说：大多数对象很快死亡
  • 强代假说：存活越久的对象越可能继续存活

分代设计 ​

  • 年轻代：新创建的对象
  • 老年代：多次GC后仍然存活的对象

代间引用处理 ​

  • 写屏障：记录从老年代到年轻代的引用
  • 卡表：记录可能包含跨代引用的内存区域

伪代码实现 ​

class GenerationalGC:
    young_gen = YoungGeneration()
    old_gen = OldGeneration()
    remembered_set = Set()
    
    function minor_gc():
        // 只收集年轻代
        roots = get_roots() + remembered_set
        young_gen.collect(roots)
        
        // 提升存活时间长的对象
        for each survivor in young_gen:
            if survivor.age > threshold:
                old_gen.promote(survivor)
    
    function major_gc():
        // 收集整个堆
        roots = get_roots()
        young_gen.collect(roots)
        old_gen.collect(roots)
    
    function write_barrier(source, target):
        if source in old_gen and target in young_gen:
            remembered_set.add(source)

优缺点 ​

优点：

  • 针对对象生命周期优化
  • GC暂停时间短
  • 吞吐量高

缺点：

  • 实现复杂
  • 需要写屏障支持

4. 高级垃圾回收技术 ​

4.1 增量式垃圾回收 ​

  • 将GC工作分成小片段执行
  • 与应用程序交替运行
  • 减少单次暂停时间

4.2 并发垃圾回收 ​

  • GC线程与应用程序线程并发执行
  • 几乎无暂停时间
  • 需要复杂的同步机制

4.3 并行垃圾回收 ​

  • 使用多个GC线程并行工作
  • 减少GC总时间
  • 需要多核处理器支持

5. 现代垃圾收集器实现 ​

5.1 Java HotSpot VM 收集器 ​

Serial收集器 ​

  • 单线程Stop-the-World
  • 适合客户端应用

Parallel收集器 ​

  • 多线程并行收集
  • 注重吞吐量

CMS收集器 ​

  • 并发标记清除
  • 低暂停时间

G1收集器 ​

  • 分Region的堆布局
  • 可预测的暂停时间目标

5.2 .NET CLR收集器 ​

工作站模式 ​

  • 针对交互式应用优化
  • 低暂停时间优先

服务器模式 ​

  • 针对服务器应用优化
  • 吞吐量优先

6. 垃圾回收性能指标 ​

6.1 关键指标 ​

  • 吞吐量：GC时间占程序总运行时间的比例
  • 暂停时间：单次GC导致应用程序暂停的时间
  • 内存效率：GC管理的内存使用效率
  • 可扩展性：在大堆上的表现

6.2 调优参数 ​

java
// Java GC调优示例
-XX:+UseG1GC                    // 使用G1收集器
-XX:MaxGCPauseMillis=200        // 目标最大暂停时间
-XX:InitiatingHeapOccupancyPercent=45  // 触发并发GC的堆占用率
-Xms4g -Xmx4g                   // 堆大小设置

7.2 编程实践 ​

java
// 减少内存分配压力
public class ObjectPool<T> {
    private Queue<T> pool = new LinkedList<>();
    
    public T getObject() {
        if (pool.isEmpty()) {
            return createNewObject();
        }
        return pool.poll();
    }
    
    public void returnObject(T obj) {
        resetObject(obj);
        pool.offer(obj);
    }
}

总结 ​

垃圾回收是现代编程语言和操作系统的重要特性，它通过自动化内存管理大大提高了开发效率和程序稳定性。不同的GC算法各有优缺点，适用于不同的应用场景。理解GC的工作原理对于编写高性能、内存高效的应用程序至关重要。

随着硬件和软件技术的发展，垃圾回收技术也在不断演进，向着更低延迟、更高吞吐量和更好可预测性的方向发展。
