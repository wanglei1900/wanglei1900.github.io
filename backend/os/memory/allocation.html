操作系统内存管理 - 内存分配学习笔记 ​

1. 内存管理概述 ​

1.1 内存管理的基本目标 ​

  • 地址抽象：将逻辑地址转换为物理地址
  • 内存保护：防止进程间非法访问
  • 内存共享：允许进程间共享内存区域
  • 虚拟内存：提供比物理内存更大的地址空间

1.2 内存管理的关键功能 ​

  • 内存分配与回收
  • 地址转换
  • 内存保护
  • 内存共享
  • 虚拟内存管理

2. 连续内存分配 ​

2.1 单一连续分配 ​

  • 特点：整个系统只有一个用户进程占用内存
  • 缺点：内存利用率低，不支持多道程序

2.2 固定分区分配 ​

cpp
// 分区表结构示例
struct Partition {
    int base_address;  // 基地址
    int size;         // 分区大小
    bool allocated;   // 分配状态
    int process_id;   // 占用进程ID
};

分配策略：

  • 等大小分区：所有分区大小相同
  • 不等大小分区：多种大小的分区组合

问题：

  • 内部碎片：分区内未使用的空间
  • 分区数量固定，限制并发进程数

2.3 动态分区分配 ​

数据结构：

  • 空闲分区表
  • 空闲分区链

分配算法：

首次适应算法（First Fit） ​

cpp
// 首次适应算法伪代码
Partition* first_fit(int request_size) {
    Partition* current = free_list_head;
    while (current != nullptr) {
        if (current->size >= request_size) {
            return current;  // 找到第一个合适的空闲分区
        }
        current = current->next;
    }
    return nullptr;  // 没有找到合适分区
}

最佳适应算法（Best Fit） ​

cpp
// 最佳适应算法伪代码
Partition* best_fit(int request_size) {
    Partition* best = nullptr;
    Partition* current = free_list_head;
    
    while (current != nullptr) {
        if (current->size >= request_size) {
            if (best == nullptr || current->size < best->size) {
                best = current;  // 找到最小的合适分区
            }
        }
        current = current->next;
    }
    return best;
}

最坏适应算法（Worst Fit） ​

cpp
// 最坏适应算法伪代码
Partition* worst_fit(int request_size) {
    Partition* worst = nullptr;
    Partition* current = free_list_head;
    
    while (current != nullptr) {
        if (current->size >= request_size) {
            if (worst == nullptr || current->size > worst->size) {
                worst = current;  // 找到最大的合适分区
            }
        }
        current = current->next;
    }
    return worst;
}

邻近适应算法（Next Fit） ​

  • 从上次分配结束的位置开始查找
  • 减少查找开销

2.4 分区回收与碎片问题 ​

分区回收情况：

  1. 上下邻接都是空闲分区：合并三个分区
  2. 上邻接是空闲分区：向上合并
  3. 下邻接是空闲分区：向下合并
  4. 无邻接空闲分区：创建新空闲分区

碎片问题：

  • 外部碎片：分布在各个已分配分区之间的空闲分区
  • 内部碎片：分配单元内部未使用的空间

解决方案：

  • 紧凑技术：移动内存中的进程，使所有空闲分区连成一片
  • 交换技术：将暂时不运行的进程换出到外存

3. 非连续内存分配 ​

3.1 分页管理（Paging） ​

基本概念 ​

cpp
// 页表项结构
struct PageTableEntry {
    int frame_number;    // 物理帧号
    bool valid;         // 有效位
    bool dirty;         // 修改位
    bool referenced;    // 引用位
    int protection;     // 保护位
};

地址转换过程：

逻辑地址 = 页号(P) + 页内偏移(D)
物理地址 = 帧号(f) + 页内偏移(D)

多级页表 ​

cpp
// 二级页表示例
struct SecondLevelPageTable {
    PageTableEntry entries[PAGE_TABLE_SIZE];
};

struct FirstLevelPageTable {
    SecondLevelPageTable* second_level_tables[OUTER_TABLE_SIZE];
};

优势：

  • 减少页表内存占用
  • 支持稀疏地址空间

缺点：

  • 增加地址转换时间

快表（TLB） ​

  • 转换后备缓冲器，缓存最近使用的页表项
  • 大幅提高地址转换速度

3.2 分段管理（Segmentation） ​

段表结构 ​

cpp
struct SegmentTableEntry {
    int base_address;    // 段基址
    int limit;          // 段长度
    bool valid;         // 有效位
    int protection;     // 保护权限
};

地址转换：

逻辑地址 = 段号(S) + 段内偏移(D)
if (D < limit) {
    物理地址 = base_address + D
} else {
    产生段错误
}

分段优势 ​

  • 符合程序逻辑结构
  • 便于共享和保护
  • 支持动态增长

3.3 段页式管理 ​

  • 结合分段和分页的优点
  • 先分段，段内再分页

4. 虚拟内存管理 ​

4.1 请求分页系统 ​

页表扩展 ​

cpp
struct EnhancedPageTableEntry {
    int frame_number;    // 物理帧号
    bool present;       // 存在位
    bool modified;      // 修改位
    bool referenced;    // 引用位
    int protection;     // 保护位
    int location;       // 页面位置（内存/磁盘）
};

缺页中断处理流程 ​

  1. 检查页面是否在内存中
  2. 如果不在，产生缺页中断
  3. 从磁盘调入所需页面
  4. 如果有必要，调出某个页面
  5. 更新页表
  6. 重新执行引起中断的指令

4.2 页面置换算法 ​

最佳置换算法（OPT） ​

cpp
// OPT算法伪代码
int opt_replace(vector<int>& page_references, int current_index, 
                vector<Page>& memory_frames) {
    int farthest_use = -1;
    int victim_page = -1;
    
    for (auto& page : memory_frames) {
        int next_use = find_next_use(page_references, current_index, page.id);
        if (next_use > farthest_use) {
            farthest_use = next_use;
            victim_page = page.id;
        }
    }
    return victim_page;
}

先进先出算法（FIFO） ​

cpp
// FIFO算法实现
class FIFOReplacer {
    queue<int> page_queue;
    
public:
    int select_victim() {
        int victim = page_queue.front();
        page_queue.pop();
        return victim;
    }
    
    void page_accessed(int page_id) {
        page_queue.push(page_id);
    }
};

最近最久未使用算法（LRU） ​

cpp
// LRU算法实现（使用链表）
class LRUReplacer {
    list<int> lru_list;
    unordered_map<int, list<int>::iterator> page_map;
    
public:
    int select_victim() {
        int victim = lru_list.back();
        lru_list.pop_back();
        page_map.erase(victim);
        return victim;
    }
    
    void page_accessed(int page_id) {
        if (page_map.find(page_id) != page_map.end()) {
            lru_list.erase(page_map[page_id]);
        }
        lru_list.push_front(page_id);
        page_map[page_id] = lru_list.begin();
    }
};

时钟算法（Clock） ​

cpp
// 时钟算法实现
class ClockReplacer {
    vector<Page> pages;
    int hand;  // 时钟指针
    
public:
    int select_victim() {
        while (true) {
            Page& current = pages[hand];
            if (current.referenced) {
                current.referenced = false;  // 给第二次机会
            } else {
                int victim = hand;
                hand = (hand + 1) % pages.size();
                return victim;
            }
            hand = (hand + 1) % pages.size();
        }
    }
};

4.3 页面分配策略 ​

固定分配 ​

  • 每个进程固定数量的物理帧
  • 局部置换策略

可变分配 ​

  • 根据进程需求动态调整帧数
  • 全局置换策略

工作集模型 ​

cpp
// 工作集计算
struct WorkingSet {
    unordered_set<int> pages;
    int window_size;  // 工作集窗口大小
};

WorkingSet calculate_working_set(const vector<int>& page_references, 
                                int current_time, int window_size) {
    WorkingSet ws;
    ws.window_size = window_size;
    
    for (int i = max(0, current_time - window_size); i <= current_time; i++) {
        ws.pages.insert(page_references[i]);
    }
    return ws;
}

缺页率调节 ​

  • 监控进程缺页率
  • 根据缺页率调整分配的物理帧数

8. 总结 ​

内存分配是操作系统核心功能，涉及从简单的连续分配到复杂的虚拟内存管理。现代操作系统采用多层次、多策略的内存管理方法，在性能、效率和资源利用率之间寻求平衡。理解这些概念对于系统编程和性能优化至关重要。

关键要点：

  • 选择合适的分配算法基于具体应用场景
  • 虚拟内存提供了地址空间抽象和内存保护
  • 页面置换算法影响系统整体性能
  • 现代硬件特性（多级缓存、NUMA）需要特殊考虑
