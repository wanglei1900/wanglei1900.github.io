操作系统 I/O 管理 - 阻塞/非阻塞学习笔记 ​

1. I/O 管理基础概念 ​

1.1 I/O 系统概述 ​

  • I/O 设备分类：
    • 字符设备（键盘、鼠标）：以字符为单位传输
    • 块设备（硬盘、U盘）：以数据块为单位传输
    • 网络设备（网卡）：特殊处理

1.2 I/O 控制方式 ​

  1. 程序控制 I/O (PIO)
  2. 中断驱动 I/O
  3. 直接内存访问 (DMA)
  4. 通道控制方式

2. 阻塞 I/O (Blocking I/O) ​

2.1 基本概念 ​

c
// 典型阻塞I/O示例
int n = read(fd, buffer, sizeof(buffer)); // 线程在此阻塞，直到数据就绪
process_data(buffer);

2.2 工作流程 ​

应用程序调用read() → 内核准备数据 → 应用程序阻塞等待
                        ↓
                数据准备好并复制到用户空间
                        ↓
                应用程序解除阻塞，继续执行

2.3 特点 ​

  • 同步执行：I/O操作完成前线程暂停
  • 简单易用：编程模型直观
  • 资源浪费：线程在等待时无法执行其他任务
  • 适用场景：简单应用、并发要求不高的场景

2.4 多线程阻塞方案 ​

c
// 每个连接一个线程
void* handle_client(void* arg) {
    int client_fd = *(int*)arg;
    char buffer[1024];
    
    while(1) {
        // 阻塞读取
        int n = read(client_fd, buffer, sizeof(buffer));
        if(n <= 0) break;
        
        // 处理数据
        process_request(buffer, n);
    }
    close(client_fd);
    return NULL;
}

3. 非阻塞 I/O (Non-blocking I/O) ​

3.1 基本概念 ​

c
// 设置文件描述符为非阻塞
fcntl(fd, F_SETFL, O_NONBLOCK);

// 非阻塞读取
int n = read(fd, buffer, sizeof(buffer));
if(n == -1 && errno == EAGAIN) {
    // 数据未就绪，可以执行其他任务
    do_other_work();
} else {
    process_data(buffer, n);
}

3.2 工作流程 ​

应用程序调用read() → 内核立即返回
                        ↓
            如果数据未就绪，返回错误(EAGAIN)
                        ↓
            应用程序轮询或执行其他任务

3.3 特点 ​

  • 立即返回：无论数据是否就绪都立即返回
  • 轮询开销：需要不断检查I/O状态
  • CPU利用率：可能造成CPU空转
  • 编程复杂：需要处理返回状态

3.4 轮询实现 ​

c
int non_blocking_read(int fd, char* buffer, int size) {
    int n;
    do {
        n = read(fd, buffer, size);
        if(n == -1) {
            if(errno == EAGAIN || errno == EWOULDBLOCK) {
                // 数据未就绪，短暂等待后重试
                usleep(1000); // 1ms
                continue;
            } else {
                // 真实错误
                return -1;
            }
        }
    } while(n == -1);
    
    return n;
}

4. I/O 多路复用 (I/O Multiplexing) ​

4.1 select 系统调用 ​

c
fd_set readfds;
struct timeval timeout;

while(1) {
    FD_ZERO(&readfds);
    FD_SET(socket_fd, &readfds);
    
    timeout.tv_sec = 5;
    timeout.tv_usec = 0;
    
    int ready = select(socket_fd + 1, &readfds, NULL, NULL, &timeout);
    
    if(ready > 0) {
        if(FD_ISSET(socket_fd, &readfds)) {
            // 数据就绪，可以非阻塞读取
            read(socket_fd, buffer, sizeof(buffer));
        }
    }
}

4.2 poll 系统调用 ​

c
struct pollfd fds[1];
fds[0].fd = socket_fd;
fds[0].events = POLLIN;

while(1) {
    int ready = poll(fds, 1, 5000); // 5秒超时
    
    if(ready > 0) {
        if(fds[0].revents & POLLIN) {
            // 数据就绪
            read(socket_fd, buffer, sizeof(buffer));
        }
    }
}

4.3 epoll (Linux) ​

c
// 创建epoll实例
int epoll_fd = epoll_create1(0);

// 添加监控的文件描述符
struct epoll_event event;
event.events = EPOLLIN;
event.data.fd = socket_fd;
epoll_ctl(epoll_fd, EPOLL_CTL_ADD, socket_fd, &event);

struct epoll_event events[MAX_EVENTS];
while(1) {
    int nfds = epoll_wait(epoll_fd, events, MAX_EVENTS, -1);
    
    for(int i = 0; i < nfds; i++) {
        if(events[i].events & EPOLLIN) {
            // 处理就绪的I/O
            handle_io(events[i].data.fd);
        }
    }
}

5. 异步 I/O (Asynchronous I/O) ​

5.1 Linux AIO ​

c
struct aiocb aio_req;
char buffer[BUFFER_SIZE];

memset(&aio_req, 0, sizeof(aio_req));
aio_req.aio_fildes = fd;
aio_req.aio_buf = buffer;
aio_req.aio_nbytes = BUFFER_SIZE;

// 发起异步读取
aio_read(&aio_req);

// 可以做其他工作
do_other_work();

// 检查完成状态
while(aio_error(&aio_req) == EINPROGRESS) {
    // 等待完成
}

// 获取结果
ssize_t bytes_read = aio_return(&aio_req);

6. Reactor 模式 ​

6.1 基本架构 ​

Event Demultiplexer (select/poll/epoll)
        ↓
Dispatcher (事件分发器)
        ↓
Event Handler (事件处理器)

6.2 实现示例 ​

cpp
class Reactor {
private:
    std::unordered_map<int, std::function<void()>> handlers;
    int epoll_fd;
    
public:
    void register_handler(int fd, std::function<void()> handler) {
        handlers[fd] = handler;
        
        struct epoll_event event;
        event.events = EPOLLIN;
        event.data.fd = fd;
        epoll_ctl(epoll_fd, EPOLL_CTL_ADD, fd, &event);
    }
    
    void run() {
        struct epoll_event events[64];
        
        while(true) {
            int n = epoll_wait(epoll_fd, events, 64, -1);
            for(int i = 0; i < n; i++) {
                int fd = events[i].data.fd;
                if(handlers.count(fd)) {
                    handlers[fd]();
                }
            }
        }
    }
};

7. 性能比较 ​

7.1 各种I/O模型对比 ​

模型并发能力CPU利用率编程复杂度适用场景
阻塞I/O低低简单低并发应用
非阻塞I/O+轮询中低中等不推荐
I/O多路复用高高复杂高并发网络应用
异步I/O高高复杂高性能I/O密集型

7.2 选择策略 ​

  1. 连接数少：阻塞I/O或多线程阻塞
  2. 高并发连接：I/O多路复用(epoll/kqueue)
  3. 大量文件I/O：考虑异步I/O
  4. 跨平台需求：select/poll或使用库(libevent/libuv)

8. 实际编程注意事项 ​

8.1 错误处理 ​

c
// 正确的非阻塞I/O错误处理
ssize_t n = read(fd, buf, size);
if(n == -1) {
    if(errno == EAGAIN || errno == EWOULDBLOCK) {
        // 非阻塞I/O的正常情况，稍后重试
        return;
    } else if(errno == EINTR) {
        // 被信号中断，可以重试
        return;
    } else {
        // 真正的错误
        perror("read failed");
        close(fd);
        return;
    }
}

8.2 边缘触发 vs 水平触发 ​

  • 水平触发(Level-Triggered)：数据可读时一直通知
  • 边缘触发(Edge-Triggered)：状态变化时只通知一次
c
// epoll边缘触发示例
event.events = EPOLLIN | EPOLLET;  // 边缘触发

// 必须一次性读取所有数据
while(true) {
    ssize_t count = read(fd, buffer, sizeof(buffer));
    if(count == -1) {
        if(errno == EAGAIN) break; // 数据读取完毕
        // 处理错误
        break;
    } else if(count == 0) {
        // 连接关闭
        break;
    }
    process_data(buffer, count);
}

9. 现代I/O编程框架 ​

9.1 常用库 ​

  • libevent：跨平台事件通知库
  • libuv：Node.js使用的异步I/O库
  • Boost.Asio：C++异步I/O库

9.2 最佳实践 ​

  1. 避免混合使用不同I/O模型
  2. 注意线程安全
  3. 合理设置缓冲区大小
  4. 监控I/O性能指标
  5. 考虑使用成熟的网络库
