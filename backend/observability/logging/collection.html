可观测性、日志管理与日志收集学习笔记 ​

第一部分：核心概念 ​

1. 可观测性 ​

  • 定义：可观测性不仅仅是监控。它是指通过系统的外部输出来理解其内部状态的能力。一个系统可观测性越高，我们越能通过其产生的数据快速定位和诊断未知问题。
  • 三大支柱：
    1. 日志：系统在特定时间点发生的事件的离散记录。回答“发生了什么”。
    2. 指标：随时间变化的、可聚合的数值数据。回答“系统表现如何”。
    3. 追踪：单个请求在分布式系统中端到端的路径和性能。回答“请求经过了哪里，性能瓶颈在哪”。

2. 日志管理 ​

  • 定义：一个涵盖日志从生成到最终处置的完整生命周期管理过程。
  • 目标：确保日志数据可用、可靠、安全，并能被高效地用于故障排查、安全审计和业务分析。
  • 生命周期：
    1. 生成与收集
    2. 传输与缓冲
    3. 处理与丰富
    4. 存储与索引
    5. 分析与可视化
    6. 归档与销毁

3. 日志收集 ​

  • 定义：日志管理生命周期的第一个关键环节，负责从各种来源（如应用程序、操作系统、网络设备等）可靠地获取日志数据，并将其发送到中央处理系统。
  • 核心挑战：
    • 来源多样性：日志格式、输出位置（文件、标准输出、网络端口）各不相同。
    • 数据海量性：在微服务和云原生环境下，日志数据量巨大。
    • 可靠性：不能因为日志收集影响应用性能，也不能丢失日志。
    • 资源消耗：收集代理本身应尽可能轻量。

2. 最佳实践 ​

  1. 结构化日志：

    • 优先输出 JSON 格式的日志，而不是纯文本。这便于后续的解析和字段查询。
    • 示例： {"timestamp": "2023-10-27T10:00:00Z", "level": "ERROR", "message": "Database connection failed", "user_id": 12345}

  2. 配置合理的日志级别： 避免在生产环境大量输出 DEBUG 日志，减少不必要的开销。

  3. 使用侧车模式： 在 Kubernetes 中，为每个 Pod 部署一个专用的日志收集代理容器（如 Fluent Bit），与业务容器共享日志卷。这是最推荐的模式。

    mermaid
    graph TB
    subgraph Pod
        A[业务容器]
        F[日志收集容器<br>Fluent Bit]
        A -- 写入日志 --> V[共享Volume]
        V -- 读取日志 --> F
    end
    F --> CentralLogging[中央日志平台]

  4. 解耦与缓冲： 务必在收集代理和后端处理系统之间使用 Kafka 等消息队列，以应对后端故障或流量激增。

  5. 敏感信息处理： 在收集或处理阶段，使用插件对密码、密钥、身份证号等敏感信息进行脱敏。

  6. 使用标签/元数据丰富日志： 在收集时为日志添加诸如 pod_name, namespace, node_name, app_version 等元数据，便于在分布式环境中定位问题。

第五部分：现代架构与趋势 ​

1. EFK Stack（Elasticsearch + Fluentd/Fluent Bit + Kibana） ​

  • Fluentd/Fluent Bit： 负责收集和传输日志。
  • Elasticsearch： 负责存储和索引日志，提供强大的搜索能力。
  • Kibana： 负责日志的可视化、查询和分析。
  • 这是目前最流行的开源日志管理解决方案之一。

2. Loki Stack（Grafana Loki + Promtail + Grafana） ​

  • 设计哲学： 只索引日志的元数据（标签），而不索引日志内容，存储压缩的日志内容。更简单、成本更低。
  • Promtail： 负责收集日志并添加标签，然后发送给 Loki。
  • Loki： 日志存储引擎。
  • Grafana： 用于查询和可视化 Loki 中的日志，可以与指标和追踪在同一界面中展示。
  • 特别适合与 Prometheus 指标和 Tempo/Grafana 追踪一起使用，实现统一的可观测性。

3. 无代理架构 ​

在某些 Serverless 或高度受限的环境中，应用程序可能直接将日志推送到一个中央化的服务（如云服务商的日志服务），而不在本地运行收集代理。

总结 ​

  • 日志是可观测性的基石，它记录了离散事件，用于回答“发生了什么”。
  • 日志收集是日志管理的入口，其核心是可靠、高效地从各种来源获取数据。
  • 选择合适的收集代理（如 Fluentd, Filebeat, Fluent Bit, Vector）是关键决策，需权衡性能、资源和功能。
  • 一个健壮的收集架构必须考虑缓冲（Kafka） 和处理。
  • 遵循最佳实践（结构化、侧车模式、解耦、脱敏）是保证日志系统有效性的前提。
  • 现代日志系统（如 EFK 和 Loki）提供了完整的解决方案，选择取决于具体需求（如全文本搜索 vs. 成本效率）。
