📝 理解日志轮转 ​

日志轮转是系统管理中一个自动化的归档过期日志文件的过程。服务器上运行的软件（如Web服务器、数据库等）会持续记录日志，面对数量巨大的日志，日志轮转提供了一个有效的方法来限制日志文件的大小，同时保留近期的日志用于分析。

核心价值

  • 防止磁盘空间耗尽：避免单个日志文件无限增长，占满磁盘空间，导致系统或应用故障。
  • 便于日志归档与检索：按时间或大小分割日志，便于分类、压缩、归档和后续查找分析。
  • 提升处理效率：操作较小的日志文件通常比操作单个巨型文件性能更高。

🔧 核心轮转机制与工具 ​

在Linux生态中，logrotate是最常用和最核心的日志轮转工具。它功能强大，配置灵活，是系统管理的必备技能。

Logrotate 工作原理 ​

logrotate 的工作原理可以概括为以下几个步骤，通常会结合create或copytruncate两种模式之一：

mermaid
flowchart TD
    A[触发轮转<br>cron/手动] --> B{轮转模式}
    B -- create<br>默认推荐 --> C[创建新的空日志文件]
    C --> D[重命名当前日志文件<br>如.log变为.log.1]
    D --> E[让应用切换到新文件<br>发信号或重启]
    
    B -- copytruncate<br>兼容性方案 --> F[复制当前日志文件<br>为备份文件]
    F --> G[清空截断原日志文件]
    G --> H[应用持续写入原文件]
    
    E & H --> I[可选的后续处理<br>压缩旧文件<br>删除超期文件<br>执行自定义脚本]

logrotate通常通过cron定时任务自动运行。例如，系统默认的logrotate任务放在/etc/cron.daily/目录下，每天执行一次。

Logrotate 配置文件 ​

logrotate的主要配置文件包括：

  • /etc/logrotate.conf：主配置文件，设置全局默认选项。
  • /etc/logrotate.d/：目录，用于存放特定应用程序的配置文件。该目录下的所有配置文件都会被/etc/logrotate.conf包含，这是配置应用日志轮转的主要位置。

一个典型的Nginx日志轮转配置示例如下，它清晰地展示了关键配置项的作用：

bash
/var/log/nginx/*.log {  # 指定要轮转的日志文件路径
    daily               # 轮转频率：每天
    rotate 7            # 保留7个备份文件
    missingok           # 日志文件不存在时，忽略错误继续执行
    notifempty          # 如果日志文件为空，则不进行轮转
    compress            # 压缩旧日志以节省空间
    delaycompress       # 延迟压缩，最新一个备份文件不压缩
    dateext             # 使用日期作为旧日志的后缀
    create 0644 www-data www-data  # 轮转后创建新日志文件，并指定权限和属主
    postrotate          # 轮转后执行的脚本
        # 通知Nginx重新打开日志文件，确保写入新文件
        [ -s /run/nginx.pid ] && kill -USR1 `cat /run/nginx.pid`
    endscript
}

create vs copytruncate ​

这是两种主要的轮转模式，理解它们的区别至关重要。

  • create（默认推荐）：

    • 过程：如图表所示，先重命名当前日志文件，然后创建一个新的同名日志文件，最后通过信号通知应用程序切换到新文件。
    • 优点：日志连续性有保障，更安全可靠。
    • 缺点：需要应用程序支持接收信号并重新打开日志文件。

  • copytruncate：

    • 过程：如图表所示，先复制当前日志文件内容到一个备份文件，然后清空（截断）原文件。
    • 优点：兼容性强，适用于那些无法通知其重新打开日志文件的应用程序。
    • 缺点：在复制和清空之间存在一个时间窗口，可能导致少量日志丢失。文件inode变化也可能导致某些日志采集器重复采集。

🛠️ 不同技术栈下的实践 ​

1. 系统与通用应用 (使用 Logrotate) ​

对于Nginx、系统日志等，直接在/etc/logrotate.d/目录下创建自定义配置文件即可，如前文示例。

手动测试与调试： 在应用配置之前，务必使用以下命令手动测试，这对调试很重要：

bash
sudo logrotate -d -f /etc/logrotate.d/your_app  # -d 调试模式，输出信息但不实际执行
sudo logrotate -f /etc/logrotate.d/your_app     # -f 强制立即执行轮转

2. Node.js 应用 ​

方案一：使用系统 Logrotate 这是最通用和推荐的方法。为你的Node.js应用日志在/etc/logrotate.d/下创建配置文件，配置方式与Nginx类似。

方案二：使用PM2内置日志管理 如果使用PM2进程管理器部署Node.js应用，它可以提供内置的日志轮转功能。

javascript
// ecosystem.config.js
module.exports = {
  apps: [{
    name: 'my-app',
    script: 'app.js',
    out_file: '/var/log/nodejs/my-app-out.log',
    error_file: '/var/log/nodejs/my-app-err.log',
    max_size: '10M',  // 单个日志文件最大10MB
    max_files: 7,      // 保留7个历史日志文件
    log_date_format: 'YYYY-MM-DD HH:mm Z'
  }]
};

3. Python 应用 ​

Python的logging模块内置了支持日志轮转的Handler。

基于大小的轮转：

python
import logging
from logging.handlers import RotatingFileHandler

handler = RotatingFileHandler(
    'my_app.log', maxBytes=10*1024*1024,  # 10MB
    backupCount=5  # 保留5个备份
)
logger.addHandler(handler)

基于时间的轮转：

python
import logging
from logging.handlers import TimedRotatingFileHandler

handler = TimedRotatingFileHandler(
    'my_app.log', when='midnight',  # 每天午夜轮转
    interval=1, backupCount=7
)
logger.addHandler(handler)

⚠️ 常见陷阱与最佳实践 ​

警惕日志轮转的"雷区" ​

  1. 谨慎使用 copytruncate：如前所述，可能导致日志丢失或重复采集。优先考虑使用create模式并配合postrotate脚本通知应用程序。
  2. 避免多进程并发写同一日志文件：这可能导致日志内容交叉混乱、采集不完整。应确保每个进程写入不同的日志文件，或使用中央日志收集器。
  3. 使用本地磁盘存储日志：避免直接使用NAS、OSS等网络存储作为日志的实时写入目标，因其元信息不一致和列表性能低，可能导致日志采集截断或停止。
  4. 禁止通过vim编辑日志文件：使用vim保存文件时会创建新文件并替换原文件，改变inode，可能导致日志重复采集或后续写入丢失。查看日志应使用less, tail, grep等只读工具。
  5. 避免覆盖写和文件空洞：不要使用覆盖整个日志文件或创建文件空洞的方式来释放空间，这会改变文件签名和内容，导致采集异常。

最佳实践总结 ​

  • 规划策略：根据日志量和重要性，制定清晰的轮转周期（日/周/月）和保留策略（数量/时间）。
  • 标准化命名：使用dateext让旧日志文件名更清晰。
  • 启用压缩：使用compress和delaycompress节省磁盘空间。
  • 确保权限正确：使用create指令确保新创建的日志文件具有正确的权限和属主，以便应用程序能够继续写入。
  • 监控与清理：定期检查日志轮转是否按计划执行，并监控磁盘空间。
