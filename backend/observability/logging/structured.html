1. 可观测性基础概念 ​

1.1 什么是可观测性 ​

可观测性 是指通过系统外部输出来理解系统内部状态的能力，包含三大支柱：

  • 日志 (Logs)
  • 指标 (Metrics)
  • 追踪 (Traces)

    A[可观测性] --> B[日志 Logs]
    A --> C[指标 Metrics]
    A --> D[追踪 Traces]
    
    B --> B1[事件记录]
    B --> B2[错误调试]
    B --> B3[行为分析]
    
    C --> C1[性能监控]
    C --> C2[资源使用]
    C --> C3[趋势分析]
    
    D --> D1[请求链路]
    D --> D2[性能瓶颈]
    D --> D3[依赖关系]

1.2 三大支柱的关系 ​

维度日志指标追踪
数据类型离散事件数值数据请求链路
粒度细粒度聚合数据请求级别
主要用途调试、审计监控、告警性能分析

3. 结构化日志详解 ​

3.1 非结构化 vs 结构化日志 ​

非结构化日志（传统方式）：

2023-10-01 12:30:45 ERROR User login failed for user john@example.com

结构化日志（现代方式）：

json
{
  "timestamp": "2023-10-01T12:30:45.123Z",
  "level": "ERROR",
  "message": "User login failed",
  "user_id": "usr_12345",
  "email": "john@example.com",
  "ip_address": "192.168.1.100",
  "session_id": "sess_abc123",
  "error_code": "AUTH_001",
  "service": "authentication-service",
  "trace_id": "trace-789xyz"
}

3.2 结构化日志的核心优势 ​

  1. 机器可读性 - 易于解析和处理
  2. 查询效率 - 支持复杂查询和过滤
  3. 字段标准化 - 统一的日志schema
  4. 上下文丰富 - 包含完整的业务上下文
  5. 易于集成 - 与监控系统无缝集成

3.3 结构化日志的关键字段 ​

json
{
  // 基础元数据
  "timestamp": "2023-10-01T12:30:45.123Z",
  "level": "INFO",
  "logger": "com.example.UserService",
  
  // 业务上下文
  "message": "User profile updated",
  "user_id": "usr_123",
  "action": "profile_update",
  
  // 技术上下文
  "service": "user-service",
  "version": "1.2.3",
  "environment": "production",
  
  // 请求链路
  "trace_id": "trace-abc123",
  "span_id": "span-456",
  "parent_span_id": "span-789",
  
  // 性能数据
  "duration_ms": 45,
  "memory_usage_mb": 128,
  
  // 自定义业务字段
  "fields": {
    "old_email": "old@example.com",
    "new_email": "new@example.com",
    "update_source": "web"
  }
}

4. 结构化日志实现模式 ​

4.1 日志 schema 设计 ​

python
# Python 结构化日志 schema 示例
import logging
import json
from datetime import datetime
from typing import Dict, Any

class StructuredLogger:
    def __init__(self, name: str, service: str, version: str):
        self.logger = logging.getLogger(name)
        self.base_fields = {
            "service": service,
            "version": version,
            "environment": self.get_environment()
        }
    
    def info(self, message: str, **kwargs):
        log_entry = {
            **self.base_fields,
            "timestamp": datetime.utcnow().isoformat() + "Z",
            "level": "INFO",
            "message": message,
            **kwargs
        }
        self.logger.info(json.dumps(log_entry))
    
    def error(self, message: str, error: Exception = None, **kwargs):
        log_entry = {
            **self.base_fields,
            "timestamp": datetime.utcnow().isoformat() + "Z",
            "level": "ERROR",
            "message": message,
            "error_type": error.__class__.__name__ if error else None,
            "error_message": str(error) if error else None,
            **kwargs
        }
        self.logger.error(json.dumps(log_entry))

6. 结构化日志最佳实践 ​

6.1 设计原则 ​

  1. 一致性原则

    • 使用统一的字段命名规范
    • 保持相同语义的字段名称一致

  2. 上下文完整性

    • 包含足够的调试信息
    • 添加业务相关的标识符

  3. 性能考虑

    • 避免记录敏感信息
    • 控制日志体积和频率

6.3 安全考虑 ​

python
class SecureLogger:
    def __init__(self, logger):
        self.logger = logger
        self.sensitive_fields = [
            'password', 'token', 'secret', 
            'credit_card', 'ssn', 'api_key'
        ]
    
    def sanitize_data(self, data: Dict) -> Dict:
        sanitized = data.copy()
        for key, value in sanitized.items():
            if any(sensitive in key.lower() for sensitive in self.sensitive_fields):
                sanitized[key] = '***REDACTED***'
        return sanitized
    
    def info(self, message: str, **kwargs):
        safe_data = self.sanitize_data(kwargs)
        self.logger.info(message, **safe_data)

7.2 性能监控集成 ​

python
import time
import functools

def log_performance(operation_name: str):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            start_time = time.time()
            try:
                result = func(*args, **kwargs)
                duration = time.time() - start_time
                
                logger.info(
                    f"{operation_name} completed",
                    operation=operation_name,
                    duration_ms=round(duration * 1000, 2),
                    status="success"
                )
                return result
            except Exception as e:
                duration = time.time() - start_time
                logger.error(
                    f"{operation_name} failed",
                    operation=operation_name,
                    duration_ms=round(duration * 1000, 2),
                    status="error",
                    error=str(e)
                )
                raise
        return wrapper
    return decorator

class AuditLogger:
    def __init__(self, logger):
        self.logger = logger
    
    def log_security_event(self, event_type: str, user_id: str, **details):
        audit_log = {
            "event_type": event_type,
            "user_id": user_id,
            "timestamp": datetime.utcnow().isoformat() + "Z",
            "severity": "HIGH",

        }
        
        self.logger.info("Security audit event", **audit_log)

9. 总结 ​

结构化日志是现代可观测性体系的核心组成部分，它提供了：

  1. 更好的可调试性 - 通过丰富的上下文信息
  2. 更高的查询效率 - 支持复杂的过滤和分析
  3. 更强的可扩展性 - 易于集成到监控和告警系统
  4. 更佳的可维护性 - 统一的日志格式和规范

通过采用结构化日志，团队可以更有效地监控、调试和维护复杂的分布式系统。

关键要点：

  • 始终使用JSON格式的结构化日志
  • 包含足够的上下文信息
  • 遵循统一的字段命名规范
  • 集成追踪信息实现端到端可观测性
  • 实施适当的安全和隐私保护措施
