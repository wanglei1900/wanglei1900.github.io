理解和掌握链路追踪中的采样策略，对于构建高效、可控的可观测体系至关重要。下面这份学习笔记梳理了采样的核心知识、不同策略的优劣以及业界实践，希望能帮助你建立系统性的理解。

🔍 可观测性：链路追踪采样策略完全指南 ​

1️⃣ 为什么需要采样 ​

在分布式系统中，面对海量请求产生的巨大链路数据，全量采集会面临诸多挑战：

  • 存储成本压力：全量采集调用链数据会产生巨大的存储成本。以一个具体案例为例，某系统链路调用量4000 QPS，每个调用产生约30个Span，每个Span约500 Bytes，一天产生的数据量就高达4.7 TiB。若有100个调用链路入口需要全量采集，每天则可能产生400 TiB以上的数据。

  • 系统性能影响：全量采集会给每个业务服务的网络I/O以及链路追踪服务的计算和存储带来压力。

  • 极低的信噪比：根据伴鱼的实践经验，保守假设平均每个HTTP API服务的总QPS为100，完整存下全量数据需要10TB/天；乐观假设100名服务器研发每人每天查看1条trace，则整体信噪比仅千万分之一，投入产出比很低。

2️⃣ 采样的关键决策点 ​

制定采样策略时，需要考虑以下几个关键维度：

  • 采样时机：决定在链路的哪个阶段做出采样决策（头部、尾部或单元采样）。
  • 连贯性：是否保证整个调用链的完整性。
  • 策略灵活性：能否根据业务需求动态调整采样规则。
  • 资源开销：在业务服务、网络传输和服务端之间的平衡。

3️⃣ 采样策略分类 ​

根据采样决策的时机和方式，主要分为三大类策略：

3.1 头部采样 (Head-based Sampling) ​

mermaid
flowchart TD
    A[请求进入入口服务] --> B{采样决策}
    B -- 采样 --> C[标记并传递采样上下文]
    C --> D[下游服务继承采样]
    B -- 不采样 --> E[丢弃数据]

头部采样在请求入口处就决定整条链路是否采样。

  • 优点：

    • 显著降低业务服务器的网络I/O开销
    • 减少服务端的存储和计算开销

  • 缺点：

    • 采样发生在链路产生初期，命中异常和慢响应的几率低
    • 可能错过关键问题链路，影响故障排查

  • 增强方案：配合异常回溯上报机制，下游链路出现异常后，可以动态扭转上游链路的采样状态。

3.2 尾部采样 (Tail-based Sampling) ​

mermaid
flowchart TD
    A[请求经过完整链路] --> B[所有Span上报到Collector]
    B --> C[根据预设规则分析]
    C --> D{是否符合采样条件}
    D -- 是 --> E[保留完整链路]
    D -- 否 --> F[丢弃数据]

尾部采样在请求处理完成后，根据预设规则决定是否保留链路。

  • 优点：

    • 可精准采集异常、慢响应或有业务价值的链路
    • 有效降低存储成本同时保留高价值数据

  • 缺点：

    • 对业务服务器的网络I/O压力无缓解
    • 需要在服务端缓存所有链路数据直至做出决策

3.3 单元采样 (Unitary Sampling) ​

各个业务模块自主决定是否上报当前节点，单个节点的采样决策不影响链路上的其他服务。

  • 优点：避免整体业务链路采样决策影响，节点的异常信息可以精准上报
  • 缺点：链路连贯性无法保证，无法支持根据上下游进行有效根因分析

4️⃣ 具体采样算法与实践 ​

4.1 基础采样算法 ​

算法类型实现方式适用场景
固定概率采样按固定概率采样，如采样率10%通用场景，流量均匀的系统
简单随机采样每个请求独立随机决定是否采样基础采样需求
限流采样保证每个进程每隔一段时间最多采k个高流量服务，保护后端系统
周期性完整采样单位时间内只采集固定数量事件，超出的丢弃控制峰值流量下的数据量

4.2 高级采样策略 ​

  • 基于条件的采样：根据特定条件采样，如耗时阈值（>300ms）、HTTP状态码（400-600）、可用区等

  • 自适应采样：按单位时间采集固定数目的Trace为目标，例如单实例100条/min

  • 动态采样策略：通过采样策略树和执行轨迹图两种数据结构自动调整跟踪采样率，提高异常执行的跟踪占比

  • 染色采样：对于特定标记的请求（如测试泳道、重要用户）100%采样

  • 应急采样：请求传递过程中检测到错误或异常时，强制采样该请求

5️⃣ 业界实践案例 ​

5.1 头部采样增强方案 ​

SkyWalking：

  • 支持简单的采样百分比
  • 允许错误链路强制采样 (forceSampleErrorSegment)
  • 对慢SQL采样特别优化

Jaeger：

  • 支持Const（全采样或不采样）、Probabilistic（按固定概率采样）、Rate Limiting（限流采样）三种方式
  • 支持远程动态调整采样方式

5.2 尾部采样实践 ​

货拉拉：

  • 实现差异化完成链路采样
  • 保证1小时以内的数据全量保存（热数据）
  • 一小时以外的数据，只保留错、慢、核心服务请求Trace（冷数据）
  • 将整体存储成本降低了60%

腾讯云APM：

  • 支持异常、慢响应链路全保留
  • 可配置核心业务逻辑全保留
  • 重大事件保障期间全面监控

5.3 自适应采样实践 ​

阿里云ARMS自适应采样：

  • 特定接口全采样：通过自定义接口名、前后缀标记需要100%采样的接口
  • 接口Top N采样：使用变种LFU算法，单位时间内只对每个接口的有限条目请求采样
  • 小流量兜底采样：单位时间内，每个接口至少保证有1次采样

6️⃣ 采样策略选择指南 ​

6.1 基于业务场景的策略选择 ​

场景类型推荐策略配置建议
核心业务链路尾部采样 + 高采样率关键接口可配置80%-100%采样率
高流量入口头部采样 + 限流控制整体数据量，设置较低采样率
边缘业务单元采样/头部采样配置较低采样率（1%-5%）
重大事件保障临时全采样/染色采样特定时间段或特定标签全量采集
小流量接口自适应采样兜底确保每个接口单位时间至少有一次采样

6.2 成本效益优化策略 ​

  • 入口应用控制：通过调整入口应用的采样率可显著控制整体可观测数据采集量
  • 接口粒度配置：针对核心接口定向配置高比例采样率，非核心接口降低采样率
  • 价值导向采集：根据货拉拉经验，80%~90%的Trace数据都是无价值的，聚焦错、慢、核心服务请求

7️⃣ 总结 ​

采样策略的选择本质上是在观测价值与资源成本之间寻求平衡。有效的采样策略应该：

  1. 确保高价值链路（异常、慢调用、核心业务）被高效捕获
  2. 在成本可控的前提下提供足够的故障排查信息
  3. 具备灵活性，能根据不同场景动态调整
  4. 保持关键链路的连贯性，支持端到端问题定位

通过组合多种采样策略，因地制宜地配置，才能在可控的资源开销内，最大程度保留事故相关链路，支持高效的故障排查和性能监控。
