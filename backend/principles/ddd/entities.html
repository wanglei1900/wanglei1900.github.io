领域驱动设计(DDD) - 实体与值对象 学习笔记 ​

1. 领域驱动设计(DDD)概述 ​

1.1 DDD核心思想 ​

  • 以领域为核心：软件设计应反映业务领域的内在逻辑
  • 通用语言：开发团队与业务专家使用统一术语
  • 界限上下文：定义领域模型的边界
  • 战略设计：高层次架构决策
  • 战术设计：具体模式实现领域模型

2. 实体(Entity) ​

2.1 定义与特征 ​

实体是具有唯一标识和生命周期概念的领域对象。

核心特征：

  • 身份标识：具有唯一ID，不依赖于属性值
  • 连续性：在其生命周期内保持身份不变
  • 可变性：状态可以随时间改变
  • 生命周期：有创建、修改、销毁的过程

2.2 身份标识的实现方式 ​

java
// 示例：用户实体
public class User implements Entity<UserId> {
    private final UserId id;
    private String name;
    private Email email;
    private Date createdAt;
    private Date updatedAt;

    // 构造函数
    public User(UserId id, String name, Email email) {
        this.id = Objects.requireNonNull(id);
        this.name = validateName(name);
        this.email = email;
        this.createdAt = new Date();
        this.updatedAt = new Date();
    }

    // 基于身份的相等性比较
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        User user = (User) o;
        return id.equals(user.id);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
}

// 值对象：用户ID
public class UserId implements ValueObject {
    private final String value;
    
    public UserId(String value) {
        this.value = validateId(value);
    }
    
    // 值对象的相等性基于所有属性
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        UserId userId = (UserId) o;
        return value.equals(userId.value);
    }
}

2.3 实体的设计原则 ​

2.3.1 最小化可变性 ​

java
// 好的实践：使用不变性保护核心属性
public class Order implements Entity<OrderId> {
    private final OrderId id;
    private final CustomerId customerId;
    private final Date createdAt;
    private OrderStatus status;
    private List<OrderItem> items;

    // 核心标识不可变
    public Order(OrderId id, CustomerId customerId) {
        this.id = id;
        this.customerId = customerId;
        this.createdAt = new Date();
        this.status = OrderStatus.CREATED;
        this.items = new ArrayList<>();
    }

    // 通过方法控制状态变更
    public void addItem(ProductId productId, Quantity quantity) {
        // 业务规则验证
        if (status != OrderStatus.CREATED) {
            throw new IllegalStateException("Cannot modify completed order");
        }
        this.items.add(new OrderItem(productId, quantity));
    }
}

2.3.2 富行为模型 ​

java
public class BankAccount implements Entity<AccountNumber> {
    private final AccountNumber accountNumber;
    private Money balance;
    private AccountStatus status;

    // 业务行为作为方法
    public void withdraw(Money amount) {
        validateAccountActive();
        validateSufficientBalance(amount);
        this.balance = balance.subtract(amount);
        registerTransaction(TransactionType.WITHDRAWAL, amount);
    }

    public void deposit(Money amount) {
        validateAccountActive();
        this.balance = balance.add(amount);
        registerTransaction(TransactionType.DEPOSIT, amount);
    }

    private void validateAccountActive() {
        if (status != AccountStatus.ACTIVE) {
            throw new IllegalStateException("Account is not active");
        }
    }
}

3. 值对象(Value Object) ​

3.1 定义与特征 ​

值对象是描述领域特征的不可变对象，没有概念标识。

核心特征：

  • 无标识性：没有唯一标识，由其属性值定义
  • 不可变性：创建后状态不能改变
  • 值相等性：所有属性相等则对象相等
  • 可替换性：可以自由替换为相等的对象
  • 自包含性：包含所有必要的行为

3.2 值对象的实现模式 ​

3.2.1 基本值对象 ​

java
// 金钱值对象
public final class Money implements ValueObject {
    private final BigDecimal amount;
    private final Currency currency;

    public Money(BigDecimal amount, Currency currency) {
        this.amount = validateAmount(amount);
        this.currency = Objects.requireNonNull(currency);
    }

    // 不可变操作：返回新对象
    public Money add(Money other) {
        validateSameCurrency(other);
        return new Money(amount.add(other.amount), currency);
    }

    public Money subtract(Money other) {
        validateSameCurrency(other);
        return new Money(amount.subtract(other.amount), currency);
    }

    // 基于值的相等性
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Money money = (Money) o;
        return amount.compareTo(money.amount) == 0 && 
               currency.equals(money.currency);
    }

    @Override
    public int hashCode() {
        return Objects.hash(amount, currency);
    }
}

3.2.2 复合值对象 ​

java
// 地址值对象
public final class Address implements ValueObject {
    private final String street;
    private final String city;
    private final String postalCode;
    private final Country country;

    public Address(String street, String city, String postalCode, Country country) {
        this.street = validateStreet(street);
        this.city = validateCity(city);
        this.postalCode = validatePostalCode(postalCode);
        this.country = Objects.requireNonNull(country);
    }

    // 验证逻辑
    private String validateStreet(String street) {
        if (street == null || street.trim().isEmpty()) {
            throw new IllegalArgumentException("Street cannot be empty");
        }
        return street.trim();
    }

    // 完整的相等性比较
    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Address address = (Address) o;
        return street.equals(address.street) &&
               city.equals(address.city) &&
               postalCode.equals(address.postalCode) &&
               country.equals(address.country);
    }

    @Override
    public int hashCode() {
        return Objects.hash(street, city, postalCode, country);
    }
}

3.3 值对象的优势 ​

3.3.1 线程安全 ​

java
// 由于不可变性，值对象天然线程安全
public class Coordinate implements ValueObject {
    private final double latitude;
    private final double longitude;

    public Coordinate(double latitude, double longitude) {
        this.latitude = validateLatitude(latitude);
        this.longitude = validateLongitude(longitude);
    }

    // 无副作用的方法
    public Coordinate move(double deltaLat, double deltaLon) {
        return new Coordinate(latitude + deltaLat, longitude + deltaLon);
    }
}

3.3.2 简化测试 ​

java
class MoneyTest {
    @Test
    void should_add_money_correctly() {
        Money m1 = new Money(new BigDecimal("100.00"), Currency.USD);
        Money m2 = new Money(new BigDecimal("50.00"), Currency.USD);

4. 实体与值对象的比较 ​

4.1 核心差异对比表 ​

特征实体(Entity)值对象(Value Object)
身份标识有唯一标识无标识，由属性定义
相等性基于标识比较基于所有属性比较
可变性状态可变创建后不可变
生命周期有完整生命周期无独立生命周期
设计重点身份和连续性值和不变性

4.2 设计决策指南 ​

4.2.1 何时使用实体 ​

java
// 需要跟踪身份和状态变化的情况
public class Product implements Entity<ProductId> {
    private final ProductId id;
    private String name;
    private Money price;
    private ProductCategory category;
    
    // 需要跟踪价格变化历史

        this.price = newPrice;
        this.registerPriceChange(newPrice);
    }
}

6. 设计最佳实践 ​

6.1 验证与不变性保证 ​

java
public abstract class DomainObject {
    protected void validateNotNull(Object obj, String message) {
        if (obj == null) {
            throw new IllegalArgumentException(message);
        }
    }
    
    protected void validateCondition(boolean condition, String message) {
        if (!condition) {
            throw new IllegalArgumentException(message);
        }
    }
}

public final class Email implements ValueObject {
    private final String value;

    public Email(String value) {
        validateNotNull(value, "Email cannot be null");
        validateEmailFormat(value);
        this.value = value.toLowerCase().trim();
    }

    private void validateEmailFormat(String email) {
        String pattern = "^[A-Za-z0-9+_.-]+@(.+)$";
        if (!email.matches(pattern)) {
            throw new IllegalArgumentException("Invalid email format");
        }
    }
}

6.2 防御性复制 ​

java
public final class Period implements ValueObject {
    private final Date startDate;
    private final Date endDate;

    public Period(Date startDate, Date endDate) {
        // 防御性复制，防止外部修改
        this.startDate = new Date(startDate.getTime());
        this.endDate = new Date(endDate.getTime());
        validatePeriod();
    }

    public Date getStartDate() {
        // 返回副本，保护内部状态
        return new Date(startDate.getTime());
    }

    public Date getEndDate() {
        return new Date(endDate.getTime());
    }

    private void validatePeriod() {
        if (startDate.after(endDate)) {
            throw new IllegalArgumentException("Start date must be before end date");
        }
    }
}

7. 常见陷阱与解决方案 ​

7.1 过度使用实体 ​

问题：将所有领域对象都设计为实体

java
// 错误示例：将值对象设计为实体

    @Id
    private Long id;  // 不必要的标识
    private String street;
    private String city;

// 正确做法：使用值对象
public class Address implements ValueObject {
    private final String street;
    private final String city;
    // 基于值的相等性
}

8. 总结 ​

8.1 核心要点 ​

  1. 实体关注身份，值对象关注值
  2. 优先使用值对象，除非需要身份标识
  3. 保持值对象不可变，实体可变但控制变化
  4. 使用通用语言命名领域对象
  5. 封装业务规则在领域对象内部

8.2 设计检查清单 ​

  • [ ] 对象是否有独立身份？ → 实体
  • [ ] 对象是否由属性完全定义？ → 值对象
  • [ ] 对象是否需要跟踪变化？ → 实体
  • [ ] 对象是否可以自由替换？ → 值对象
  • [ ] 是否封装了完整的业务逻辑？
  • [ ] 是否保证了不变性约束？
  • [ ] 是否使用了防御性复制？

通过正确应用实体和值对象模式，可以创建出更清晰、更可维护、更符合业务领域的软件设计。
