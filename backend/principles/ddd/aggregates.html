领域驱动设计(DDD) - 聚合根学习笔记 ​

1. 聚合根核心概念 ​

1.1 什么是聚合根(Aggregate Root) ​

  • 定义: 聚合根是聚合的入口点和唯一外部访问点
  • 职责: 维护聚合内所有对象的一致性边界
  • 特点:
    • 具有全局唯一标识
    • 负责维护业务规则的不变性
    • 控制对聚合内其他对象的访问

1.2 聚合(Aggregate)组成 ​

聚合根 (Aggregate Root)
├── 实体 (Entities)
│   ├── 具有生命周期和唯一标识
│   └── 可独立存在但属于聚合
└── 值对象 (Value Objects)
    ├── 无唯一标识，通过属性定义
    └── 不可变，可替换

2. 聚合根设计原则 ​

2.1 不变性约束(Invariants) ​

java
// 示例：订单聚合根
public class Order implements AggregateRoot {
    private OrderId id;
    private CustomerId customerId;
    private List<OrderItem> items;
    private OrderStatus status;
    private Money totalAmount;
    
    // 业务规则：订单总额必须等于所有订单项金额之和
    public void addItem(Product product, int quantity) {
        // 维护不变性约束
        OrderItem newItem = new OrderItem(product, quantity);
        this.items.add(newItem);
        this.totalAmount = calculateTotalAmount(); // 重新计算总额
        validateInvariants(); // 验证业务规则
    }
    
    private void validateInvariants() {
        if (totalAmount.compareTo(calculateItemsTotal()) != 0) {
            throw new BusinessRuleViolationException("订单总额不一致");
        }
    }
}

2.2 事务边界 ​

  • 单个事务 = 单个聚合的修改
  • 跨聚合操作通过领域事件实现最终一致性

2.3 引用规则 ​

  • 聚合外部只能持有聚合根的引用
  • 聚合内部对象不能被外部直接引用

3. 聚合根识别方法 ​

3.1 识别步骤 ​

  1. 找出业务核心概念 → 候选实体
  2. 分析生命周期 → 确定根实体
  3. 定义一致性边界 → 划定聚合范围
  4. 明确访问入口 → 确定聚合根

3.2 案例分析：电商系统 ​

// 正确设计：订单聚合
Order (聚合根)
├── OrderItem (实体)
├── ShippingAddress (值对象)
└── PaymentInfo (值对象)

// 错误设计：将Customer作为Order的一部分
Order
├── Customer ← 这应该是另一个聚合的根
└── OrderItems

4. 聚合根实现模式 ​

4.1 基本结构 ​

java
// 聚合根基类
public abstract class AggregateRoot<ID> {
    private ID id;
    private Long version;
    private final List<DomainEvent> domainEvents = new ArrayList<>();
    
    public ID getId() { return id; }
    public Long getVersion() { return version; }
    
    protected void addDomainEvent(DomainEvent event) {
        this.domainEvents.add(event);
    }
    
    public List<DomainEvent> getDomainEvents() {
        return new ArrayList<>(domainEvents);
    }
    
    public void clearDomainEvents() {
        domainEvents.clear();
    }
}

// 具体聚合根实现
public class Order extends AggregateRoot<OrderId> {
    private OrderStatus status;
    private List<OrderItem> items = new ArrayList<>();
    private Money totalAmount;
    
    // 工厂方法
    public static Order create(OrderId id, CustomerId customerId) {
        Order order = new Order();
        order.id = id;
        order.customerId = customerId;
        order.status = OrderStatus.CREATED;
        order.addDomainEvent(new OrderCreatedEvent(id, customerId));
        return order;
    }
    
    // 命令方法
    public void addItem(Product product, int quantity) {
        if (!status.canAddItems()) {
            throw new IllegalOrderStateException("无法添加商品");
        }
        
        OrderItem item = OrderItem.create(product, quantity);
        items.add(item);
        totalAmount = calculateTotal();
        addDomainEvent(new OrderItemAddedEvent(id, product.getId(), quantity));
    }
    
    // 查询方法
    public boolean containsProduct(ProductId productId) {
        return items.stream()
            .anyMatch(item -> item.getProductId().equals(productId));
    }
}

4.2 领域事件实现 ​

java
// 领域事件
public interface DomainEvent {
    Date occurredOn();
}

public class OrderCreatedEvent implements DomainEvent {
    private final OrderId orderId;
    private final CustomerId customerId;
    private final Date occurredOn;
    
    public OrderCreatedEvent(OrderId orderId, CustomerId customerId) {
        this.orderId = orderId;
        this.customerId = customerId;
        this.occurredOn = new Date();
    }
    
    // getters...
}

// 事件发布
@Service
public class OrderApplicationService {
    private final OrderRepository orderRepository;
    private final DomainEventPublisher eventPublisher;
    
    @Transactional
    public void addOrderItem(OrderId orderId, Product product, int quantity) {
        Order order = orderRepository.findById(orderId);
        order.addItem(product, quantity);
        orderRepository.save(order);
        
        // 发布领域事件
        order.getDomainEvents().forEach(eventPublisher::publish);
        order.clearDomainEvents();
    }
}

5. 仓储(Repository)模式 ​

5.1 聚合根仓储 ​

java
// 仓储接口
public interface OrderRepository {
    Order findById(OrderId id);
    void save(Order order);
    void delete(Order order);
    List<Order> findByCustomerId(CustomerId customerId);
}

// 实现
@Repository
public class OrderRepositoryImpl implements OrderRepository {
    private final OrderJpaRepository jpaRepository;
    private final OrderMapper mapper;
    
    @Override
    public Order findById(OrderId id) {
        OrderEntity entity = jpaRepository.findById(id.getValue())
            .orElseThrow(() -> new OrderNotFoundException(id));
        return mapper.toDomain(entity);
    }
    
    @Override
    public void save(Order order) {
        OrderEntity entity = mapper.toEntity(order);
        jpaRepository.save(entity);
    }
}

6. 最佳实践和常见陷阱 ​

6.1 最佳实践 ​

  1. 保持聚合小巧

    • 避免过大的聚合，减少锁竞争
    • 单个聚合应该能在内存中轻松加载

  2. 通过ID引用其他聚合

    java
    // 正确：通过ID引用
public class Order {
    private OrderId id;
    private CustomerId customerId; // 引用客户聚合
}

// 错误：直接持有其他聚合引用
public class Order {
    private OrderId id;
    private Customer customer; // 违反聚合边界
}

  3. 最终一致性

    java
    // 使用领域事件处理跨聚合业务逻辑
public class Order {
    public void confirm() {
        this.status = OrderStatus.CONFIRMED;
        addDomainEvent(new OrderConfirmedEvent(this.id, this.totalAmount));
    }
}

// 事件处理器更新其他聚合
@Component
public class OrderConfirmedEventHandler {
    @EventListener
    public void handle(OrderConfirmedEvent event) {
        // 更新客户积分
        // 通知库存系统
        // 发送确认邮件
    }
}

6.2 常见陷阱 ​

  1. 贫血模型: 将业务逻辑放在服务层而非聚合根中
  2. 聚合过大: 试图在一个聚合中包含太多实体
  3. 直接引用: 聚合间直接对象引用而非ID引用
  4. 事务边界混淆: 在单个事务中修改多个聚合

7. 实战示例：博客系统 ​

java
// 博客聚合根
public class Blog implements AggregateRoot<BlogId> {
    private BlogId id;
    private String title;
    private UserId authorId;
    private List<Post> posts = new ArrayList<>();
    private BlogStatus status;
    
    // 业务方法
    public Post publishPost(PostId postId, String title, String content) {
        if (!status.canPublish()) {
            throw new BlogNotActiveException();
        }
        
        Post post = Post.create(postId, this.id, title, content);
        posts.add(post);
        addDomainEvent(new PostPublishedEvent(postId, this.id));
        return post;
    }
    
    public void addComment(PostId postId, Comment comment) {
        Post post = findPost(postId);
        post.addComment(comment);
    }
    
    private Post findPost(PostId postId) {
        return posts.stream()
            .filter(post -> post.getId().equals(postId))
            .findFirst()
            .orElseThrow(() -> new PostNotFoundException(postId));
    }
}

// 文章实体（属于博客聚合）
public class Post {
    private PostId id;
    private BlogId blogId;
    private String title;
    private String content;
    private List<Comment> comments = new ArrayList<>();
    private PostStatus status;
    
    public void addComment(Comment comment) {
        if (!status.canComment()) {
            throw new PostClosedForCommentsException();
        }
        comments.add(comment);
    }
}

8. 测试策略 ​

java
// 聚合根单元测试
class OrderTest {
    @Test
    void should_add_item_to_order() {
        // Given
        Order order = Order.create(new OrderId("order-1"), new CustomerId("customer-1"));
        Product product = new Product(new ProductId("product-1"), new Money(100));
        
        // When
        order.addItem(product, 2);
        
        // Then
        assertThat(order.containsProduct(new ProductId("product-1"))).isTrue();
        assertThat(order.getTotalAmount()).isEqualTo(new Money(200));
        assertThat(order.getDomainEvents()).hasSize(1);
    }
    
    @Test
    void should_throw_when_adding_item_to_completed_order() {
        // Given
        Order order = Order.create(new OrderId("order-1"), new CustomerId("customer-1"));
        order.complete();
        Product product = new Product(new ProductId("product-1"), new Money(100));
        
        // When & Then
        assertThrows(IllegalOrderStateException.class, () -> {
            order.addItem(product, 1);
        });
    }
}

总结 ​

聚合根是DDD中维护业务一致性的核心概念，正确设计聚合根能够：

  • 确保业务规则在明确的边界内得到维护
  • 提供清晰的事务边界
  • 降低系统复杂度
  • 提高代码的可维护性和可测试性

关键要点：小聚合、强一致性边界、ID引用、领域事件驱动。
