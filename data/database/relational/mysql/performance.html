ini

四、慢查询优化策略 ​

1. 索引优化方案 ​

问题类型解决方案示例
无可用索引创建复合索引ADD INDEX idx_col1_col2
索引失效避免函数操作WHERE DATE(col) > ? → WHERE col > ?
回表查询使用覆盖索引SELECT id,name → 索引包含(id,name)
索引区分度低选择高区分度列cardinality > 30%

2. SQL重写技巧 ​

sql
-- 原语句（1.2s）
SELECT * FROM orders 
WHERE customer_id IN (
  SELECT id FROM customers 
  WHERE country='US'
);

-- 优化后（0.03s）
SELECT o.* 
FROM orders o
JOIN customers c ON o.customer_id = c.id
WHERE c.country='US';

七、典型性能问题解决方案 ​

1. 分页优化 ​

sql
-- 原始慢查询（偏移量大时）
SELECT * FROM logs ORDER BY id LIMIT 1000000, 20; 

-- 优化方案：游标分页
SELECT * FROM logs WHERE id > 1000000 ORDER BY id LIMIT 20;

2. 大表更新死锁 ​

sql
-- 危险操作
UPDATE accounts SET balance=balance-100 WHERE id IN (SELECT id FROM temp_table);

-- 优化方案：分批更新
WHILE has_rows DO
  UPDATE accounts 
  SET balance=balance-100 
  WHERE id IN (SELECT id FROM temp_table LIMIT 1000);
  COMMIT;
END WHILE;

3. 高并发写入瓶颈 ​

  • 优化方案：
    1. 关闭自动提交：SET autocommit=0;
    2. 批量写入：INSERT ... VALUES (...),(...)...
    3. 使用LOAD DATA替代INSERT
    4. 调整刷盘策略：innodb_flush_log_at_trx_commit=2

十、性能优化黄金法则 ​

  1. 监控先行：没有度量就没有优化
  2. 二八原则：优化20%的高频慢查询解决80%问题
  3. 迭代优化：每次只改一个变量并验证效果
  4. 回归测试：优化后执行sysbench验证
  5. 预防机制：建立SQL审核流程

持续优化循环：
监控 → 捕获 → 分析 → 优化 → 验证 → 固化
